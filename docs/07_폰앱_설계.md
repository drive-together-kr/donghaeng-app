# 동행 폰 동반 앱 설계 (Flutter)

## 1. 역할
차량에는 카메라·키보드가 없으므로 **"사람 확인이 필요한 일"**을 폰이 맡는다.
1. 로그인 (계정 = 사람)
2. 차량 페어링 QR 스캔 → 내 차 등록
3. 그룹 QR 스캔 → 내 차를 그룹에 합류
4. 동승자 메시지 입력 → 그룹 차량에서 음성으로 읽힘
5. 그룹 알림(푸시) 수신 — 차 밖에 있는 가족도 "엄마 차 도착" 확인

## 2. 스택
| 항목 | 패키지 |
|---|---|
| 프레임워크 | Flutter 3.24+ (Android 우선, iOS 빌드 가능 상태 유지) |
| 상태관리 | Riverpod |
| HTTP | dio + 인터셉터(토큰 갱신) |
| 토큰 저장 | flutter_secure_storage |
| QR 스캔 | mobile_scanner |
| 딥링크 | app_links (`{DH_PUBLIC_BASE_URL}/j/{token}`, `{DH_PUBLIC_BASE_URL}/pair?c=…`) — 호스트는 빌드 설정값(로컬 `10.0.2.2:8080`, 클라우드 `<VM-IP>.sslip.io`), 고정 도메인 없음 |
| 푸시 | firebase_messaging (P1, 초기엔 15s 폴링) |
| 지도(그룹 상세) | flutter_map + OSM 타일 |

## 3. 화면
| 화면 | 내용 |
|---|---|
| 로그인 | MVP: 이메일+닉네임 개발용 로그인 / 추후 Pleos ID·카카오 |
| 홈 | 내 차 목록, 참여 중인 그룹 카드, "QR 스캔" 큰 버튼 |
| 스캔 | 카메라 → QR 종류 자동 판별(`/pair` = 차량 등록, `/j/` = 그룹 합류) |
| 차량 등록 확인 | "차 화면의 코드 KQ7-4MZ가 맞나요?" + 차 별명 입력 → `POST /device/approve` |
| 그룹 합류 확인 | 그룹 이름·방장·인원 표시 → 어떤 내 차로 합류할지 선택 → `POST /groups/join` |
| 그룹 상세 | 멤버 차 위치(지도)·ETA·잔량, 이벤트 피드 |
| 메시지 보내기 | 프리셋 + 자유 입력(60자) → `POST /groups/{id}/messages` |

## 4. QR 판별 규칙
QR 문자열은 서버가 `{DH_PUBLIC_BASE_URL}` + 경로로 만든다. 폰 앱은 **호스트가 아니라 경로**로 종류를 판별하고, 호스트는 앱에 설정된 서버(`DH_PUBLIC_BASE_URL`)와 같은지만 확인한다.
```
{DH_PUBLIC_BASE_URL}/pair?c=XXXXXX   → 차량 페어링   (예: http://10.0.2.2:8080/pair?c=KQ74MZ)
{DH_PUBLIC_BASE_URL}/j/inv_xxxxx     → 그룹 합류     (예: https://1-2-3-4.sslip.io/j/inv_abc)
경로가 위 둘이 아님                  → "동행 QR이 아니에요"
호스트가 설정된 서버와 다름          → "다른 서버의 QR이에요" (서버 주소 확인 안내)
```
웹 폴백: 앱 미설치 상태에서 폰 기본 카메라로 찍으면 서버가 같은 경로(`/pair`, `/j/{token}`)에서 "앱 설치하기" 정적 페이지를 돌려준다(MVP는 서버 내장 정적 HTML, 도메인 비의존).

## 5. 확장 (기획서 발전 계획)
- 마이현대·기아 앱 QR 스캐너 연동 시 별도 앱 없이 합류 (현대·기아 협의 필요)
- Pleos ID 로그인 → 페어링 단계 생략(계정에 연결된 차량 자동 인식)
