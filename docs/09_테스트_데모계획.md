# 동행 테스트 · 데모 계획

## 1. 개발 환경
- Windows PC, Android Studio 2026.1.3, Pleos Connect Emulator v2.1.0 (API 34, x86_64, RAM 4GB, Cold boot)
- 에뮬레이터 2대(둘 다 Pleos 이미지): `Pleos_Connect_v2.1.0`(차 A, **pleos** flavor, 실 SDK) + `Pleos_B`(차 B, **fake** flavor — 같은 시스템 이미지의 복제 AVD, GPX 를 스스로 재생). 2026-10-27 확정, 그 전까지 차 B 역할이던 `Medium_Phone` AVD(API 37 Play 이미지, 과부하)는 삭제했다.
  - `Pleos_B` 만들기: `%USERPROFILE%\.android\avd\Pleos_Connect_v2.1.0.avd\config.ini` 를 `Pleos_B.avd\config.ini` 로 복사해 `AvdId=Pleos_B`, `avd.ini.displayname` 만 바꾸고 `Pleos_B.ini`(path 지정)를 만든다. RAM 은 이미지가 최소 4096 MB 를 강제한다. 실행: `emulator -avd Pleos_B -port 5558` → `emulator-5558`.
  - 두 AVD 공통 튜닝(2026-10-27, `config.ini.bak` 백업): `hw.gpu.mode=host`(실측 렌더러 NVIDIA RTX), `fastboot.forceColdBoot=no` + `fastboot.forceFastBoot=yes`(Quick Boot — 실행 인자에 `-no-snapshot-load` 를 주지 않는다), `hw.audioInput=no`(가상 마이크 DirectSoundCapture 실패 로그 제거). 부팅 약 20 s.
- Virtual Console(차 A 만 — 차 B 는 fake 차량 어댑터라 필요 없다): `adb -s emulator-5556 forward tcp:8089 tcp:8088` → http://127.0.0.1:8089 또는 `python tools/demo/vc.py --port 8089 soc 12`.
- 위치 이동: 차 A 는 `python tools/demo/replay_gpx.py --serial emulator-5556`(lead.gpx → `adb emu geo fix` 1 Hz → Android LocationManager 소스), 차 B 는 `FakeNaviAdapter` 가 follow.gpx 를 재생(합류 제안 수락 뒤 출발). Extended Controls 의 Routes 재생은 쓰지 않는다.
- **Pleos AVD 네트워크 주의:** Pleos_Connect_v2.1.0 은 Wi-Fi(wlan0)가 켜져 기본 네트워크가 되면 호스트(10.0.2.2)에 닿지 않는다(유선 eth0 으로만 닿음, 앱에는 `SocketTimeoutException`). 시연 전 `adb -s <pleos-serial> shell svc wifi disable` 로 Wi-Fi 를 끈다(되돌리기 `svc wifi enable`). 확인: `adb -s <serial> shell ping -c 1 10.0.2.2`.
- 서버: `infra/` 에서 `docker compose up -d` — 호스트 포트: 서버 8080, EMQX 1883/18083, Redis 6379, PostgreSQL **15432**(로컬 PostgreSQL 18이 5432 점유). 에뮬레이터에서 서버 주소 = `http://10.0.2.2:8080` (`DH_PUBLIC_BASE_URL=http://10.0.2.2:8080`)
- 폰(demo-host = 공식 앱을 흉내 낸 companion 호스트 앱): **USB 로 연결한 실기기**(같은 Wi-Fi) — 로컬 서버는 PC IP 로 접근(`DH_PUBLIC_BASE_URL=http://<PC-IP>:8080`, 방화벽 8080/1883 인바운드 허용 필요), 클라우드 배포 후엔 `https://<VM-IP>.sslip.io`. 폰이 없을 때는 `python tools/demo/api.py --email <dev 이메일> pair|join|message` 로 같은 REST 를 대신 호출해 리허설한다.

### 1.1 M1 "연결" 재현 절차 (T18, 2026-10-27 확인)
1. 서버: `cd infra && docker compose up -d` (JWT 키는 `.env` 에 고정 — 재시작해도 토큰 유지).
2. 차 A(Pleos AVD): 홈 → **내 폰과 연결하기** → 폰 demo-host(dev 로그인) → QR 스캔 → 디버그 "QR 문자열 붙여넣기"에 `verifyUri` → 차량 등록. 로그 `pairing state=CONNECTED`, `mqtt connected`, `mqtt subscribed …/cmd`.
3. 차 B(Medium_Phone 의 fake 차량 앱): 같은 방법으로 둘째 차 등록(별명 DemoCarB).
4. 차 A: **같이 가기 시작** → 목적지(프리셋) → 생성 → QR + 초대 URL 텍스트(`{base}/j/inv_…`). 로그 `group created`, `mqtt subscribed …/group/grp_…/state|event`.
5. 폰 demo-host: QR 스캔 → 붙여넣기에 초대 URL → **그룹 합류** 시트(그룹명·방장·목적지·인원 미리보기) → "어떤 차로 함께 갈까요?"에서 DemoCarB → **함께 가기**.
6. 차 B: 로그 `GROUP_JOINED groupId=… → subscribed group topics`, 홈에 "그룹: …", **그룹 보기** → "그룹에 연결됐어요. 선두차: DemoCar". 차 A: 멤버 2대(5초 폴링 또는 `MEMBER_JOINED` 이벤트). 폰 홈: "동행 중" 카드.
- 자동화: 세션 스크립트 `t18_join_demo.py`(uiautomator)로 위 절차를 끝까지 돌리고 캡처한다(`docs/images/t18/`).

## 4. 데모 시나리오 (시연 영상 2~3분 / PT 5분) — T30 확정본

화면 구성: 좌 = 선두차 A(Pleos AVD, 실 SDK), 우 = 후속차 B(Pleos_B AVD, fake 내비 GPX 재생), 하단 작은 창 = demo-host(USB 실폰, scrcpy 미러링).
자동화: `python tools/demo/demo.py --email <dev 이메일>` 이 장면 4~9 를 시간표대로 실행하고 두 차 로그로 확인 표(`tools/demo/out/<시각>/summary.md`)를 만든다. 장면 2~3 은 화면·폰에서 한다(`tools/demo/README.md`).

- 제외: F9 그룹 휴게소 자동 제안(P1, `REST_STOP_PROPOSAL` 스키마만 있음) — 구현되면 장면 6 뒤에 넣는다. 음성은 Pleos AVD 에 TTS 엔진이 없어 `voice: speak …` 로그 폴백으로 확인한다(실차·TTS 있는 기기에서는 실제 발화).
- **2026-10-27 실행 결과(4차, `tools/demo/demo.py`)**: 합류 감지 → 선두 목적지 안내 수락 → T0+22s 저잔량(A 발행·B 음성) → +46s 동승자 메시지 → +60s 경로 변경 제안 → +69s 수락(내비 재요청·ACK) → +149s B 덕평휴게소 도착·A 수신 → +155s 급제동(A 발행·B 음성) — **10/10 확인, 중단 없음**. 요약표 `docs/images/t30/demo_run_summary.md`, 캡처 `docs/images/t30/`(차 B 경로 제안 카드·그룹 주행, 차 A 그룹 주행 피드·그룹 생성·QR). 1~3차에서 잡은 것: 그룹 생성 화면 크래시(수정), 로그 감시가 링 버퍼 회전에 걸림(기기 시계 `logcat -T` 로 수정), 서버 LOW_ENERGY 중복 억제 120 s(preflight 검사 추가), 내 `MEMBER_LEFT` 세션 정리(수정).
