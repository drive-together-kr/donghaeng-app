# 동행 테스트 · 데모 계획

## 1. 개발 환경
- Windows PC, Android Studio 2026.1.3, Pleos Connect Emulator v2.1.0 (API 34, x86_64, RAM 4GB, Cold boot)
- 에뮬레이터 2대: AVD `Pleos_A`(선두), `Pleos_B`(후속) — Device Manager에서 같은 이미지로 2개 생성
  - **M1(2026-10-27) 실측 구성:** `Pleos_B` 를 만들기 전에는 `Medium_Phone` AVD(emulator-5554)에 설치한 **fake flavor 차량 앱**이 차 B 역할을 한다(같은 AVD 에 demo-host 도 설치, 둘 다 `10.0.2.2` 로 서버 접근). 차 A = Pleos AVD(emulator-5556). 두 차 모두 같은 dev 계정에 페어링돼 있어야 폰이 차 B 를 골라 합류시킬 수 있다.
- Virtual Console: 에뮬레이터마다 포트를 다르게 포워딩
  ```powershell
  $adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
  & $adb devices                                   # emulator-5554, emulator-5556 확인
  & $adb -s emulator-5554 forward tcp:8088 tcp:8088   # A → http://127.0.0.1:8088
  & $adb -s emulator-5556 forward tcp:8089 tcp:8088   # B → http://127.0.0.1:8089
  ```
  (두 번째 포워딩이 안 되면 B는 Fake 차량 어댑터로 시연)
- 위치 이동: Android 에뮬레이터 Extended Controls → Location → Routes에 GPX 불러와 재생 (A, B 각각 다른 GPX)
- **Pleos AVD 네트워크 주의:** Pleos_Connect_v2.1.0 은 Wi-Fi(wlan0)가 켜져 기본 네트워크가 되면 호스트(10.0.2.2)에 닿지 않는다(유선 eth0 으로만 닿음, 앱에는 `SocketTimeoutException`). 시연 전 `adb -s <pleos-serial> shell svc wifi disable` 로 Wi-Fi 를 끈다(되돌리기 `svc wifi enable`). 확인: `adb -s <serial> shell ping -c 1 10.0.2.2`.
- 서버: `infra/` 에서 `docker compose up -d` — 호스트 포트: 서버 8080, EMQX 1883/18083, Redis 6379, PostgreSQL **15432**(로컬 PostgreSQL 18이 5432 점유). 에뮬레이터에서 서버 주소 = `http://10.0.2.2:8080` (`DH_PUBLIC_BASE_URL=http://10.0.2.2:8080`)
- 폰(demo-host = 공식 앱을 흉내 낸 companion 호스트 앱): Medium_Phone AVD 또는 실기기(같은 Wi-Fi) — 로컬 서버는 PC IP로 접근(`DH_PUBLIC_BASE_URL=http://<PC-IP>:8080`, 방화벽 8080/1883 인바운드 허용 필요), 클라우드 배포 후엔 `https://<VM-IP>.sslip.io`

### 1.1 M1 "연결" 재현 절차 (T18, 2026-10-27 확인)
1. 서버: `cd infra && docker compose up -d` (JWT 키는 `.env` 에 고정 — 재시작해도 토큰 유지).
2. 차 A(Pleos AVD): 홈 → **내 폰과 연결하기** → 폰 demo-host(dev 로그인) → QR 스캔 → 디버그 "QR 문자열 붙여넣기"에 `verifyUri` → 차량 등록. 로그 `pairing state=CONNECTED`, `mqtt connected`, `mqtt subscribed …/cmd`.
3. 차 B(Medium_Phone 의 fake 차량 앱): 같은 방법으로 둘째 차 등록(별명 DemoCarB).
4. 차 A: **같이 가기 시작** → 목적지(프리셋) → 생성 → QR + 초대 URL 텍스트(`{base}/j/inv_…`). 로그 `group created`, `mqtt subscribed …/group/grp_…/state|event`.
5. 폰 demo-host: QR 스캔 → 붙여넣기에 초대 URL → **그룹 합류** 시트(그룹명·방장·목적지·인원 미리보기) → "어떤 차로 함께 갈까요?"에서 DemoCarB → **함께 가기**.
6. 차 B: 로그 `GROUP_JOINED groupId=… → subscribed group topics`, 홈에 "그룹: …", **그룹 보기** → "그룹에 연결됐어요. 선두차: DemoCar". 차 A: 멤버 2대(5초 폴링 또는 `MEMBER_JOINED` 이벤트). 폰 홈: "동행 중" 카드.
- 자동화: 세션 스크립트 `t18_join_demo.py`(uiautomator)로 위 절차를 끝까지 돌리고 캡처한다(`docs/images/t18/`).

## 4. 데모 시나리오 (시연 영상 2~3분 / PT 5분)

화면 구성: 좌 = 선두차 A, 우 = 후속차 B, 하단 작은 창 = demo-host(공식 앱 동행 메뉴) 화면 미러링(scrcpy 또는 폰 AVD 창)

| # | 장면 | 조작 | 보여줄 것 |
|---|---|---|---|
| 1 | 문제 제기 (10s) | 자막 | "차 두 대로 여행 갈 때, 운전하면서 전화할 수 없다" |
| 2 | 그룹 시작 | A: 목적지 "강릉" → "같이 가기" | A 화면 QR |
| 3 | QR 합류 | demo-host(공식 앱 동행 메뉴)로 A의 QR 스캔 → B 선택 | B 화면에 "그룹 연결됨" + "선두차 목적지로 안내할까요?" → 수락 → B 내비 경로 |
| 4 | 함께 주행 | GPX 재생 A·B | 양쪽 화면에 서로의 위치·ETA, 지연 ms 오버레이 |
| 5 | 차량 상태 공유 | A Virtual Console Energy 연료 12% | B 음성: "아빠 차 연료가 12% 남았어요" |
| 6 | 휴게소 제안 (P1) | 자동 | 양쪽 "18km 앞 OO휴게소에서 쉬어갈까요?" → 수락 → 경유지 추가 |
| 7 | 휴게소 도착 | A GPX 휴게소 도착 | B 음성: "아빠 차가 OO휴게소에 도착했어요" |
| 8 | 경로 변경 따라가기 | A가 맛집 경유지 추가 | B "따라갈까요?" → 수락 → B 내비 반영 |
| 9 | 급제동 공유 | A BRAKE 강하게 | B 음성: "앞쪽 아빠 차가 급제동했어요" |
| 10 | 마무리 (10s) | 자막 | "전화 없이, 한 대처럼. 동행" + 현대·기아·제네시스 연결 |
