# 동행 서버 설계 (donghaeng-server)

## 1. 기술 스택
| 항목 | 선택 |
|---|---|
| 언어/런타임 | Kotlin 2.0, JDK 21 (Gradle toolchain 21 — 로컬 JDK 경로는 커밋하지 않고 `~/.gradle/gradle.properties`의 `org.gradle.java.installations.paths`로 지정) |
| 프레임워크 | Spring Boot 3.3 (Web MVC, Validation, Actuator, Security) |
| DB | PostgreSQL 16 + Spring Data JDBC(또는 jOOQ) + Flyway |
| 캐시/실시간 | Redis 7 (Lettuce) |
| MQTT 브로커 | EMQX 5 (Docker), JWT 인증 + ACL |
| MQTT 클라이언트(서버) | HiveMQ MQTT Client, 공유 구독 `$share/server/...` |
| 인증 | 자체 JWT(RS256) — 키는 환경 변수/파일, `kid` 회전 지원 |
| 테스트 | JUnit5, Testcontainers(Postgres·Redis·EMQX), MockK |
| 관측 | Actuator + Micrometer(Prometheus 포맷), 구조화 JSON 로그(좌표 마스킹) |
| 빌드 | Gradle Kotlin DSL, Docker 이미지(멀티 스테이지 `server/Dockerfile`; Jib 는 선택) |

## 3. 처리 파이프라인
```
EMQX ──($share/server/dh/v1/vehicle/+/telemetry)──► TopicRouter ─► presence.TelemetryIngestor
                                                               └─► insight.RuleEngine.onTelemetry
EMQX ──(…/event)──► event.VehicleEventHandler ─► dedup(Redis) ─► SpeechComposer ─► GroupEventPublisher
                                               └─► routesync (ROUTE_CHANGED) / insight (LOW_ENERGY 등)
EMQX ──(…/ack)────► routesync / insight (투표 집계)
Scheduler(2s) ─► SnapshotPublisher: GroupMembershipApi.activeRosters() + veh:{vid}:state/online → group/state(retained) 발행 (T24 구현)
Scheduler(10s)─► OfflineRule, DeviationRule, 연속주행 체크
Scheduler(1h) ─► 만료 초대·디바이스코드 정리, group_event 24h 초과 삭제
```
- 그룹 소속 검증: 수신 메시지의 `vid`가 토큰 subject와 일치하는지는 EMQX JWT 인증의 `verify_claims { sub = "${username}" }`(username = vid 바인딩)와 ACL이 보장, 서버는 `veh:{vid}:group` 확인 후 처리.
- 멱등성: 차량 이벤트는 `(vid, seq)` 기준 중복 무시(재연결 재전송 대비).

### 3.1 시각 기준 (T31)
모든 봉투 `ts` 는 서버 `Clock` 이다. `GET /v1/time`(`common.web.TimeController`, 공개 경로) 이 같은 `Clock` 의 ms 를 돌려주며, 차량 앱이 이것으로 시계 오프셋을 잡아 지연(ms)을 표시한다. 서버 쪽 추가 상태는 없다.

## 5. 보안
- JWT: 사용자 토큰 1h / 차량 토큰 24h, refresh 30일(회전). 차량 토큰 claim: `sub=veh_…`, `owner=usr_…`, `typ=vehicle`.
- 공식 앱 계정: companion 모듈이 `/auth/exchange` 로 넘긴 호스트 앱 OAuth 토큰은 `ExternalTokenVerifier.verify(provider, token) → ExternalIdentity(provider, sub, displayName)` 로만 검증한다(인터페이스; MVP 구현은 `DevTokenVerifier` — `dev` 의 토큰은 `/auth/login` 이 발급한 JWT 를 `JwtDecoder` 로 검증; 공식 앱 4종은 `NotSupportedTokenVerifier` 가 501 `PROVIDER_NOT_SUPPORTED`). 차량 소유 조회는 `VehicleDirectory`(실서비스 OEM 차량 API, MVP `DbVehicleDirectory`), 페어링(대체 수단)으로 등록된 차량은 `VehicleRegistry`(동행 DB 등록·소유권 이전)에 적는다.
- 키·검증 구현(T10): `JwtKeyProvider` 가 `DH_JWT_PRIVATE_KEY_PEM`(PKCS#8) 을 읽고 없으면 개발용 2048비트 키를 생성(WARN, 재시작 시 토큰 무효), `kid` = 공개키 SHA-256 앞 16 hex. `JwtIssuer` 가 RS256 으로 서명(`iss=donghaeng`, `jti`), `JwksController` 가 공개 JWK Set 을 내보내고, `JwtDecoderConfig` 의 `NimbusJwtDecoder`(공개키 + 발급자·만료 검증)를 `common/security/SecurityConfig` 의 `oauth2ResourceServer { jwt }` 가 쓴다 — `typ` 클레임 `user`/`vehicle` → `ROLE_USER`/`ROLE_VEHICLE`; `/v1/me/` 아래·`POST /v1/device/approve`·`POST /v1/groups/join` 은 ROLE_USER, `POST /v1/groups` 는 ROLE_VEHICLE, 나머지 `/v1/groups/**` 는 두 역할 모두 허용하고 group 모듈이 멤버·방장을 본다. 미인증·무효 토큰·권한 부족은 모두 docs/03 오류 JSON(401 `UNAUTHORIZED`/`INVALID_TOKEN`, 403 `FORBIDDEN`). refresh 는 `RefreshTokenService`(랜덤 32바이트 Base62 → SHA-256 저장, 30일, 회전). CarInfo ID 는 `CarIdHasher`(`SHA-256(id + DH_CAR_ID_SALT)`).
- EMQX: JWT 인증(공개키 검증), ACL 규칙은 `${username}` 기반 토픽 템플릿 + 그룹 토픽은 서버가 HTTP ACL 훅으로 판정(`/internal/mqtt/acl`). JWT 인증에 `verify_claims { sub = "${username}" }` 를 걸어 토큰 subject 와 username(vid)을 묶는다 — §3 의 "vid = 토큰 subject" 보장의 근거이며, HTTP ACL 훅은 토큰을 받지 못하므로 여기서만 묶을 수 있다. 서버 자신의 MQTT 클라이언트도 username = 자기 토큰 sub 로 접속한다.
- 초대 토큰: 랜덤 32바이트(Base62) — DB엔 SHA-256 해시만 저장, 10분 유효, 사용 횟수 제한.
- Rate limit: `/device/token` 폴링 interval 미준수 시 `SLOW_DOWN`, 로그인·참여 API는 IP당 분당 30회.
- 개인정보: 좌표·닉네임 로그 마스킹, 그룹 종료 시 Redis 상태·이벤트 즉시 삭제, CarInfo ID는 salt 해시로만 저장.

## 6. 로컬 실행 (docker-compose)
```yaml
services:
  postgres: { image: postgres:16, environment: { POSTGRES_DB: donghaeng, POSTGRES_USER: dh, POSTGRES_PASSWORD: dh }, ports: ["127.0.0.1:15432:5432"] }   # 호스트 15432(loopback) — 개발 PC 의 로컬 PostgreSQL 이 5432 를 쓰는 경우가 많다
  redis:    { image: redis:7, ports: ["127.0.0.1:6379:6379"] }
  emqx:
    image: emqx/emqx:5.8
    ports: ["1883:1883", "127.0.0.1:8083:8083", "127.0.0.1:18083:18083"]   # tcp(공개) / ws / dashboard(로컬 전용)
    environment:
      EMQX_AUTHENTICATION__1__MECHANISM: jwt
      EMQX_AUTHENTICATION__1__FROM: password
      EMQX_AUTHENTICATION__1__USE_JWKS: "true"
      EMQX_AUTHENTICATION__1__ENDPOINT: http://server:8080/.well-known/jwks.json
      EMQX_AUTHENTICATION__1__REFRESH_INTERVAL: 30                        # 서버 기동 후 최대 30초 뒤부터 인증 가능
      EMQX_AUTHENTICATION__1__VERIFY_CLAIMS: '{sub = "$${username}"}'   # 토큰 sub == username(vid)
  server:
    build: ../server   # infra/docker-compose.yml 기준 경로
    ports: ["8080:8080"]
    environment:
      SPRING_PROFILES_ACTIVE: local
      DH_DB_URL: jdbc:postgresql://postgres:5432/donghaeng   # DH_DB_USER / DH_DB_PASSWORD 도 함께
      DH_REDIS_HOST: redis
      DH_MQTT_URI: tcp://emqx:1883
      DH_PUBLIC_BASE_URL: http://10.0.2.2:8080     # QR·딥링크용 공개 주소 (03 문서)
      DH_MQTT_PUBLIC_URI: tcp://10.0.2.2:1883
    depends_on: [postgres, redis, emqx]
```
(정확한 EMQX 환경 변수 키는 구현 시 EMQX 5 문서로 확인. 막히면 MVP 1주차엔 EMQX 기본 인증(username/password = vid/token)으로 시작하고 JWT 검증은 HTTP 인증 훅 `/internal/mqtt/auth`로 대체.)

호스트 포트: PostgreSQL **15432**(개발 PC 의 로컬 PostgreSQL 이 5432 를 쓰는 경우가 많아 피함), Redis 6379, EMQX 1883/8083/18083, 서버 8080. 실기기 접속용 1883·8080 만 모든 인터페이스에 공개하고 나머지는 127.0.0.1 에만 바인딩한다(에뮬레이터의 10.0.2.2 는 호스트 loopback). IDE에서 서버를 직접 띄울 때 JDBC URL은 `jdbc:postgresql://localhost:15432/donghaeng`(컨테이너 내부에서는 `postgres:5432`).

## 7. 클라우드 배포 (데모용)
- VM 1대(2 vCPU/4GB, 서울 리전) + Docker Compose + Caddy(HTTPS 443 → server:8080, TLS 8883 → emqx:1883 스트림 프록시 또는 EMQX 자체 TLS)
- 도메인 불필요: `https://<VM-IP>.sslip.io`(예: `https://1-2-3-4.sslip.io`)로 Caddy가 Let's Encrypt 인증서를 자동 발급. 서버 설정 `DH_PUBLIC_BASE_URL=https://<VM-IP>.sslip.io`, `DH_MQTT_PUBLIC_URI=ssl://<VM-IP>.sslip.io:8883`
- 백업 불필요(데모), 단 `.env`는 저장소에 커밋 금지
- 개발용 기본 비밀번호(dh/dh, admin/public)는 클라우드에서 반드시 변경, Redis `requirepass` 설정. 15432/6379/8083/18083 은 loopback 바인딩 유지(외부 비공개) — 인터넷에 열리는 것은 Caddy 의 443/8883 뿐
