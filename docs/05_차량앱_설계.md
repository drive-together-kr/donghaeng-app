## 3. 어댑터 인터페이스

```kotlin
interface VehicleAdapter {
    suspend fun vehicleId(): String?                    // CarInfo 차량 ID
    fun fuelPercent(): Flow<Int?>                       // Fuel.registerFuelPercent
    fun evStateOfCharge(): Flow<Int?>                   // EvBattery.registerEvBatteryStateOfCharge
    fun brakePedal(): Flow<Boolean>                     // Brake.registerBrakePedalStatus
    fun turnSignal(): Flow<TurnSignalState>             // TurnSignal.registerTurnSignalState
    fun airbagDeployed(): Flow<Boolean>                 // Safety.registerSeatAirbagDeployed
    fun speedKph(): Flow<Float?>                        // AAOS CarPropertyManager PERF_VEHICLE_SPEED (실패 시 empty)
    fun gear(): Flow<Gear?>                             // AAOS GEAR_SELECTION (실패 시 empty)
    suspend fun capabilities(): VehicleCapabilities     // 각 check*Capabilities 결과 요약
}

interface NaviAdapter {
    fun events(): Flow<NaviEvent>   // CurrentLocation, TripInfo, DrivingInfo, RouteStateInfo,
                                    // DestinationChanged, WaypointChanged, WaypointArrived, DestinationArrived,
                                    // SpeedLimit, NavigationStatus, Error
    suspend fun requestRoute(dest: Place)
    suspend fun requestRouteWithWaypoints(dest: Place, waypoints: List<Place>)
    suspend fun addWaypoint(place: Place, index: WaypointIndex = WaypointIndex.FIRST)
    suspend fun currentDestination(): Place?
    suspend fun showNavigation()
    suspend fun nextTurn(timeoutMs: Long): NextTurnResult   // getTBTInfo → onTBTInfo 첫 항목: Ahead(NextTurn(distanceM, kind, description)) / NoGuidance / Unknown
}

interface LocationAdapter { fun locations(): Flow<Fix> }   // Fix(lat, lon, heading, accuracy, ts, source)
interface VoiceAdapter { suspend fun speak(text: String, priority: Priority); fun stop() }

### 3.1 Pleos SDK 사용 규칙 (공식 문서·샘플 기준)
- `Vehicle(context).initialize()` 후 `vehicle.getFuel()` 등 `getXxx()`로 도메인 객체를 얻는다. 사용이 끝나면 `vehicle.release()`.
- get·set·capability 결과는 `onComplete`/`onFailed` 비동기 람다. **콜백이 끝나기 전에 release 금지.**
- 구독은 `registerXxx(listener)` / `unregisterXxx(listener)` — **등록한 같은 리스너 객체·같은 area로 해제.**
- 지원 여부를 먼저 `checkXxxCapabilities`로 확인하고, 미지원이면 그 기능을 UI에서 숨긴다.
- NaviHelper: `NaviHelper(context)` → `initialize()` → `addListener(NaviHelperEventListener)` → 요청 → `removeListener` → `release()`.
  - 경로 요청 데이터: `RouteInfo(latitude, longitude, poiId, poiName, poiSubId, address)`,
    `RequestWaypointInfo(..., waypointIndex = WaypointIndex.FIRST, ...)`, `RouteWithWaypointsRequest(destination, waypoints)`
  - 사용하는 콜백: `onCurrentLocationInfo`, `onTripInfo`, `onDrivingInfo`, `onRouteStateInfo`, `onDestinationChanged`,
    `onWaypointChanged`, `onWayPointArrived`, `onDestinationArrived`, `onRouteStarted`, `onRouteEnded`, `onRouteCancelled`,
    `onCurrentRoadSpeedLimit`, `onNavigationStatus`, `onError`
  - 실제 전달되는 이벤트는 Navigation 앱 상태에 따라 다를 수 있으므로 **모든 필드를 nullable로 다룬다.**
- 데이터 클래스 필드명은 SDK 버전에 따라 다를 수 있다 → 어댑터 안에서만 SDK 타입을 다루고, 밖으로는 우리 도메인 타입으로 변환.
- **T20 구현 메모 (`PleosNaviAdapter`, NaviHelper 3.0.5 javap 확인):**
  - `events()` 는 `callbackFlow` — 구독마다 리스너 1개 등록, `awaitClose` 에서 같은 리스너로 `removeListener`. 안내 중이 아니면 위치 콜백이 없으므로 구독 중 1초마다 `getCurrentLocationInfo()` 를 요청한다(응답은 `onCurrentLocationInfo`). 구독 시작 시 `getRouteStateInfo()`·`getDestinationInfo()` 1회.
  - `onDestinationChanged()` 는 인자가 없다 → `getDestinationInfo()` 재요청 → `onDestinationInfo(DestinationInfo)` 를 `DestinationChanged(Place)` 로. `onWaypointChanged` 도 같은 방식으로 `getWaypointInfo()` → `onWayPointInfo(List)`.
  - SDK `TripInfo(distance, eta)` 와 `DrivingInfo.destination(DrivingState duration/distance)` 둘 다 도메인 `TripInfo` 로 보낸다. `onWayPointArrived`/`onDestinationArrived` 는 이름·주소만 주므로 마지막으로 알던 목적지·경유지 목록에서 `Place` 를 찾아 채운다.
  - `onCurrentRoadSpeedLimit` 는 AVD 에서 1Hz 로 같은 값(0)이 반복돼 **값이 바뀔 때만** `SpeedLimit` 이벤트로 올린다. `onNavigationStatus` 의 `isGuiding` = `ROUTE_DRIVE`.
  - `nextTurn(timeoutMs)`(SURF 카드 TBT 게이트, §5.2) = 요청마다 리스너를 붙였다 떼는 `callbackFlow`(awaitClose 에서 같은 리스너 제거) → `getTBTInfo()` → `onTBTInfo(List<TBTInfo>)` 의 첫 항목(`TBTInfo(type: TurnType, distance: Double, description: String)`, navi-data 3.0.4 javap). 빈 목록 = `NoGuidance`, 응답 없음(기본 0.8 s)·실패·NaN·음수 = `Unknown`. **`distance` 단위는 문서·공식 샘플(pleos-sample-navi-app 은 toString 로그만)에 없어 미터로 가정**(`TBT_DISTANCE_TO_M = 1.0`) — **2026-10-28 기기 확인: 미터**(차 A `rawDistance=80.0` = 내비 TBT "80m", 첫 항목 = 다음 회전) — 첫 응답 원값을 `navi tbt 첫 응답 … rawDistance=` 로 남기니 기기에서 내비 화면 TBT 숫자와 비교해 확인한다(docs/10 R16). `onDrivingInfo`(DrivingInfo — 목적지·경유지별 남은 거리/시간)는 회전 거리가 아니라 쓰지 않는다. NaviHelper 리스너 목록은 앱 안의 CopyOnWriteArrayList 라 붙였다 떼는 비용이 작다(바인더 호출은 `getTBTInfo` 한 번). Fake 는 GPX 진행 거리 기준 1.2 km 마다 가상 회전(좌우 번갈아, 끝은 `TURN_ARRIVE`, 목적지 없으면 `NoGuidance`).
  - `currentDestination()` = 임시 리스너 등록 → `getDestinationInfo()` → `onDestinationInfo` 2초 대기(없으면 null). `showNavigation()` = `requestNavigationScreen(NavigationScreenRequest.RouteOptionList)` — **`pleos.car.permission.NAVI_CUSTOM_MAP` 필요**(SDK 가 검사하는 권한: NAVI_ROUTE, NAVI_ROUTE_SEARCH, NAVI_CUSTOM_MAP, NAVI_CUSTOM_ROUTE, NAVI_CUSTOM_ETC(InternalApi)).
  - 확인 화면: 진단 → "내비 이벤트 (T20)" 카드(콜백 종류별 수·마지막 값·확인용 요청 버튼), 캡처 `docs/images/t20/`.
  - 도메인 `WaypointIndex.FIRST/LAST` → SDK `WaypointIndex.FIRST/SECOND`(SDK 는 경유지 2개까지). `RouteInfo`/`RequestWaypointInfo` 는 named-arg 로 생성(`poiSubId="0"`, `routeOption=RECOMMENDED`).
  - 앱 전체에서 리스너는 `NaviEventMonitor`(싱글턴) 하나만 구독하고 나머지(T23 텔레메트리, T26 이벤트, 진단 화면)는 그 `events` SharedFlow / `state` 를 쓴다. 스트림이 끝나거나 예외면 10초 뒤 재구독.
  - `FakeNaviAdapter` 는 `assets/gpx/lead.gpx`·`follow.gpx`(직선 보간 가상 경로, 약 57 km) 를 틱당 `speedMps` 로 재표본화해 1Hz 재생 — heading 은 다음 점 방향, 10틱마다 `TripInfo`(경로 잔여 거리/시간)·`DrivingInfo`, 경유지 60 m 이내 `WaypointArrived`, 종점에서 `DestinationArrived`+`RouteStateInfo(ENDED)` 1회 후 정지. GPX 가 없으면 기준점 드리프트로 폴백.

### 3.2 위치 소스 우선순위
1. `FusedLocation.isSupported()` 와 `pleos.car.permission.FUSED_LOCATION` 런타임 승인이 **모두** true → FusedLocation (선택 사항 — Playground 상 "준비 중"이지만 SDK는 배포됨, 에뮬레이터에서 런타임 확인. 없어도 아래 체인으로 동작, CLAUDE.md 규칙 5)
2. NaviHelper `onCurrentLocationInfo` (주력 대안)
3. Android `LocationManager` (AAOS 표준)
4. Fake (GPX 재생, 개발·데모용)

속도: Car API → 실패 시 연속 위치로 계산(Haversine / Δt, 3샘플 이동평균).

**T21 구현 메모:**
- `adapter.location.LocationSource`(source, isAvailable, staleTimeoutMs, locations) 를 `CompositeLocationAdapter` 가 순서대로 시도한다. 첫 Fix 10초 / 이후 소스별 stale(기본 5초, Android 15초) 안에 Fix 가 없거나 스트림이 끝나면 다음 순위, 끝까지 실패하면 5초 뒤 처음부터. 하위 소스를 쓰는 동안 60초마다 상위 소스를 **병렬로** 짧게 구독해 Fix 가 실제로 오면 올라간다(탐색 중에도 현재 Fix 는 계속 흘러 1Hz 에 구멍이 없다). 발행 `Fix.source` 는 실제 소스.
- 소스: `PleosFusedLocationAdapter`(pleos: `FUSED_LOCATION` 승인 && `isSupported()` 일 때만 가용, register/unregister 같은 리스너, `confidence` 는 미터가 아니라 accuracy=null) → `NaviLocationSource`(`NaviEventMonitor.events` 의 CurrentLocation — 리스너 중복 없음) → `AndroidLocationSource`(FINE 승인 + GPS/NETWORK provider, 30초 이내 lastKnown 먼저, 1초/0 m 업데이트) → `FakeLocationAdapter`(항상, 고정점).
- `domain.location.LocationFeed`(싱글턴, 앱 시작 시 start): 체인을 한 번만 구독해 `fixes`(replay 1)·`speedKph`·`state` 제공. 소스가 바뀌면 `SpeedEstimator` 리셋. T23 텔레메트리·T26 이벤트는 이걸 구독한다. 권한이 바뀌면 `restart()`.
- `SpeedEstimator`: Δt<0.5s 샘플은 기준점 유지, Δt>10s 면 창 초기화, 250 km/h 초과는 튐으로 무시, 3샘플 평균.
- 권한 요청 시점: `feature.permissions.LocationPermissionGate`(NavHost 옆) — **활성 그룹 + 정차** 일 때 1회 `ACCESS_FINE/COARSE_LOCATION`(+API 33 `POST_NOTIFICATIONS`) 요청, 결과와 무관하게 체인 재탐색. 진단 화면 "위치 소스 (T21)" 카드에도 요청·재탐색 버튼.
- Pleos AVD 실측(2026-10-27): `FUSED_LOCATION` 이 미승인으로 나와 FUSED 건너뜀 → NAVI 첫 Fix 없음(내비 앱 미동작) → ANDROID gps 활성. `adb -s emulator-5556 emu geo fix <lon> <lat>` 를 1Hz 로 이동시키면 속도 ≈ 62 km/h 로 계산된다. fake flavor 는 NAVI(FakeNaviAdapter GPX) 가 활성.

### 3.2.1 차량 신호 구현 메모 (T22)
- `PleosVehicleAdapter` 신호 Flow 는 공통 골격 `vehicleFlow(name) { v -> register…; 현재값 1회 조회; Cleanup { unregister(같은 리스너) } }` — SDK 없으면 빈 스트림, 미지원(onFailed)은 `null` 한 번 후 종료(Int 계열) / 빈 스트림(Boolean 계열).
  리스너 파라미터는 **nullable**(`Int?`, `Boolean?`, `TurnSignalValue?`, `VehicleGear?`; javap + 컴파일 실측), `onFailed(Exception)` 은 non-null.
- 에어백: `checkAirbagDeployedCapabilities` 가 준 좌석 영역마다 `registerSeatAirbagDeployed(area, listener)` → 하나라도 true 면 true. AVD 는 check 자체가 실패 → 빈 스트림.

### 3.3 급제동 판정 (EventDetector)
- 조건: 브레이크 ON && (1초 내 속도 감소 ≥ 14.4 km/h ≈ 4 m/s²) && 직전 속도 ≥ 40 km/h

### 5.1 정차 대시보드 (GROUP_DRIVE 경로, 2026-10-28)
그룹 주행 경로(`DhRoutes.GROUP_DRIVE`)의 화면은 T25 의 리스트+지도 대신 `feature.drive.DriveDashboardScreen` 이다(시안 D1·D2 → 실데이터). **주행 중 앞 화면은 순정 내비**이므로 이 화면은 그룹 생성·합류 직후와 **정차 중**에 본다.
- 데이터: `GroupDriveViewModel`(T25 상태 + `RouteSyncEngine.activeWaypoint` + `NaviEventMonitor` 제한속도 + `LatencyMeter` 이벤트 지연 + `SurfaceFeed` 모드·실제 수신 시각이 붙은 최근 이벤트) → 순수 함수 `DriveDashboardMapper` → `DriveDashboardUi`(단위 테스트 `DriveDashboardMapperTest`).
- 대열 막대: 위치(선두까지 거리)를 아는 차만, `offsetKm = (최후미 distanceToLeaderM − 그 차 값)/1000`, 대열 길이 = 최후미 값, 바로 앞차와 3 km 초과면 주황 구간, 간격은 내 차 기준("앞 1.2 km"/"뒤 350 m"). 막대 끝 = 다음 정차지(내 위치 + 직선거리), 없으면 선두 + 2 km. 오른쪽 끝 "{목적지} {내 남은 km} km".
- 다음 정차지 = `RouteSyncEngine` 이 **마지막으로 수락(멤버)·발행(선두)한 경로의 첫 경유지**(`RouteSyncState.activeWaypoint` — 경유지 없는 경로 수락·내비 경유지 도착·그룹 변경 시 null). 다음 정차 카드는 경유지가 있을 때만(이름·내 위치에서 직선거리; 차별 ETA·주유/충전·도달 가능은 아직 모름 → 생략·"—").
- 그룹 도착 = 멤버 `eta.destTs` 최댓값과 그 차, 내 도착 = 내 eta(남은 km·분). 내 주행 줄 = 제한속도(내비, 0 은 숨김) · 연속 주행(`ContinuousDriveTimer` — 앱 시작부터 `DrivingStateMonitor` 를 따라 주행 구간만 더하고, **15분 이상 정차하면 0**, 짧은 정차는 유지; 2시간 이상 주황 + 휴식 권장. 처음 구현은 그룹 합류 `joinedAtMs` 부터 세어 밤새 이어진 시연 그룹에서 정차 중인데도 "연속 주행 18시간 27분"을 띄웠다) · "다음 휴식 추천: {경유지}"(회전 안내 자리 — 회전은 순정 내비 몫).
- 이벤트 띠·지난 소식은 플로팅 패널과 같은 규칙(`surface.SurfaceEvents`): **내 차 출처 제외, 대상 아님 제외**(급제동은 출처보다 뒤차만 — 위 수신 대상), 띠 = 받은 지 10초 안 **그리고** 서버 시계(`ClockSync.serverNow`)로 60초 안에 생긴 가장 최근 이벤트(없으면 띠 숨김), 정차 블록 '지난 소식' = 발생 시각(봉투 ts) 최신 5개, "N초 전" = 서버 시계 − 봉투 ts(+[더 보기] → 이벤트 피드). MQTT 세션 유지(cleanStart=false) 때문에 재접속하면 브로커가 쌓아 둔 QoS1 옛 이벤트를 한꺼번에 '지금' 보내는데, 이들이 '방금 소식'·"0초 전"으로 보이지 않게 하려는 것이다(카드 60 s·음성 5 s 와 같은 기준). 정차 블록 버튼: 그룹 관리(→ 그룹 생성 화면 Active: 초대 QR·멤버·나가기/종료 — **확인 다이얼로그**를 거친다, 방장 한 번 탭 = 그룹 전체 종료라 R13 오탭 방지) · 설정 · 홈. 프리셋(F8)·보내지 않은 무전(F16)은 데이터가 생길 때까지 블록째 숨긴다.
- 하단 [무전](F16 다음 작업 — 지금은 "무전은 곧 지원돼요" 토스트·로그) · [내비 보기](`surface.NaviLauncher`, 경로 선택은 순수 함수 `choose`: ① 순정 내비 패키지 `ai.umos.maps.android.navigation.app` 의 실행 인텐트 ② `CATEGORY_APP_MAPS` selector 가 순정 내비로 풀릴 때 ③ pleos 빌드는 그 밖이면 `NaviAdapter.showNavigation()`(NaviHelper) — 다른 지도 앱·선택 창으로 새지 않게 ④ fake 빌드는 selector 가 한 앱으로 풀릴 때만, 선택 창이면 NaviHelper 폴백. 매니페스트 `<queries>` 에 패키지·APP_MAPS 인텐트) · 오른쪽 끝 연결 상태 + T31 지연 문구 그대로("지연 이벤트 N ms · 상태 N ms", 설정에서 끄면 없음).

### 5.2 주행 중 표면 (사용자 확정 2026-10-28)
**원칙: 주행 중 앞 화면은 항상 순정 내비, 동행은 가리지 않는 표면으로만.** 표면은 넷뿐이다 — ① 순정 내비 위 **플로팅 패널** ② **이벤트 알림 카드**(5초, **'카드 + 음성' 대체 모드에서만**, 회전 300 m 이내면 회전 후로 미룸) ③ **음성**(T27 `VoiceAnnouncer`) ④ **그룹 휴게소 = 내비 경유지**(T28 `RouteSyncEngine`). 실측 근거: `docs/images/surfaces/*.png`, 제약은 docs/10 R16.

**모드 전환(`surface.SurfacePolicy`, 순수 함수):** 그룹 세션 없음 → `OFF` / 오버레이 권한(`Settings.canDrawOverlays`) 있음 → `PANEL`(패널 소식 줄 + 음성, **헤드업 카드 없음** — 2026-10-28 사용자 지시, 카드가 내비 TBT 를 가렸다 `impl_02`) / 없음 → `CARDS_ONLY`('카드 + 음성' 대체 모드, 정차 대시보드 안내 1줄). 권한은 `OverlayPermissionMonitor` 가 앱 시작·포그라운드 복귀(Activity 생명주기) 때, 그리고 **그룹이 있는 동안만** 5초마다 다시 본다(Pleos 는 `appops` 로만 바뀌므로; 그룹이 없으면 쓸 데가 없어 주기 바인더 호출을 하지 않는다). 패널 표시 = `PANEL` && 동행 `MainActivity` 가 **보이지 않음**(`AppForegroundTracker` — resumed 가 아니라 started~stopped 로 본다: 정차 중 위치 권한 다이얼로그처럼 화면은 보이지만 paused 인 동안 패널이 동행 화면 위에 뜨지 않게) — 동행 화면이 보이면 대시보드가 같은 정보를 보여 준다. 깜빡임 방지로 표시만 0.6 s 늦춘다.

**플로팅 패널(`surface.FloatingPanelService`):** Service + LifecycleOwner + SavedStateRegistryOwner 가 `ComposeView`(`feature.drive.FloatingPanel`)를 `TYPE_APPLICATION_OVERLAY` + `FLAG_NOT_FOCUSABLE|FLAG_NOT_TOUCH_MODAL` 로 띄운다(패널 밖 터치는 내비로). 데이터는 싱글턴 `SurfaceState.panelUi`(Hilt EntryPoint) ← `FloatingPanelMapper`(순수 함수, 단위 테스트):

**주간/야간:** `Configuration.uiMode` 야간 → 짙은 반투명(0xE6161A20) + 흰 글씨, 주간 → 밝은 반투명(0xEDFAFBFC) + 짙은 글씨(톤 색은 흰 바탕 대비 4.5:1 이상으로 진하게), 라임 [무전]은 둘 다 유지. 설정이 바뀌면 서비스가 즉시 다시 그린다. 시안 확인: `screen=design&variant=panel_dark|panel_light|panel_full|panel_worst|panel_longdest`, Compose Preview "플로팅 패널 야간/주간/5대/폭 최악(긴 그룹 이름)/긴 목적지".

**이벤트 알림 카드(`surface.EventCardNotifier`, 판단 `EventCardPolicy` 순수 함수):** `MqttSessionManager.groupEventsReceived` 구독. 대상 = LOW_ENERGY·HARD_BRAKE·AIRBAG_DEPLOYED·WAYPOINT_ARRIVED·DESTINATION_ARRIVED·MEMBER_JOINED·MEMBER_OFFLINE·PASSENGER_MESSAGE(+ F16 `VOICE_MESSAGE` — 문자열 비교). 내 차 출처 제외, 대상 아님 제외(`not-audience` — 급제동은 출처보다 뒤차만, 스냅샷은 `MqttSessionManager.groupState`), 신선도 60 s(`ClockSync.serverNow() − 봉투 ts`). 빈도 제한 `CardThrottle`: 같은 `eventId` 한 번(최근 128개, QoS1 중복 수신), 같은 종류·같은 출처 30초에 한 장(연결 들락날락 MEMBER_OFFLINE 등; 메시지는 제외), 전체 5초(= 카드 수명)에 2장까지(위험 ALERT — 에어백은 예외), 못 올린 카드는 한도를 쓰지 않는다. 채널 **`dh_events_silent`(IMPORTANCE_HIGH, `setSound(null, null)`·진동 없음** — 같은 이벤트를 음성이 읽으므로 알림음과 겹치지 않게; 소리 있던 첫 채널 `dh_events` 는 지운다, 채널 소리는 만든 뒤 못 바꾼다), category 메시지 → `msg`, 그 밖(저잔량·급제동·도착·합류·끊김) → `navigation`. **Pleos 알림 표시기(`ai.umos.notification`)는 일반 앱 알림 중 category `call`·`msg`·`navigation`(·`connect.system`)만 헤드업 카드로 띄우고 `status` 는 IMPORTANCE_HIGH 여도 알림 목록에만 넣는다** (2026-10-28 실측 — 첫 구현의 급제동·저잔량 카드(`status`)가 안 떴고, 표시기 로그 `needHeadUpNotification` 이 navigation·msg 에만 찍힘; `car_warning` 등 차량 category 는 시스템 서명·권한 앱 전용, SecurityException), 제목 = 서버 음성 문구(없으면 종류 라벨), 본문 = 그룹 이름, `setTimeoutAfter(5000)`(2026-10-28 8초 → 5초)·autoCancel, **같은 종류는 같은 알림 id 로 교체**(쌓이지 않음). **`CARDS_ONLY` 에서만 동작** — `PANEL` 이면 카드 없이 skip `panel-mode`(같은 소식은 패널 소식 줄 10초 + 음성), 미룬 카드가 있을 때 `PANEL` 로 바뀌면 버린다(`mode-PANEL`). `POST_NOTIFICATIONS`(API 33+)는 위치 권한과 같은 시점(활성 그룹 + 정차, `LocationPermissionGate`)에 함께 요청하고, 거부되면 카드 없이 패널·음성만.

**카드 TBT 게이트(`surface.TurnCardGate` 순수 클래스 + `TurnProbe`, 사용자 지시 2026-10-28):** 헤드업 카드는 순정 내비 상단 회전 안내(TBT) 위에 겹치므로 대체 모드에서도 회전 직전에는 띄우지 않는다. 카드를 올리기 직전에 `NaviAdapter.nextTurn(0.8 s)` 를 **한 번** 묻고 다음 회전까지 **≤ 300 m** 면 카드를 미룬다(음성은 `VoiceAnnouncer` 가 이미 읽었다, 로그 `surface: card deferred type=… tbt=…m`). 미룬 카드가 있는 동안만 **1초마다** 다시 묻고(평소엔 묻지 않는다), '회전 후' — ① **다음 회전이 300 m 밖** ② TBT 없음(안내 끝) ③ 모름이 **3번 연달아**(한 번 늦은 응답·재탐색으로 회전 직전에 뜨지 않게, 내비가 아예 답을 못 하면 약 3~5초 뒤) — 이면 미룬 순서대로 올린다(`surface: card released type=… reason=far|no-guidance|unknown tbt=… after=…s`). **회전을 지났어도 다음 회전이 또 300 m 안이면 계속 미룬다**(연속 회전 — 놓으면 그 회전의 TBT 를 가린다, 로그 `surface: card still held — …`). 같은 종류는 최신 1장만 남기고, **120초** 넘게 밀린 카드는 버린다(`surface: card expired …`). **미룬 카드가 있으면 새 카드도 줄 끝에 선다** — 같은 TBT 읽기에서 옛 카드만 올리고 새 카드는 미루는 일이 없고, 줄이 풀릴 때 빈도 한도(5초 2장)에 걸린 카드는(새 카드 포함) 버리지 않고 다음 확인에서 순서대로 나간다(`why=near|tbt-unknown|burst`). 미룬 카드가 없을 때 빈도 한도에 걸린 카드는 전처럼 버린다. **미룬 카드가 없을 때 TBT 를 모르면(타임아웃·미지원·실패·자리표시 항목) 카드를 바로 올린다.** TBT 첫 항목 → 결과는 순수 함수 `nextTurnOf`(자리표시 `TURN_UNKNOWN`·0 m 에 문구 없음 → 모름, docs/10 R16). AVD 차 A 는 안내 중 TBT 가 고정값이라 덮어쓰기 없이는 카드가 120초 뒤 버려진다(docs/09 §1.3). 시계는 단조 시계(`SystemClock.elapsedRealtime`). 진행 상태는 `EventCardState`(held·deferred·released·expired·lastTbt) → 디버그 `surface` 한 줄.

**조용한 상시 알림:** `DriveSessionService` 의 포그라운드 알림은 옛 채널 `drive_session`(IMPORTANCE_LOW, category navigation — Pleos 상단 카드로 떠 내비 TBT 를 가렸다, `b_floating_panel_design.png`)을 지우고 새 채널 **`drive_session_quiet`** 로 올린다. 채널은 IMPORTANCE_MIN(소리·진동·배지 없음)으로 **만들지만** 포그라운드 서비스 알림이라 Android(NotificationManagerService)가 사용자 설정이 없으면 **LOW 로 올린다**(dumpsys 에 importance=2 로 보일 수 있다 — LOW 도 소리·헤드업 없음). Pleos 상단 카드를 막는 핵심은 **`CATEGORY_SERVICE`** 다(category navigation 이 카드로 뜨던 원인; 78dcafd 프로브는 FGS 가 아닌 ongoing 알림으로 확인했고, FGS 알림은 `dumpsys notification` + 순정 내비 화면 캡처로 확인한다). 알림은 `setSilent`·`setOnlyAlertOnce`·`PRIORITY_MIN`·`CATEGORY_SERVICE`·ongoing, **문구 고정 "동행 그룹 주행 중"**, 내용 갱신 없음. 내비 위에 뜨는 것은 플로팅 패널과(권한이 없을 때만) 이벤트 알림 카드뿐이다.

**배선·확인:** `surface.DriveSurfaceController`(Application 에서 start) — Activity 생명주기 등록, 권한 감시·`SurfaceState`·`EventCardNotifier` 시작, `PanelKeeper`(순수 코루틴 로직)가 `panelVisible` 과 서비스의 `shownState`(창이 실제로 붙었는지)를 함께 보고 패널 서비스를 시작/종료 — 붙지 않으면(백그라운드 시작 제한 `IllegalStateException`, addView 실패 뒤 stopSelf, 시스템의 유휴 서비스 정리) 3초부터 두 배씩(최대 30초) 다시 시작하고 시도·실패를 `describe()` 의 `keeper=` 에 남긴다. Hilt 바인딩 `di/SurfaceModule`. 로그 `surface: mode=…`, `surface panel: shown corner=… widthPx=… scale=…`, `surface: card <종류> id=… category=… tbt=…`, `surface: card deferred|released|expired …`. debug 리시버 액션 `surface`(상태 한 줄 — 카드 `held`(미룬 수)·`lastTbt`, `tbt=override=…`)·`surface_pos corner=…`(모서리 지정)·`event type=…`(로컬 이벤트로 패널 소식 줄·카드·음성 확인, 결과 `card=POSTED|DEFERRED|SKIPPED`)·`tbt --ei m <거리> --ei for_s <초>`(카드 게이트가 읽는 TBT 를 잠시 덮어쓰기, `m=-1` 해제 — AVD 순정 내비는 위치가 고정돼 TBT 가 늘 같다). 테스트: `SurfacePolicyTest`·`FloatingPanelMapperTest`·`EventCardPolicyTest`(+ `CardThrottle`, PANEL 미게시)·`TurnCardGateTest`(≤ 300 m 미룸·300 m 밖에서 게시·연속 회전 계속 미룸·모름 → 즉시(미룬 카드 없을 때)·미룬 중 모름 1번은 유지·3번 연달아 놓음·120초 폐기·PANEL 미게시·1초 재조회는 미룬 동안만·줄이 있으면 새 카드도 줄 끝(빈도 한도에 버리지 않음)·같은 종류 최신·`TurnProbe` 덮어쓰기)·`NextTurnTest`(자리표시 TBT → 모름)·`SurfaceStateTest`·`SurfaceSignalsTest`(`PanelKeeper` 재시작·백오프, 권한 주기 확인, `NaviLauncher.choose`)·`DriveDashboardMapperTest`.

## 6. 백그라운드 동작
- 그룹 활성 중에는 **포그라운드 서비스**(`DriveSessionService`)가 텔레메트리·MQTT·음성을 담당 → 다른 앱이 화면을 차지해도 동작.
- 그룹 비활성 시 서비스 종료(불필요한 상주 금지, Pleos 리소스 가이드).
- 앱 프로세스 재생성 시 `activeGroupId`로 자동 재연결.
- **(T23 구현 메모)** `domain.telemetry.TelemetryCollector`(싱글턴, 앱 시작 시 start): `MqttSessionManager.session` 이 non-null 인 동안 1초마다 `Telemetry` 를 `dh/v1/vehicle/{vid}/telemetry` 에 QoS 0 으로 발행한다.
  위치 = `LocationFeed.fixes` 최신 Fix(10초보다 오래됐거나 없으면 그 틱은 건너뜀 — 가짜 위치 금지), 속도 = `VehicleSignals.speedKph`(Car API) → 없으면 `LocationFeed.speedKph`(Haversine), 기어 = 차량 신호(UNKNOWN 은 null),
  ETA = `NaviEventMonitor.state` 의 마지막 TripInfo(120초 이내)를 **30초마다 또는 거리 500 m/시간 60 s 이상 변화 시** 포함(`destTs = tripTs + remainS`), 에너지 = 연료/SoC **1%p 변화 시 + 60초마다 재전송**.
  발행 실패(연결 없음)는 세기만 하고 재전송하지 않는다. 의존은 전부 함수/StateFlow(`di/SignalsModule` 에서 배선)라 JVM 단위 테스트로 검증한다.
  `service.DriveSessionService`(포그라운드, `foregroundServiceType="location|dataSync"` — 위치 권한이 있으면 location, 없으면 dataSync 로 시작, 둘 다 실패해도 크래시 없이 계속) 는 `DriveSessionController` 가 그룹 세션 유무를 보고 시작/종료한다. 서비스는 알림 하나로 프로세스 우선순위만 올리고, 수집·발행은 Application 싱글턴이 한다. 알림은 조용한 채널 `drive_session_quiet`(MIN 으로 만들지만 FGS 라 시스템이 LOW 로 올릴 수 있음, `CATEGORY_SERVICE`·문구 고정 — §5.2)이다.
- **(T16 구현 메모)** MQTT 접속은 그룹 전에도 유지한다: 폰(companion)이 이 차를 그룹에 넣는 순간 서버가 `dh/v1/vehicle/{vid}/cmd` 로 `GROUP_JOINED` 를 보내므로(docs/03 §5.5, T18) 차량은 페어링만 돼 있으면 cmd 를 듣고 있어야 한다. `MqttSessionManager` 가 Application 에서 시작해 페어링 상태(TokenStore)를 보고 붙고 끊으며, `GROUP_JOINED` 를 받으면 `GroupSessionStore`(DataStore `group_session`)에 저장하고 그룹 `state/event` 를 구독한다. 포그라운드 서비스(T23)는 이 연결을 백그라운드에서 유지하는 역할만 더한다.

※ 차량 앱은 QR 문자열을 직접 만들지 않는다. 페어링 QR(verifyUri)·그룹 QR(invite.url)은 서버 응답을 그대로 표시한다(도메인 비의존) — 서버를 바꿔도 앱 쪽 변경 없음.
```

**T32 — 클라우드 기본 · 숨은 서버 주소 메뉴 · MQTT WSS 자동 전환**
- **release 기본 = 클라우드**: release buildType 이 `https://{dhCloudHost}` / `ssl://{dhCloudHost}:8883` 를 BuildConfig 에 넣는다. VM IP 를 받으면 gradle.properties 의 `dhCloudHost=` 를 채우거나 `-PdhCloudHost=` 로 준다(공개 주소 — 비밀 아님). VM IP 가 바뀌면 재빌드 대신 숨은 메뉴로 바꿀 수 있다.
- **숨은 메뉴 '서버 주소'** (`feature/settings/ServerAddressDialog`): 설정 화면 제목을 **3초 안에 5번 탭**(`HiddenTapCounter`) — 주행 중에는 탭을 세지 않고, 열려 있어도 저장·복원 버튼이 꺼진다(§4).
  지금 유효값과 출처(빌드 기본값/사용자 지정), 빌드 기본값을 보이고 서버 주소·MQTT 주소(비우면 페어링 응답 `mqtt.uri`)를 받는다.
  검증(`ServerAddressRules`): 서버 주소는 경로 없는 `http(s)://호스트[:포트]`(API 가 `/v1/…` 절대 경로라 경로 접두는 못 쓴다, 기본 포트 80·443 은 지워 저장 — 같은 서버인지는 scheme·host·port origin 으로 비교), 평문 http 는 `BuildConfig.DH_CLEARTEXT_HOSTS`(open = `*`, cloud = 로컬 3개) 안에서만, MQTT 는 `MqttUriPolicy` 규칙(새 서버 기준 https 면 평문 금지).
  정규화: 서버 주소는 빌드 기본값과 같은 origin 이면 '사용자 지정 아님'. **MQTT 는 빈 값만 '지정 안 함'**(= 페어링 응답) — 빌드 기본 MQTT 주소와 같은 값도 사용자 지정으로 저장한다(서버의 `DH_MQTT_PUBLIC_URI` 가 빠져 응답이 `tcp://` 라 거부될 때 바로 그 값으로 고치는 메뉴라서). BuildConfig `DH_MQTT_PUBLIC_URI` 는 접속·표시에 쓰이지 않는다.
  저장 전 확인 창 → `ServerSwitcher.apply`: **서버 주소가 바뀌면 `TokenStore.clear(SERVER_CHANGED)`**(차량 JWT 는 그 서버의 RS256 키로 서명돼 다른 서버·EMQX JWKS 에서 무효) → `MqttSessionManager` 가 토큰 Empty 를 보고 MQTT 를 끊고 그룹 세션을 정리(기존 경로) → 폰에서 다시 연결. 시계도 새 서버로 다시 맞춘다(`ClockSync.resync`). **MQTT 주소만 바뀌면** 같은 자격 증명으로 끊었다 다시 붙는다. 어느 쪽이든 기억한 MQTT 전송은 지운다. [기본값 복원] = 사용자 지정 삭제(같은 규칙).
  `ServerSwitcher` 는 앱 수명 범위(자체 `SupervisorJob` + IO)에서 돈다 — 설정 화면을 벗어나 ViewModel 이 취소돼도 주소 교체·토큰 삭제·재연결이 반쯤 멈추지 않고(`await` 만 취소), `commit()`·MQTT 끊기(최대 3 s)가 메인 스레드를 막지 않는다.
  REST 는 `ServerHostInterceptor`(OkHttp, 로깅·인증 인터셉터보다 앞)가 Retrofit base(빌드 기본값) origin 으로 가는 요청의 scheme·host·port 만 유효값으로 바꾼다 — Retrofit·API 인터페이스 재생성 없음, 토큰 갱신 전용 클라이언트에도 같은 인터셉터. 저장: SharedPreferences `server_config`(인터셉터가 요청마다 동기로 읽으므로 DataStore 대신). 홈 빌드 정보·진단 빌드 카드의 서버 주소는 유효값 + "(사용자 지정)", **MQTT 주소는 실제로 쓰는 값**(`MqttAddressDisplay`): 사용자 지정 "(사용자 지정)" > 지금 자격 증명의 `mqtt.uri` "(서버가 준 주소)" > 페어링 전 "페어링하면 서버가 알려 줘요". 실제 전송(wss 폴백 등)은 진단 MQTT 카드 '브로커'·'전송'.
- **MQTT WSS 자동 전환** (`MqttTransportFallback` 순수 로직 + `HiveMqttGateway`): 서버 주소(유효값)가 https 면 후보 = [기본 전송(서버 응답/사용자 지정, 클라우드 `ssl://…:8883`), 파생 `wss://{베이스 호스트}[:{베이스 포트}]/mqtt`(기본 443)]. 파생 규칙은 docs/03 머리말 — 서버 응답(protocol)은 바꾸지 않는다. http(로컬)면 후보는 하나(1883 직결).
  - 실패 분류(`mqttFailureKind`, 원인 사슬): CONNACK 응답(인증 거부 등) = 브로커에 닿음 · DNS 실패(`UnknownHostException`)·`ENETUNREACH` = 망 없음(터널·시동 직후 — 후보가 같은 호스트라 전송을 바꿔도 같다) → **둘 다 세지 않고** 연속 실패도 지운다 · 그 밖(거부·시간 초과·TLS/WebSocket 핸드셰이크 실패·`EHOSTUNREACH`) = 닿지 못함. `EHOSTUNREACH` 는 방화벽 ICMP host-prohibited 거절(firewalld 기본)에서도 나와 8883 차단 신호일 수 있어 센다. 연결됐다 끊긴 것도 실패 아님.
  - 전환 조건 ① 닿지 못한 시도가 **연속 2회** → 재연결 직전 `reconnector.transportConfig(…)` 로 전송만 바꾼다(같은 클라이언트·clientId·세션). ② **첫 연결이 10 s 안에 안 됨**(소켓·TLS 가 매달리는 8883 차단망 — 아직 붙은 적·전환한 적·브로커 응답(인증 거부 뒤 갱신 대기 포함)·망 없음이 없을 때 한 번) → 다음 전송을 **정해만 두고** 매달린 시도가 끝나면(실패 콜백) 또는 다음 시도 직전(gate 콜백)에 같은 클라이언트에 적용한다 — 클라이언트를 새로 만들지 않아 늦게 붙은 이전 연결이 새 연결의 세션을 빼앗고(EMQX session taken over) LWT offline 을 내보내는 일이 없다. 매달린 시도가 늦게 붙거나 브로커 응답·망 없음으로 끝나면 그 전환은 무른다.
  - 다음 시도 대기: 마지막 연결 뒤 **한 바퀴 안**의 새 전송은 1 s 뒤 곧바로, **후보를 한 바퀴 다 돈 뒤**(망·서버 문제일 가능성)는 계속 번갈아 시도하되 정상 백오프(1 s → 30 s)·로그 INFO 로 — 서버 다운 중 재시도가 두 배가 되거나 WARN 이 30초마다 쌓이지 않는다.
  - WebSocket: HiveMQ `transportConfig().sslWithDefaultConfig().webSocketConfig().serverPath("mqtt").subprotocol("mqtt")` — 시스템 신뢰 저장소 TLS(Let's Encrypt, API 28 포함). `io.netty:netty-codec-http:4.1.115.Final` 을 직접 의존(HiveMQ POM 에서 optional — 없으면 wss 사용 시 NoClassDefFoundError).
  - 기억: **다른 전송이 실제로 실패한 뒤 한 바퀴 안에 붙은 전송만** SharedPreferences `mqtt_transport`(`{브로커 호스트}|{tls|wss}`)에 남겨 다음 시작에 먼저 시도, 그 전송이 같은 조건으로 실패하면 반대로 돌아간다(그 전송으로 붙으면 기억을 고친다). 망 없음·인증 거부·한 바퀴 다 실패(서버 다운)로는 바뀌지 않는다 — 망이 돌아온 순간의 전송이 우연히 기억돼 8883 이 열린 망에서도 wss 로 고정되는 일이 없다. 서버 주소를 바꾸면 지운다.
  - 관측: 로그 `mqtt transport fallback → wss (from tls: 2 failed attempts cause=…) broker=<host>:443` 또는 `… (from tls: not connected in 10s — applied at next attempt) …` + `mqtt transport wss applied after the hung tls attempt ended`, `mqtt connected broker=<host>:443 transport=wss …`; `MqttStatus.transport`(tcp/tls/ws/wss)·`transportFallbacks` → 진단 MQTT 카드 '전송', 30초 `health … tr=wss …`.
  - 단위 테스트: 결정은 `MqttTransportFallbackTest`(실패 종류·한 바퀴·시간 초과 무르기·인증 거부 뒤 시간 초과 → 전환 없음·기억 규칙), 배선은 `HiveMqttGatewayFallbackTest` 가 실제 HiveMQ 클라이언트를 로컬 소켓(받자마자 닫는 서버 / 3 s 붙잡는 서버, EMQX 없음)에 붙여 ssl 2회 실패 → 같은 클라이언트 wss 전환, 시간 초과 → 매달린 시도가 끝난 뒤에야 wss 시도를 확인한다.
- 남은 것(VM 수령 후, docs/08 T32): 실 VM 에서 ssl 8883 연결·WSS 폴백(숨은 메뉴 MQTT 주소에 닫힌 포트 `ssl://<VM-IP>.sslip.io:8884` → 거부면 2~3 s, 방화벽이 버리면 약 10 s 뒤 `→ wss`) 로그·진단 캡처.

## 8. T33 구현 메모 — 토큰 수명·저장소 오류·재연결·로그 보존
배경: docs/10 R13 — 확인 창 없는 해제 버튼이 토큰을 지웠고, `MqttSessionManager` 가 토큰 Empty 를 보면 사유 불문 그룹 세션까지 지웠다. 차량 토큰(24h)에는 갱신 흐름이 없어 만료 뒤 REST 401·MQTT 인증 거부 무한 재연결인데 홈은 '연결됨' 인 상태가 될 수 있었다.

**토큰 저장소 상태** (`core/common/TokenStore`)
```
Loading ─ load() ─┬─ Present(credentials)
                  ├─ Empty                 ← 미페어링 / clear(reason)
                  └─ Unavailable(reason)   ← 생성·읽기 예외(Keystore·SecurityException·IOException…). 지운 게 아니다
```
- `EncryptedTokenStore` 는 생성 실패를 프로세스 동안 고정하지 않는다 — 다음 `load()`/`save()` 가 다시 만든다. 쓰기 실패는 이번 실행 동안만 메모리에 두고(Present 유지) E 로그·`dh_diag` 기록.
- `clear(reason: TokenClearReason)`: `USER_SETTINGS_DISCONNECT`·`USER_REPAIR`·`TOKEN_REVOKED_CMD`·`REFRESH_REJECTED`·`SERVER_CHANGED`(T32 런타임 서버 변경용)·`STORE_RESET`(설정 '저장소 초기화' — `dh_tokens` 파일째 삭제). 암호화 파일을 열 수 없으면 파일째 지운다.
- `updateTokens(expectedRefresh, access, refresh)`: refresh 회전 결과를 한 번의 commit 으로, 보낸 refresh 가 아직 저장돼 있을 때만(compare-and-set) — 갱신 도중의 연결 해제를 되살리지 않는다.
- `clearIf(expectedRefresh, reason)`(T33 리뷰): 저장된 refresh 가 보낸 것과 같을 때만 지운다 — 비교·삭제가 저장소 잠금 안에서 한 번에라, 갱신 응답을 기다리는 사이 재페어링한 새 자격 증명을 옛 401 이 지우지 않는다.
- `StoredCredentials`·`TokenStoreState.Present` 의 `toString()` 은 마스킹 값만(vehicleId·ownerId 앞4+뒤2, 토큰 앞 4자+길이, 닉네임 첫 글자) — 상태를 통째로 문자열에 넣어도 logcat·링 버퍼·`dh_log.txt` 에 원문이 남지 않는다(규칙 8, T33 리뷰).
- `GroupSessionStore.clear(reason: SessionClearReason)`: `UNPAIRED`(토큰 Empty 일 때만)·`GROUP_ENDED`·`MEMBER_LEFT_ME`·`LEFT_LOCALLY`·`STORE_CORRUPT`. DataStore `group_session` 에 `ReplaceFileCorruptionHandler` — 손상이면 빈 값으로 갈아 끼우고 `STORE_CORRUPT` 기록, 해석 불가 세션도 비운다. 읽기 I/O 오류는 '세션 없음'(파일 유지).
- 삭제 기록: 일반 SharedPreferences `dh_diag` 에 마지막 토큰 삭제·세션 삭제·저장소 오류의 사유·시각·마스킹 ID(`ClearRecord`) + `DhLog.i("token store: cleared reason=… vehicleId=veh_…7Q")`. 설정 '마지막 해제', 진단 '토큰·저장소' 카드에 표시.

**MqttSessionManager** — Present: 접속·구독. Empty: 옛 cmd 토픽 구독 해제·끊기·세션 `UNPAIRED` 삭제. **Unavailable: 세션 유지, 연결 안 함, 30 s 간격 최대 10회 `load()` 재시도**(홈 '다시 시도' 가 처음부터 다시). `start()` 의 코루틴에 `CoroutineExceptionHandler`, 단계마다 예외를 삼켜 수신 루프가 끊기지 않게 했다. cmd `TOKEN_REVOKED` 는 `clear(TOKEN_REVOKED_CMD)` — 단 봉투 `ts`(epoch ms, 서버 시계)를 초로 내린 값 ≤ 지금 토큰 `iat`(초)면 재페어링 전 MQTT 영속 세션(clientId = vehicleId, 세션 만료 300 s)에 쌓였다 늦게 온 것이라 무시한다(같은 초도 무시 — 해제 직전 같은 초에 갱신된 토큰은 남을 수 있다). 300 s 넘게 오프라인일 때의 해제는 cmd 가 사라진다 — 다음 갱신 401 까지 '연결됨' 으로 남는 한계(docs/03 §1.3). 단계별 예외 로그에는 상태 객체가 아니라 종류 이름만 넣는다(`token state Present`).

**차량 토큰 갱신** (`domain/pairing/TokenRefresher`, 싱글턴, `DongHaengApp` 에서 start)
- 선제: 앱 시작 직후·30분마다 JWT payload `exp`(base64url, 서명 검증 없음 — `JwtClaims`)를 보고 남은 시간 ≤ 2시간이면 `POST /v1/auth/refresh`.
- REST 401: `VehicleTokenAuthenticator`(OkHttp `Authenticator`) → `runBlocking { refreshAfterRejection(거부된 토큰) }` → 새 Bearer 로 1회 재시도. `/v1/auth/*`·`/v1/device/*`·`priorResponse` 있음·Bearer 없음은 제외. 갱신 호출은 **Authenticator 가 없는 별도 OkHttpClient**(`@RefreshClient IdentityApi`, 자기 Dispatcher) — 기본 클라이언트 스레드가 막혀도 호스트당 동시 요청 한도에 걸려 교착하지 않는다.
- MQTT: `HiveMqttGateway` 의 disconnected 리스너가 cause 의 `Mqtt5ConnAckException` reasonCode `NOT_AUTHORIZED`/`BAD_USER_NAME_OR_PASSWORD` 를 보면 `authFailures` 로 알리고(`MqttStatus.authFailures`·`lastAuthFailureAtMs`) 재연결을 최대 15 s 미룬다 → `MqttSessionManager` 가 갱신 → 저장소가 새 토큰을 내면 `connect(새 토큰)` 이 대기 중인 재연결을 즉시 연다.
- single-flight `Mutex`: 기다리는 동안 다른 호출이 회전했으면(거부된 토큰 ≠ 현재 토큰) 서버를 다시 부르지 않는다. 방금(60 s 안) 받은 토큰이 또 거부되면 회전하지 않고(`Throttled`), MQTT 발 시도는 30 s 간격.
- **MQTT 발 회전 백오프**(T33 리뷰): 회전한 새 토큰도 브로커가 거부하면(EMQX JWKS 캐시·kid 불일치·authn 설정 등 토큰과 무관한 원인) 다음 MQTT 발 회전까지 1→2→4→8→16→30분. MQTT 가 CONNECTED 가 되면(`MqttSessionManager` → `TokenRefresher.onMqttConnected()`) 처음부터. 백오프 중 `Throttled` 는 구간마다 W 한 줄만(`token refresh backoff … streak=N`). 단계는 `TokenRefreshState.mqttRotationStreak` → 진단 'MQTT 발 갱신 백오프'·health `mqttRot`.
- 결과(T33 리뷰 반영): refresh 401 은 본문 `code == INVALID_TOKEN` 일 때만 자격 증명 문제(그 밖의 401 은 프록시·캡티브 포털일 수 있어 `Failed`, 토큰 유지).
  - 선제 갱신(STARTUP/PERIODIC/MANUAL)이 401 인데 access token 이 아직 유효 → `RejectedDeferred`: 지우지 않고 `repairNeededSinceMs` → 홈 '다시 연결이 필요해요 — HH:mm 까지는 지금처럼 동작'. 다음 점검은 만료 직후(+5 s)로 당겨져 그때 401 이면 지운다. 회전 응답 유실(서버 커밋 뒤 타임아웃) 때 그룹 세션까지 즉시 지워지던 문제(R13 과 같은 결과)를 막는다.
  - 실제 거부(HTTP_401/MQTT_AUTH) 뒤 401, 또는 access token 도 만료 → `clearIf(보낸 refresh, REFRESH_REJECTED)` → 홈 '폰에서 다시 연결해 주세요'.
  - 네트워크·5xx → 토큰 유지. 선제 갱신이면 20 s 뒤 한 번 더(서버 재사용 유예 60 s 안 — docs/03 §1.1), 그다음은 30분(만료 시각을 넘기지 않음). `ApiResult.HttpFailure.Unauthorized`(401) 하위 타입.
- `TokenRefreshState.accessExpiresAtMs` 는 저장소 상태를 구독해 재페어링·해제·회전 즉시 갱신(진단 '토큰 만료'·health `expMin` 이 옛 토큰 값으로 남지 않게).
- 그룹 화면 REST 401: 자격 증명이 서버 사유(`REFRESH_REJECTED`·`TOKEN_REVOKED_CMD`)로 지워졌을 때만 '폰에서 다시 연결', 그 밖(갱신 네트워크 실패·백오프)은 '연결을 확인하고 잠시 후 다시 시도해 주세요'.

**재연결** (`HiveMqttGateway`): automaticReconnect 는 켜 두되 대기 시간은 게이트웨이가 정한다 — 끊길 때마다 `reconnector.delay(0)` + `reconnectWhen(gate)` 로 다음 시도를 우리 타이머(1 s → 30 s 지수 백오프 ±20 %, 인증 거부는 ≥ 15 s)에 묶고, 시도 직전 콜백에서 최신 토큰을 다시 싣는다(HiveMQ 1.3.4 javap: `connectWith`·`reconnect(false)` 는 이벤트 루프면 콜백에서도 가능, `reconnectWhen`·`delay` 는 리스너 안에서만). 앱이 끊거나 클라이언트를 갈아 끼우면 이전 클라이언트는 retired — 콜백이 `reconnect(false)` 로 대기 중 재연결을 취소하고, 늦게 붙으면 바로 끊는다(같은 clientId 두 개가 서로 밀어내지 않게). 토큰만 바뀌면(갱신) 연결은 유지 — EMQX 가 옛 토큰 `exp` 에 끊으면 다음 재연결이 새 토큰을 쓴다.
