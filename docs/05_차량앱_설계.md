`pleos.car.permission.*` 와 `android.car.permission.CAR_POWERTRAIN` 은 normal(설치 시 자동 승인, 런타임 팝업 없음 — 공식 샘플 가이드).

(그룹 세션 시작 시점, T22/T23), 거부 시 속도는 Haversine 계산으로 폴백한다(`VehicleCapabilities.speed=false`, §3.2). 위치·알림 권한은 그룹 세션이 시작되기 전에는 요청하지 않는다.

### 3.1 Pleos SDK 사용 규칙 (공식 문서·샘플 기준)
- `Vehicle(context).initialize()` 후 `vehicle.getFuel()` 등 `getXxx()`로 도메인 객체를 얻는다. 사용이 끝나면 `vehicle.release()`.
- get·set·capability 결과는 `onComplete`/`onFailed` 비동기 람다. **콜백이 끝나기 전에 release 금지.**
- 구독은 `registerXxx(listener)` / `unregisterXxx(listener)` — **등록한 같은 리스너 객체·같은 area로 해제.**
- 지원 여부를 먼저 `checkXxxCapabilities`로 확인하고, 미지원이면 그 기능을 UI에서 숨긴다.
- NaviHelper: `NaviHelper(context)` → `initialize()` → `addListener(NaviHelperEventListener)` → 요청 → `removeListener` → `release()`.
  - 경로 요청 데이터: `RouteInfo(latitude, longitude, poiId, poiName, poiSubId, address)`,
    `RequestWaypointInfo(..., waypointIndex = WaypointIndex.FIRST, ...)`, `RouteWithWaypointsRequest(destination, waypoints)`
  - 사용하는 콜백: `onCurrentLocationInfo`, `onTripInfo`, `onDrivingInfo`, `onRouteStateInfo`, `onDestinationChanged`,
    `onWaypointChanged`, `onWayPointArrived`, `onDestinationArrived`, `onRouteStarted`, `onRouteEnded`, `onRouteCancelled`,
    `onCurrentRoadSpeedLimit`, `onNavigationStatus`, `onError`
  - 실제 전달되는 이벤트는 Navigation 앱 상태에 따라 다를 수 있으므로 **모든 필드를 nullable로 다룬다.**
- 데이터 클래스 필드명은 SDK 버전에 따라 다를 수 있다 → 어댑터 안에서만 SDK 타입을 다루고, 밖으로는 우리 도메인 타입으로 변환.
- **T20 구현 메모 (`PleosNaviAdapter`, NaviHelper 3.0.5 javap 확인):**
  - `events()` 는 `callbackFlow` — 구독마다 리스너 1개 등록, `awaitClose` 에서 같은 리스너로 `removeListener`. 안내 중이 아니면 위치 콜백이 없으므로 구독 중 1초마다 `getCurrentLocationInfo()` 를 요청한다(응답은 `onCurrentLocationInfo`). 구독 시작 시 `getRouteStateInfo()`·`getDestinationInfo()` 1회.
  - `onDestinationChanged()` 는 인자가 없다 → `getDestinationInfo()` 재요청 → `onDestinationInfo(DestinationInfo)` 를 `DestinationChanged(Place)` 로. `onWaypointChanged` 도 같은 방식으로 `getWaypointInfo()` → `onWayPointInfo(List)`.
  - SDK `TripInfo(distance, eta)` 와 `DrivingInfo.destination(DrivingState duration/distance)` 둘 다 도메인 `TripInfo` 로 보낸다. `onWayPointArrived`/`onDestinationArrived` 는 이름·주소만 주므로 마지막으로 알던 목적지·경유지 목록에서 `Place` 를 찾아 채운다.
  - `onCurrentRoadSpeedLimit` 는 AVD 에서 1Hz 로 같은 값(0)이 반복돼 **값이 바뀔 때만** `SpeedLimit` 이벤트로 올린다. `onNavigationStatus` 의 `isGuiding` = `ROUTE_DRIVE`.
  - `currentDestination()` = 임시 리스너 등록 → `getDestinationInfo()` → `onDestinationInfo` 2초 대기(없으면 null). `showNavigation()` = `requestNavigationScreen(NavigationScreenRequest.RouteOptionList)` — **`pleos.car.permission.NAVI_CUSTOM_MAP` 필요**(SDK 가 검사하는 권한: NAVI_ROUTE, NAVI_ROUTE_SEARCH, NAVI_CUSTOM_MAP, NAVI_CUSTOM_ROUTE, NAVI_CUSTOM_ETC(InternalApi)).
  - 확인 화면: 진단 → "내비 이벤트 (T20)" 카드(콜백 종류별 수·마지막 값·확인용 요청 버튼), 캡처 `docs/images/t20/`.
  - 도메인 `WaypointIndex.FIRST/LAST` → SDK `WaypointIndex.FIRST/SECOND`(SDK 는 경유지 2개까지). `RouteInfo`/`RequestWaypointInfo` 는 named-arg 로 생성(`poiSubId="0"`, `routeOption=RECOMMENDED`).
  - 앱 전체에서 리스너는 `NaviEventMonitor`(싱글턴) 하나만 구독하고 나머지(T23 텔레메트리, T26 이벤트, 진단 화면)는 그 `events` SharedFlow / `state` 를 쓴다. 스트림이 끝나거나 예외면 10초 뒤 재구독.
  - `FakeNaviAdapter` 는 `assets/gpx/lead.gpx`·`follow.gpx`(직선 보간 가상 경로, 약 57 km) 를 틱당 `speedMps` 로 재표본화해 1Hz 재생 — heading 은 다음 점 방향, 10틱마다 `TripInfo`(경로 잔여 거리/시간)·`DrivingInfo`, 경유지 60 m 이내 `WaypointArrived`, 종점에서 `DestinationArrived`+`RouteStateInfo(ENDED)` 1회 후 정지. GPX 가 없으면 기준점 드리프트로 폴백.

### 3.2 위치 소스 우선순위
1. `FusedLocation.isSupported()` 와 `pleos.car.permission.FUSED_LOCATION` 런타임 승인이 **모두** true → FusedLocation (선택 사항 — Playground 상 "준비 중"이지만 SDK는 배포됨, 에뮬레이터에서 런타임 확인. 없어도 아래 체인으로 동작, CLAUDE.md 규칙 5)
2. NaviHelper `onCurrentLocationInfo` (주력 대안)
3. Android `LocationManager` (AAOS 표준)
4. Fake (GPX 재생, 개발·데모용)

속도: Car API → 실패 시 연속 위치로 계산(Haversine / Δt, 3샘플 이동평균).

**T21 구현 메모:**
- `adapter.location.LocationSource`(source, isAvailable, staleTimeoutMs, locations) 를 `CompositeLocationAdapter` 가 순서대로 시도한다. 첫 Fix 10초 / 이후 소스별 stale(기본 5초, Android 15초) 안에 Fix 가 없거나 스트림이 끝나면 다음 순위, 끝까지 실패하면 5초 뒤 처음부터. 하위 소스를 쓰는 동안 60초마다 상위 소스를 **병렬로** 짧게 구독해 Fix 가 실제로 오면 올라간다(탐색 중에도 현재 Fix 는 계속 흘러 1Hz 에 구멍이 없다). 발행 `Fix.source` 는 실제 소스.
- 소스: `PleosFusedLocationAdapter`(pleos: `FUSED_LOCATION` 승인 && `isSupported()` 일 때만 가용, register/unregister 같은 리스너, `confidence` 는 미터가 아니라 accuracy=null) → `NaviLocationSource`(`NaviEventMonitor.events` 의 CurrentLocation — 리스너 중복 없음) → `AndroidLocationSource`(FINE 승인 + GPS/NETWORK provider, 30초 이내 lastKnown 먼저, 1초/0 m 업데이트) → `FakeLocationAdapter`(항상, 고정점).
- `domain.location.LocationFeed`(싱글턴, 앱 시작 시 start): 체인을 한 번만 구독해 `fixes`(replay 1)·`speedKph`·`state` 제공. 소스가 바뀌면 `SpeedEstimator` 리셋. T23 텔레메트리·T26 이벤트는 이걸 구독한다. 권한이 바뀌면 `restart()`.
- `SpeedEstimator`: Δt<0.5s 샘플은 기준점 유지, Δt>10s 면 창 초기화, 250 km/h 초과는 튐으로 무시, 3샘플 평균.
- 권한 요청 시점: `feature.permissions.LocationPermissionGate`(NavHost 옆) — **활성 그룹 + 정차** 일 때 1회 `ACCESS_FINE/COARSE_LOCATION`(+API 33 `POST_NOTIFICATIONS`) 요청, 결과와 무관하게 체인 재탐색. 진단 화면 "위치 소스 (T21)" 카드에도 요청·재탐색 버튼.
- Pleos AVD 실측(2026-10-27): `FUSED_LOCATION` 이 미승인으로 나와 FUSED 건너뜀 → NAVI 첫 Fix 없음(내비 앱 미동작) → ANDROID gps 활성. `adb -s emulator-5556 emu geo fix <lon> <lat>` 를 1Hz 로 이동시키면 속도 ≈ 62 km/h 로 계산된다. fake flavor 는 NAVI(FakeNaviAdapter GPX) 가 활성.

### 3.2.1 차량 신호 구현 메모 (T22)
- `PleosVehicleAdapter` 신호 Flow 는 공통 골격 `vehicleFlow(name) { v -> register…; 현재값 1회 조회; Cleanup { unregister(같은 리스너) } }` — SDK 없으면 빈 스트림, 미지원(onFailed)은 `null` 한 번 후 종료(Int 계열) / 빈 스트림(Boolean 계열).
  리스너 파라미터는 **nullable**(`Int?`, `Boolean?`, `TurnSignalValue?`, `VehicleGear?`; javap + 컴파일 실측), `onFailed(Exception)` 은 non-null.
- 에어백: `checkAirbagDeployedCapabilities` 가 준 좌석 영역마다 `registerSeatAirbagDeployed(area, listener)` → 하나라도 true 면 true. AVD 는 check 자체가 실패 → 빈 스트림.
- 속도: Pleos SDK 에 없음 → `CarApiSignals`(AAOS `android.car`, `useLibrary("android.car")` + pleos 매니페스트 `uses-library required=false`) `PERF_VEHICLE_SPEED`(m/s×3.6). dangerous 권한 `CAR_SPEED` 는 `LocationPermissions.runtimePermissions()` 가 자동차 기기에서만 묶어 요청. 기어: Pleos `Gear.registerGearSelection`(check 메서드 없음 → 현재값 조회로 capability 판정) → 실패 시 Car API `GEAR_SELECTION`.
  Car API 속성 목록은 앱 시작 직후 비어 있을 수 있어(AVD 실측) probe 를 1.5초 간격 3회 재시도한다.
- `domain.vehicle.VehicleSignals`(싱글턴, 앱 시작 시 start): 신호마다 독립 코루틴으로 구독해 최신값·수신 수·스트림 상태를 `state` 로 제공, 끝난/실패한 스트림은 30초 뒤 재구독, 값이 바뀔 때만 로그 `vehicle signal fuel=61`. T23 텔레메트리·T26 이벤트는 이걸 쓴다(어댑터 Flow 를 직접 또 구독하지 않는다).
- AVD 실측(2026-10-27, Virtual Console HTTP): 기어 Reverse → `gear=R`, 브레이크 70% → `brake=true`, 방향지시등 BlinkLeft → `turn=LEFT`, EV SoC 23 → `soc=23`, 속도 55 km/h → `speed=55.0`(Car API). Fuel 은 `property ID is not in carPropertyConfig list` 로 미지원(null), Airbag check 실패 → 빈 스트림.
- Virtual Console 을 스크립트로 조작하려면 `adb forward tcp:8089 tcp:8088` 뒤 **`POST /browser/session` 을 1초마다 보내 세션을 살려 두고**(timeout 3초, 없으면 PUT 이 503) `PUT /vehicle/gear?gear=Reverse`, `PUT /vehicle/controls?speed_kph=55&brake_pct=70`, `PUT /vehicle/turn-signal?mode=BlinkLeft`, `PUT /vehicle/ev-battery?field=soc&value=23`; 상태는 `GET /vehicle/state`, 항목 목록은 `GET /vehicle/catalog`(`write_endpoint`·`control.field`).

### 3.3 급제동 판정 (EventDetector)
- 조건: 브레이크 ON && (1초 내 속도 감소 ≥ 14.4 km/h ≈ 4 m/s²) && 직전 속도 ≥ 40 km/h
- 쿨다운 30초. 서버도 120초 중복 억제.

## 6. 백그라운드 동작
- 그룹 활성 중에는 **포그라운드 서비스**(`DriveSessionService`)가 텔레메트리·MQTT·음성을 담당 → 다른 앱이 화면을 차지해도 동작.
- 그룹 비활성 시 서비스 종료(불필요한 상주 금지, Pleos 리소스 가이드).
- 앱 프로세스 재생성 시 `activeGroupId`로 자동 재연결.
- **(T23 구현 메모)** `domain.telemetry.TelemetryCollector`(싱글턴, 앱 시작 시 start): `MqttSessionManager.session` 이 non-null 인 동안 1초마다 `Telemetry` 를 `dh/v1/vehicle/{vid}/telemetry` 에 QoS 0 으로 발행한다.
  위치 = `LocationFeed.fixes` 최신 Fix(10초보다 오래됐거나 없으면 그 틱은 건너뜀 — 가짜 위치 금지), 속도 = `VehicleSignals.speedKph`(Car API) → 없으면 `LocationFeed.speedKph`(Haversine), 기어 = 차량 신호(UNKNOWN 은 null),
  ETA = `NaviEventMonitor.state` 의 마지막 TripInfo(120초 이내)를 **30초마다 또는 거리 500 m/시간 60 s 이상 변화 시** 포함(`destTs = tripTs + remainS`), 에너지 = 연료/SoC **1%p 변화 시 + 60초마다 재전송**.
  발행 실패(연결 없음)는 세기만 하고 재전송하지 않는다. 의존은 전부 함수/StateFlow(`di/SignalsModule` 에서 배선)라 JVM 단위 테스트로 검증한다.
  `service.DriveSessionService`(포그라운드, `foregroundServiceType="location|dataSync"` — 위치 권한이 있으면 location, 없으면 dataSync 로 시작, 둘 다 실패해도 크래시 없이 계속) 는 `DriveSessionController` 가 그룹 세션 유무를 보고 시작/종료한다. 서비스는 알림 하나로 프로세스 우선순위만 올리고, 수집·발행은 Application 싱글턴이 한다.
- **(T16 구현 메모)** MQTT 접속은 그룹 전에도 유지한다: 폰(companion)이 이 차를 그룹에 넣는 순간 서버가 `dh/v1/vehicle/{vid}/cmd` 로 `GROUP_JOINED` 를 보내므로(docs/03 §5.5, T18) 차량은 페어링만 돼 있으면 cmd 를 듣고 있어야 한다. `MqttSessionManager` 가 Application 에서 시작해 페어링 상태(TokenStore)를 보고 붙고 끊으며, `GROUP_JOINED` 를 받으면 `GroupSessionStore`(DataStore `group_session`)에 저장하고 그룹 `state/event` 를 구독한다. 포그라운드 서비스(T23)는 이 연결을 백그라운드에서 유지하는 역할만 더한다.
