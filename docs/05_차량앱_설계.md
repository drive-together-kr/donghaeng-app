`pleos.car.permission.*` 와 `android.car.permission.CAR_POWERTRAIN` 은 normal(설치 시 자동 승인, 런타임 팝업 없음 — 공식 샘플 가이드).
`android.car.permission.CAR_SPEED` 는 dangerous(런타임, 그룹 '차량 정보')로 Pleos AVD 에서 `granted=false` 로 설치된다(dumpsys 실측).
ACCESS_FINE_LOCATION·POST_NOTIFICATIONS·(FusedLocation 사용 시) FUSED_LOCATION 과 함께 **정차 상태(isRequiresDistractionOptimization=false)에서 1회** 요청하고
(그룹 세션 시작 시점, T22/T23), 거부 시 속도는 Haversine 계산으로 폴백한다(`VehicleCapabilities.speed=false`, §3.2). 위치·알림 권한은 그룹 세션이 시작되기 전에는 요청하지 않는다.
`pleos.car.permission.FUSED_LOCATION` 은 Pleos AVD 실측 **dangerous**(2026-11-02 `pm list permissions -f`)라 선언만으로는 '미승인' 이다 — 이 앱이 선언했고(pleos flavor) 기기가 dangerous 로 정의했을 때만 같은 다이얼로그에 넣어 요청한다(`LocationPermissions.fusedRequestable`, A-RT2). 승인되면 위치 체인 재탐색으로 FUSED 가 앞에 붙고, 거부해도 다른 소스로 계속한다(규칙 5).

### 3.1 Pleos SDK 사용 규칙 (공식 문서·샘플 기준)
- `Vehicle(context).initialize()` 후 `vehicle.getFuel()` 등 `getXxx()`로 도메인 객체를 얻는다. 사용이 끝나면 `vehicle.release()`.
- get·set·capability 결과는 `onComplete`/`onFailed` 비동기 람다. **콜백이 끝나기 전에 release 금지.**
- 구독은 `registerXxx(listener)` / `unregisterXxx(listener)` — **등록한 같은 리스너 객체·같은 area로 해제.**
- 지원 여부를 먼저 `checkXxxCapabilities`로 확인하고, 미지원이면 그 기능을 UI에서 숨긴다.
- NaviHelper: `NaviHelper(context)` → `initialize()` → `addListener(NaviHelperEventListener)` → 요청 → `removeListener` → `release()`.
  - 경로 요청 데이터: `RouteInfo(latitude, longitude, poiId, poiName, poiSubId, address)`,
    `RequestWaypointInfo(..., waypointIndex = WaypointIndex.FIRST, ...)`, `RouteWithWaypointsRequest(destination, waypoints)`
  - 사용하는 콜백: `onCurrentLocationInfo`, `onTripInfo`, `onDrivingInfo`, `onRouteStateInfo`, `onDestinationChanged`,
    `onWaypointChanged`, `onWayPointArrived`, `onDestinationArrived`, `onRouteStarted`, `onRouteEnded`, `onRouteCancelled`,
    `onCurrentRoadSpeedLimit`, `onNavigationStatus`, `onError`
  - 실제 전달되는 이벤트는 Navigation 앱 상태에 따라 다를 수 있으므로 **모든 필드를 nullable로 다룬다.**
- 데이터 클래스 필드명은 SDK 버전에 따라 다를 수 있다 → 어댑터 안에서만 SDK 타입을 다루고, 밖으로는 우리 도메인 타입으로 변환.
- **T20 구현 메모 (`PleosNaviAdapter`, NaviHelper 3.0.5 javap 확인):**
  - `events()` 는 `callbackFlow` — 구독마다 리스너 1개 등록, `awaitClose` 에서 같은 리스너로 `removeListener`. 안내 중이 아니면 위치 콜백이 없으므로 구독 중 1초마다 `getCurrentLocationInfo()` 를 요청한다(응답은 `onCurrentLocationInfo`). 구독 시작 시 `getRouteStateInfo()`·`getDestinationInfo()` 1회.
  - `onDestinationChanged()` 는 인자가 없다 → `getDestinationInfo()` 재요청 → `onDestinationInfo(DestinationInfo)` 를 `DestinationChanged(Place)` 로. `onWaypointChanged` 도 같은 방식으로 `getWaypointInfo()` → `onWayPointInfo(List)`. 구독 때 당겨 온 첫 응답(그 사이 `onDestinationChanged` 없음)은 `DestinationChanged(snapshot=true)` — 변경이 아니라 현재값(선두 경로 동기화의 재시작 기준선, RA-1). 로그 `navi onDestinationInfo … snapshot=true|false`.
  - SDK `TripInfo(distance, eta)` 와 `DrivingInfo.destination(DrivingState duration/distance)` 둘 다 도메인 `TripInfo` 로 보낸다. `onWayPointArrived`/`onDestinationArrived` 는 이름·주소만 주므로 마지막으로 알던 목적지·경유지 목록에서 `Place` 를 찾아 채운다.
  - `onCurrentRoadSpeedLimit` 는 AVD 에서 1Hz 로 같은 값(0)이 반복돼 **값이 바뀔 때만** `SpeedLimit` 이벤트로 올린다. `onNavigationStatus` 의 `isGuiding` = `ROUTE_DRIVE`.
  - `nextTurn(timeoutMs)`(SURF 카드 TBT 게이트, §5.2) = 요청마다 리스너를 붙였다 떼는 `callbackFlow`(awaitClose 에서 같은 리스너 제거) → `getTBTInfo()` → `onTBTInfo(List<TBTInfo>)` 의 첫 항목(`TBTInfo(type: TurnType, distance: Double, description: String)`, navi-data 3.0.4 javap). 빈 목록 = `NoGuidance`, 응답 없음(기본 0.8 s)·실패·NaN·음수 = `Unknown`. **`distance` 단위는 문서·공식 샘플(pleos-sample-navi-app 은 toString 로그만)에 없어 미터로 가정**(`TBT_DISTANCE_TO_M = 1.0`) — **2026-10-28 기기 확인: 미터**(차 A `rawDistance=80.0` = 내비 TBT "80m", 첫 항목 = 다음 회전) — 첫 응답 원값을 `navi tbt 첫 응답 … rawDistance=` 로 남기니 기기에서 내비 화면 TBT 숫자와 비교해 확인한다(docs/10 R16). `onDrivingInfo`(DrivingInfo — 목적지·경유지별 남은 거리/시간)는 회전 거리가 아니라 쓰지 않는다. NaviHelper 리스너 목록은 앱 안의 CopyOnWriteArrayList 라 붙였다 떼는 비용이 작다(바인더 호출은 `getTBTInfo` 한 번). Fake 는 GPX 진행 거리 기준 1.2 km 마다 가상 회전(좌우 번갈아, 끝은 `TURN_ARRIVE`, 목적지 없으면 `NoGuidance`).
  - `currentDestination()` = 임시 리스너 등록 → `getDestinationInfo()` → `onDestinationInfo` 2초 대기(없으면 null). `showNavigation()` = `requestNavigationScreen(NavigationScreenRequest.RouteOptionList)` — **`pleos.car.permission.NAVI_CUSTOM_MAP` 필요**(SDK 가 검사하는 권한: NAVI_ROUTE, NAVI_ROUTE_SEARCH, NAVI_CUSTOM_MAP, NAVI_CUSTOM_ROUTE, NAVI_CUSTOM_ETC(InternalApi)).
  - 확인 화면: 진단 → "내비 이벤트 (T20)" 카드(콜백 종류별 수·마지막 값·확인용 요청 버튼), 캡처 `docs/images/t20/`.
  - 도메인 `WaypointIndex.FIRST/LAST` → SDK `WaypointIndex.FIRST/SECOND`(SDK 는 경유지 2개까지). `RouteInfo`/`RequestWaypointInfo` 는 named-arg 로 생성(`poiSubId="0"`, `routeOption=RECOMMENDED`).
  - 앱 전체에서 리스너는 `NaviEventMonitor`(싱글턴) 하나만 구독하고 나머지(T23 텔레메트리, T26 이벤트, 진단 화면)는 그 `events` SharedFlow / `state` 를 쓴다. 스트림이 끝나거나 예외면 10초 뒤 재구독.
  - `FakeNaviAdapter` 는 `assets/gpx/lead.gpx`·`follow.gpx`(직선 보간 가상 경로, 약 57 km) 를 틱당 `speedMps` 로 재표본화해 1Hz 재생 — heading 은 다음 점 방향, 10틱마다 `TripInfo`(경로 잔여 거리/시간)·`DrivingInfo`, 경유지 60 m 이내 `WaypointArrived`, 종점에서 `DestinationArrived`+`RouteStateInfo(ENDED)` 1회 후 정지. GPX 가 없으면 기준점 드리프트로 폴백.

### 3.2 위치 소스 우선순위
1. `FusedLocation.isSupported()` 와 `pleos.car.permission.FUSED_LOCATION` 런타임 승인이 **모두** true → FusedLocation (선택 사항 — Playground 상 "준비 중"이지만 SDK는 배포됨, 에뮬레이터에서 런타임 확인. 없어도 아래 체인으로 동작, CLAUDE.md 규칙 5)
2. NaviHelper `onCurrentLocationInfo` (주력 대안)
3. Android `LocationManager` (AAOS 표준)
4. Fake (GPX 재생, 개발·데모용)

속도: Car API → 실패 시 연속 위치로 계산(Haversine / Δt, 3샘플 이동평균).

**T21 구현 메모:**

### 3.3 급제동 판정 (EventDetector)
- 조건: 브레이크 ON && (1초 내 속도 감소 ≥ 14.4 km/h ≈ 4 m/s²) && 직전 속도 ≥ 40 km/h
- 쿨다운 30초. 서버도 120초 중복 억제.
- **T26 구현 메모:** `domain.event.EventDetector`(순수 로직, 1Hz `Sample`: 속도·브레이크·연료/SoC·에어백·위치) — LOW_ENERGY(≤15% 최초, 이후 5%p마다, 20% 이상이면 초기화), HARD_BRAKE(브레이크 ON, 직전 샘플 0.5~1.5초, 직전 속도 ≥ 40, 감속 ≥ 4 m/s², 쿨다운 30초), STOPPED(속도 < 1 km/h 60초) / RESUMED(≥ 5 km/h, 총 정차 시간), AIRBAG_DEPLOYED(에지 1회), DESTINATION_ARRIVED(내비 콜백 또는 그룹 목적지 150 m 안 + 속도 < 3, 목적지당 1회), WAYPOINT_ARRIVED(내비 콜백).
  - DESTINATION_ARRIVED 는 **그룹이 가는 목적지**(그룹 목적지 + 따라간 선두 경로의 목적지 `RouteSyncState.followedDestination`)에 도착했을 때만(A005): 내비 도착은 내비가 준 목적지 좌표(없으면 마지막 위치 — 1 km)가 그 목적지들 중 하나에서 500 m 안일 때만 발행하고, 아니면(주유소 등으로 바꿔 도착) 무시하며 래치도 걸지 않는다 — 나중의 진짜 도착을 막지 않게. 좌표 정보가 하나도 없으면 예전처럼 그룹 목적지 도착으로 본다. 래치는 목적지(좌표)별.
  - 엔진(`VehicleEventEngine`)은 같은 그룹·같은 목적지의 세션 갱신(초대 재발급·같은 `GROUP_JOINED` 재수신)으로는 판정을 다시 시작하지 않는다(A054 — 도착해 서 있던 차가 도착을 다시 알렸다). 판정기 접근은 내비 수집과 1 Hz 틱이 한 잠금 안에서(A059 — 같은 순간 두 번 발행 방지).
  `VehicleEventEngine`(싱글턴, 활성 그룹 동안만)이 `VehicleSignals.state` + `LocationFeed` 최신 Fix 로 샘플을 만들고 `NaviEventMonitor.events` 를 넘겨 판정 결과를 `dh/v1/vehicle/{vid}/event` 에 **QoS 1** 로 발행한다(봉투 type = 이벤트 종류, 본문 = protocol `LowEnergy`/`HardBrake`/…). 서버가 소속 그룹·중복 억제·문구를 붙여 `group/{gid}/event` 로 돌려주므로 내 이벤트도 그룹 이벤트로 돌아와 피드에 보인다.
  이벤트 피드: `feature.events.EventsViewModel`(MQTT 실시간 `groupEvents` replay 20 + `GET /groups/{id}` recentEvents 를 eventId 로 합침, 최신순 50) · `EventsScreen`(심각도 색·종류 라벨·요약·n초 전·실시간 표시). 그룹 주행 화면 '소식 더 보기' 로 진입.
- 비상등: TurnSignal 상태가 좌·우 동시 표시를 지원하면 `HAZARD_ON`, 아니면 기능 숨김 (capability 결과 로그로 확인).

### 3.4 시계 동기화 · 지연 측정 (T31)
- `domain.time.ClockSync`: 시작 직후와 5분마다 `GET /v1/time` 을 3회 불러 **왕복이 가장 짧은 표본**으로 `offset = serverTime − (t0 + rtt/2)` 를 잡는다(실패 시 15 s 뒤 재시도). `serverNow()` 가 음성 신선도(T27, F12)의 시계다. 실측(2026-10-27): Pleos AVD 오프셋 +1196 ms(왕복 13 ms), Pleos_B +1911 ms(왕복 10 ms) — 보정 없이는 STATE 지연이 −1~2 s 로 나온다. (AVD 의 `date` 표시가 16시간 다른 것은 시간대 차이였고 epoch 는 1~2 s 차이였다.)
- `domain.latency.LatencyMeter`: 그룹 EVENT·STATE 마다 `(수신 로컬 시각 + offset) − 봉투 ts` 를 재고 최근 60 s 창의 마지막/평균/최대를 낸다(동기화 전 메시지는 세지 않음, 음수는 0 으로 자르고 횟수만 기록). 그룹 주행 화면 연결 칩 아래 "지연 이벤트 123 ms · 상태 85 ms" 오버레이(설정 '지연 표시' 로 on/off), 진단 '지연 측정' 카드(오프셋·왕복·통계·지금 동기화). 값은 서버 → 차량 한 방향(브로커 경유)이다.
- **누적 P50/P95(진단, 클라우드 지연 측정 — docs/09 §4.2):** 60 s 창과 별개로 EVENT·STATE 각각 최근 2000개(`HISTORY_CAP`)를 모아 `summary()` 가 n·P50·P95·min·max 를 낸다. 백분위는 **최근접 순위법** `LatencyPercentiles` — 정렬 표본의 ⌈p·n/100⌉ 번째(보간 없음, 정수 산술; n = 1 이면 그 값, n = 20 의 P95 = 19번째). 0 으로 자른 표본은 **0 으로 포함**(참값이 0 과 오프셋 오차 사이라 정렬상 맨 아래가 맞다 — 빼면 백분위가 위로 밀린다), 동기화 전 메시지는 값이 없어 넣지 않는다. 누적 기준 clamped·unsynced 는 `resetHistory()` 로 함께 비운다(화면·진단 카드 값은 앱 시작 이후 누적 그대로). 누적 clamped 는 **지금 누적 표본 안에 남은 것만** 센다 — 2000개를 넘겨 오래된 표본이 밀려나면 그 표본의 clamped 도 같이 빠진다(덤프의 clamped 와 min 이 어긋나지 않게).
  EVENT 는 이벤트마다 `latency: event 182ms (avg … max … n=…) type=PASSENGER_MESSAGE id=…X7K2QZ ts=<봉투 서버 ms> rx=<수신 로컬 ms>` 한 줄(동기화 전이면 `latency: event unsynced type=… id=… ts=… rx=…`) — `id` 는 eventId 끝 6자(ULID 난수 부분)뿐, 본문·닉네임 없음. `tools/demo/latency.py` 가 REST 로 보낸 메시지(응답 eventId)와 이 줄을 맞춘다.
- **debug 프로브(`debug/DemoNetActions.kt`, 리시버 액션):** `net_rtt --ei n 30 --ei gap_ms 300 [--ez fresh true]` = 앱 REST 클라이언트(DI 의 `OkHttpClient` 를 `newBuilder()` 로 이벤트 리스너만 붙여 — 같은 인터셉터·기본 주소·TLS 연결 풀)로 `GET /v1/time` n 번, 요청 직전 ~ 응답 본문 끝까지 `System.nanoTime` → `net: http_rtt n=… first=…ms p50=…ms p95=…ms min=…ms max=…ms base=<scheme://host[:port]> fail=… proto=… firstConn=new|reused [firstDns/firstConnect/firstTls] newConnAfterFirst=…`. **첫 표본은 `first=` 로 따로**(연결 수립 포함 가능), `n`·P50·P95·min·max 는 두 번째 표본부터, 실패는 `fail=` 로만 센다. `fresh` 면 먼저 연결 풀의 **유휴 연결만** 닫는다(OkHttp `evictAll`) — 앱의 다른 요청(ClockSync·그룹 API 등)이 진행 중인 연결은 남고, HTTP/2(클라우드 Caddy h2)는 첫 호출이 그 연결에 다중화될 수 있다. 첫 표본에 연결 수립이 들어갔는지는 **`firstConn=new` 로 확인**하고, `tools/demo/latency.py` 는 `firstConn` 이 `new` 가 아니거나 `newConnAfterFirst>0` 이면 결과 '주의' 에 남긴다.
  `net_mqtt_rtt` = 앱 MQTT 클라이언트(HiveMQ)로 QoS 1 PUBLISH → PUBACK 을 같은 형식(`net: mqtt_rtt … base=<브로커 scheme://host:port> transport=tls|wss|… via=broker-puback`). 보내는 것은 **내 presence 토픽에 지금 상태와 같은 `{"online":true}`, retain 없음**(`MqttGateway.probeAckNanos`) — 차량 ACL 이 허용하는 기존 토픽·스키마(docs/03 §4)라 새 토픽이 없고, 서버는 공유 구독으로 받아 Redis online 값을 같은 값("1", 텔레메트리도 매초 같은 값을 쓴다)으로 다시 적을 뿐 다른 차·그룹에 아무것도 보내지 않는다(retained 값도 그대로). **PUBACK 은 브로커(EMQX)까지의 왕복이며 서버 앱은 거치지 않는다** — 단 EMQX 인가 캐시(TTL 10 s)가 비어 있으면 그 표본에 브로커 → 서버 ACL 훅(HTTP) 한 번이 더해진다(첫 표본·P95 에 섞일 수 있음). 다른 후보는 쓰지 않았다: `ack` 는 서버가 형식(`prp_`+ULID)·존재·대상 차를 확인한 뒤 맞지 않으면 **아무것도 저장하지 않고 버리므로**(C110, 2026-11-02 — 그 전에는 모르는 proposalId 로도 Redis `rs:prp:{id}` 해시가 15분 남았다) 부작용은 없지만, 표본마다 서버 로그에 `route ack dropped`/`route ack for unknown proposal` 줄이 쌓이고 경로 제안 응답(§4)의 뜻을 흐린다. `event`·`telemetry` 는 그룹 상태·팬아웃을 바꾼다.
  `latency_dump` → `latency: summary event n=… p50=…ms p95=…ms min=…ms max=…ms | state n=… … | clockRtt=…ms offset=…ms clamped=… unsynced=…`, `latency_reset` → `latency: reset event=<비운 수> state=<비운 수>`. 프로브는 브로드캐스트와 떼어 앱 프로세스에서 돌고(`net: … start` → 결과 줄) 동시에 하나만 돈다. release 빌드에는 없다(`src/debug`).

- **선택**(`VoiceChainPolicy.choose`, 순수 함수): 후보를 생성과 동시에 **나란히** 초기화하고, 우선순위대로 처음 만나는 준비된 후보가 지금 경로다. 위 순위가 아직 초기화 중이고 **선택 상한 30 s** 안이면 `selecting=true` — 그동안 온 발화는 그때 준비된 가장 높은 순위로(없으면 화면만). 위 순위가 늦게(상한 뒤라도) 준비되면 그쪽으로 올라간다.
- **경로가 바뀌면 이전 경로를 멈춘다**(승격·강등 모두, `VoiceRoute.stop` — 대기·재생 중이던 문장은 `Dropped`, 실패로 안 셈): 선택 중 Pleos 큐에 들어간 문장이 5~9 s 뒤 시작해 새 경로(Android)의 다음 문장과 **두 목소리가 겹치지 않게**(리뷰 2026-10-28). 버려지는 문장은 앱 시작 직후 한 번 정도이고 소식 줄(10초)이 받친다. 로그 `voice: 이전 경로 PLEOS_TTS 멈춤(경로 바뀜 — 대기·재생 문장 버림)`. Pleos 후보는 넘긴 문장이 없으면 엔진 `stop()` 을 부르지 않는다.
- **상태 `ready`**: true = 소리 경로 있음 / null = 소리 경로가 아직 없고 **초기화 중인 후보가 있음**(선택 상한 30 s 안, 또는 상한 뒤에도 Pleos 처럼 늦은 응답·다시 시도로 준비될 수 있음) / false = 모든 후보 불가·강등(화면 표시만으로 정해짐).
- **강등**: 지금 경로가 **연속 3번 실패**(`UtteranceSignal.Failed` — 엔진 오류·시작 시간 초과·speak 거부)하면 그 후보를 프로세스 수명 동안 빼고 다음 경로로. 시작·완료 신호가 오면 0 으로. 끊김(급한 안내가 끊음)·큐 대기 초과(`Dropped`)는 실패가 아니다. 실패한 그 문장은 다음 경로로 다시 읽지 않는다(늦게 소리가 나 두 번 들리지 않게 — 위험 이벤트는 화면 강조 §5.2 가 받친다).
- **꼬리표 하나만 버리기 `VoiceAdapter.cancel(tag)`(2026-11-02, B012·B013)**: 체인은 모든 후보에 묻고, 그 꼬리표를 가진 후보만 반응한다 — 큐에 있으면 빼고(`Dropped("cancelled")`), 읽는(시작을 기다리는) 중이면 끊는다(`Dropped("interrupted")`). 전체 `stop` 과 달리 같은 때 읽던 급제동(HIGH)은 그대로 둔다. **`speakAndWait` 는 상한을 넘기거나(TIMEOUT) 기다리던 쪽이 취소되면 자기 문장을 버린다** — Pleos 부하(시작 5~9 s)에서 늦게 나온 "보낼까요?"가 열린 마이크에, "○○ 무전"이 녹음 재생 위에, 끊긴 알림이 새 녹음에 섞이지 않게. 로그 `voice: wait result=SPOKEN|FALLBACK|FAILED|TIMEOUT len=… path=… ms=…`(문장 원문 없음). **두 단계 상한 `speakAndWaitStaged(text, priority, startTimeoutMs, doneTimeoutMs, onStarted)`(2026-11-02, RB-3)**: 시작 신호(Started, 화면만이면 NoAudio)까지 `startTimeoutMs`, 시작한 뒤 끝까지 `doneTimeoutMs` — 한 개의 상한이면 Pleos 부하에서 짧은 질문이 시작도 하기 전에 버려져 아예 들리지 않았다. `onStarted` 는 시작 때 한 번(카운트다운이 그때부터 센다). F16 질문·카운트다운 안내가 쓴다(12 s + 6 s). 버리는 규칙은 같다(로그 끝에 `start=…ms`).
- **끝 신호 보장 `VoiceAdapter.reportsEnd`**: 체인은 꼬리표 붙인 문장마다 끝 신호(Done·Failed·Dropped·NoAudio)를 낸다 — `VoiceAnnouncer` 가 이것을 기다려 **어댑터에 한 번에 한 문장만** 넘긴다(B011, §4 T27 ⑦).
- **Pleos 후보 큐(`SerialUtterancePlayer`) = 우선순위 → 도착순**(B011): HIGH 는 대기 중인 NORMAL·LOW 앞(같은 HIGH 뒤)에 선다. 끊기 신호는 그 문장을 겨냥한다(`Interrupt(target)`) — 막 끝난 문장의 늦은 취소가 다음 문장을 버리지 않게.
- **Android 후보 큐(`AndroidTtsQueue`, 순수 — 엔진 `TtsEnginePort` 주입, JVM 테스트)**: utterance id 는 잠금 안에서 매긴다(동시 speak 에서 id 가 겹쳐 신호를 잃지 않게, B065). 오디오 포커스는 '콜백을 기다리는 utterance' 가 없을 때 반납 — `playSilentUtterance`·`speak` 가 ERROR 면 그 몫을 바로 빼고(묵음 실패 시 본문이 QUEUE_FLUSH 를 맡는다), onStop 도 빼며, 60 s 넘게 콜백이 없으면(엔진이 재생 도중 죽음) 정리한다(B050·B063 — 전에는 음악이 줄어든(덕킹) 채 남을 수 있었다). CRITICAL 의 `QUEUE_FLUSH` 는 **재생 차례 전에 지워진 선행 묵음에 아무 콜백도 주지 않으므로**(AOSP `SilenceSpeechItem.stopImpl` 은 빈 함수, `SilencePlaybackQueueItem.stop` 은 condvar 만 연다) 보내기 전에 줄 선 문장들의 묵음 몫을 미리 뺀다 — 본문은 onStop 이 와서 Dropped 로 끝난다(RB-2 — 전에는 에어백 안내가 끝나도 포커스가 60 s 정리까지 남았다). Android TTS 는 큐에서 문장 하나만 지울 수 없어 `cancel` 은 그 문장이 **재생 차례가 되는 순간**(묵음·본문 onStart) 엔진을 멈추고 뒤에 줄 선 문장을 같은 꼬리표·요청 시각으로 다시 넣는다(로그 `TTS 취소한 문장 차례 → 멈추고 뒤 문장 N개 다시 넣음`).
- **로그**(경로나 '선택 중'이 바뀔 때 한 줄): `voice: 경로 = ANDROID_TTS(engine=com.k2fsa.sherpa.onnx.tts.engine) 사유=1순위 준비` / `voice: 경로 = PLEOS_TTS 사유=ANDROID_TTS 불가(초기화 실패 status=-1 (엔진 없음))` / `voice: 경로 = DISPLAY_ONLY 사유=… (선택 중)`. 후보 로그: `TTS 준비 완료 (Android TextToSpeech <engine>, ko-KR)`, `Pleos TTS 준비 완료 (ON_DEVICE, ko_KR, CaaS 4.2.10) Nms`, `Pleos TTS 불가: … → 다음 경로`, `Pleos TTS 시작 지연=Nms`, `voice: <경로> 연속 실패 3회(…) → 강등, 다음 경로로`.
- **지연**: 요청(speak 호출) → **실제 소리 시작**. Android 는 본문 utterance 의 재생 차례(`UtteranceProgressListener.onStart`)와 엔진 오디오 첫 조각(`onAudioAvailable`, API 24+)이 **둘 다 온 시각(늦은 쪽)**(`AndroidTtsVoiceAdapter.soundStartAt`, 선행 묵음 200 ms 포함) — AOSP `SynthesisPlaybackQueueItem.run()` 은 `onStart` 를 먼저 보내고 엔진 오디오를 기다리며, sherpa-onnx 는 문장 합성을 끝낸 뒤 오디오를 넘기므로 `onStart` 만 보면 합성이 3 s 넘게 걸려도 0.2~0.3 s 로 보이고 위험 강조가 켜지지 않는다(리뷰 2026-10-28). 오디오 조각 신호 없이 `onDone` 이 오면 `onStart` 시각으로 대신한다. - **Pleos 후보 세부**(javap 확인): ① 권한·CaaS 확인(없으면 바로 불가 확정) ② 메인 스레드에서 `TextToSpeech(context, Mode.ON_DEVICE)` → `initialize(OnInitializeListener)` — **시간 초과·다시 시도**(`PleosTtsInitPolicy`, 리뷰 2026-10-28: 깨끗한 Pleos AVD 를 막 부팅해 CaaS 바인딩·엔진 적재가 15 s 를 넘겨도 영구 불가로 굳지 않게): 15 s 안에 답이 없으면 '응답 늦음' 표시만 하고 인스턴스·리스너를 그대로 둬 **늦은 onSuccess 도 받는다**, 한 시도가 45 s 를 넘기거나 onFailure·예외·③ 실패면 그 인스턴스를 놓고(`release`) **5 s → 20 s 뒤 다시**(최대 3번), 셋 다 실패하면 불가 확정. 그동안 상태는 초기화 중(ready=null)이라 준비되는 순간 체인이 올라간다. 로그 `Pleos TTS initialize 응답 늦음 15s — 계속 기다림 (시도 1/3)`, `Pleos TTS initialize 실패 … → 5s 뒤 다시 시도 (1/3)`, 준비 로그 끝에 ` (시도 2)` ③ `onSuccess` 안에서 `addEventListener`(먼저 부르면 UninitializedPropertyAccessException) → `setAudioAttributes(USAGE_ASSISTANCE_NAVIGATION_GUIDANCE)` → `setLocale(Locale.KOREA)`(`Locale.KOREAN` "ko" 는 `unsupported locale: ko-`) ④ `speak(text, isFinal = true)` — 둘째 인자는 스트리밍 입력의 마지막 조각 표시(SDK 내부 `SpeakRequest.isFinal`) ⑤ 리스너가 문장 구분 없는 전역 콜백이라 `SerialUtterancePlayer`(main, SDK 타입 없음, JVM 테스트)가 **한 문장씩** 넘긴다: 시작 15 s 초과 → 실패 + `stop()`, 시작 뒤 끝 신호가 `20 s + 0.3 s × 글자 수` 안에 없으면 끝난 것으로, CRITICAL 은 큐를 비우고 `stop()` → 정지 신호(최대 1 s) 뒤 읽기, 큐 30 s 초과는 버림. `release()` 는 시도를 놓을 때·불가 확정 때만(준비되면 앱 수명 동안 유지).

  설정 화면 "음성 안내" 스위치(`VoiceAnnouncer.setEnabled` 는 메모리 값만 — 저장·앱 시작 때 적용은 **설정 화면에서 바꿀 때만** A120 `UserSettings`(`dh_settings`) 한 곳이 맡는다. 진단 카드 [음성 안내 끄기/켜기]·디버그 리시버 `voice` 의 일시 전환은 저장하지 않아 앱을 다시 켜면 돌아온다 — RB-5, 리허설에서 끈 채로 PT 날 음성 장면이 조용히 빠지지 않게. 그래도 설정 화면에서 끈 값은 남으므로 시연 전 `status` 의 `voice=true` 를 확인한다. **설정 화면의 저장 호출**(`SettingsViewModel.setVoiceEnabled` → `UserSettings.setVoiceEnabled`)은 화면(UI) 트랙 반영 뒤 — 그 전 빌드는 설정 화면에서 꺼도 앱을 다시 켜면 켬으로 돌아온다), 진단 화면 "음성 안내 (T27)" 카드(경로·사유·지연·읽음/생략 수·예시 안내 듣기·테스트 발화 — §3.5).

### 5.1 정차 대시보드 (GROUP_DRIVE 경로, 2026-10-28)
그룹 주행 경로(`DhRoutes.GROUP_DRIVE`)의 화면은 T25 의 리스트+지도 대신 `feature.drive.DriveDashboardScreen` 이다(시안 D1·D2 → 실데이터). **주행 중 앞 화면은 순정 내비**이므로 이 화면은 그룹 생성·합류 직후와 **정차 중**에 본다.
- 데이터: `GroupDriveViewModel`(T25 상태 + `RouteSyncEngine.activeWaypoint` + `NaviEventMonitor` 제한속도 + `LatencyMeter` 이벤트 지연 + `SurfaceFeed` 모드·실제 수신 시각이 붙은 최근 이벤트) → 순수 함수 `DriveDashboardMapper` → `DriveDashboardUi`(단위 테스트 `DriveDashboardMapperTest`).
- 대열 막대: 위치(선두까지 거리)를 아는 차만, `offsetKm = (최후미 distanceToLeaderM − 그 차 값)/1000`, 대열 길이 = 최후미 값, 바로 앞차와 3 km 초과면 주황 구간, 간격은 내 차 기준("앞 1.2 km"/"뒤 350 m"). 막대 끝 = 다음 정차지(내 위치 + 직선거리), 없으면 선두 + 2 km. 오른쪽 끝 "{목적지} {내 남은 km} km".
- 다음 정차지 = `RouteSyncEngine` 이 **마지막으로 수락(멤버)·발행(선두)한 경로의 첫 경유지**(`RouteSyncState.activeWaypoint` — 경유지 없는 경로 수락·내비 경유지 도착·그룹 변경 시 null). 다음 정차 카드는 경유지가 있을 때만(이름·내 위치에서 직선거리; 차별 ETA·주유/충전·도달 가능은 아직 모름 → 생략·"—").
- 그룹 도착 = 멤버 `eta.destTs` 최댓값과 그 차, 내 도착 = 내 eta(남은 km·분). 내 주행 줄 = 제한속도(내비, 0 은 숨김) · 연속 주행(`ContinuousDriveTimer` — 앱 시작부터 `DrivingStateMonitor` 를 따라 주행 구간만 더하고, **15분 이상 정차하면 0**, 짧은 정차는 유지; 2시간 이상 주황 + 휴식 권장. 처음 구현은 그룹 합류 `joinedAtMs` 부터 세어 밤새 이어진 시연 그룹에서 정차 중인데도 "연속 주행 18시간 27분"을 띄웠다) · "다음 휴식 추천: {경유지}"(회전 안내 자리 — 회전은 순정 내비 몫).
- 이벤트 띠·지난 소식은 플로팅 패널과 같은 규칙(`surface.SurfaceEvents` — 띠의 위험 이벤트 강조도 패널과 같은 값, §5.2): **내 차 출처 제외, 대상 아님 제외**(급제동은 출처보다 뒤차만 — 위 수신 대상), 띠 = 받은 지 10초 안 **그리고** 서버 시계(`ClockSync.serverNow`)로 60초 안에 생긴 가장 최근 이벤트(없으면 띠 숨김), 정차 블록 '지난 소식' = 발생 시각(봉투 ts) 최신 5개, "N초 전" = 서버 시계 − 봉투 ts(+[더 보기] → 이벤트 피드). MQTT 세션 유지(cleanStart=false) 때문에 재접속하면 브로커가 쌓아 둔 QoS1 옛 이벤트를 한꺼번에 '지금' 보내는데, 이들이 '방금 소식'·"0초 전"으로 보이지 않게 하려는 것이다(카드 60 s·음성 5 s 와 같은 기준). 정차 블록 버튼: 그룹 관리(→ 그룹 생성 화면 Active: 초대 QR·멤버·나가기/종료 — **확인 다이얼로그**를 거친다, 방장 한 번 탭 = 그룹 전체 종료라 R13 오탭 방지) · 설정 · 홈. 프리셋(F8)·보내지 않은 무전(F16)은 데이터가 생길 때까지 블록째 숨긴다.

### 5.2 주행 중 표면 (사용자 확정 2026-10-28)
**원칙: 주행 중 앞 화면은 항상 순정 내비, 동행은 가리지 않는 표면으로만.** 표면은 넷뿐이다 — ① 순정 내비 위 **플로팅 패널** ② **이벤트 알림 카드**(5초, **'카드 + 음성' 대체 모드에서만**, 회전 300 m 이내면 회전 후로 미룸) ③ **음성**(T27 `VoiceAnnouncer`) ④ **그룹 휴게소 = 내비 경유지**(T28 `RouteSyncEngine`). 실측 근거: `docs/images/surfaces/*.png`, 제약은 docs/10 R16.

**모드 전환(`surface.SurfacePolicy`, 순수 함수):** 그룹 세션 없음 → `OFF` / 오버레이 권한(`Settings.canDrawOverlays`) 있음 → `PANEL`(패널 소식 줄 + 음성, **헤드업 카드 없음** — 2026-10-28 사용자 지시, 카드가 내비 TBT 를 가렸다 `impl_02`) / 없음 → `CARDS_ONLY`('카드 + 음성' 대체 모드, 정차 대시보드 안내 1줄). 권한은 `OverlayPermissionMonitor` 가 앱 시작·포그라운드 복귀(Activity 생명주기) 때, 그리고 **그룹이 있는 동안만** 5초마다 다시 본다(Pleos 는 `appops` 로만 바뀌므로; 그룹이 없으면 쓸 데가 없어 주기 바인더 호출을 하지 않는다). 패널 표시 = `PANEL` && 동행 `MainActivity` 가 **보이지 않음**(`AppForegroundTracker` — resumed 가 아니라 started~stopped 로 본다: 정차 중 위치 권한 다이얼로그처럼 화면은 보이지만 paused 인 동안 패널이 동행 화면 위에 뜨지 않게) — 동행 화면이 보이면 대시보드가 같은 정보를 보여 준다. 깜빡임 방지로 표시만 0.6 s 늦춘다.

**플로팅 패널(`surface.FloatingPanelService`):** Service + LifecycleOwner + SavedStateRegistryOwner 가 `ComposeView`(`feature.drive.FloatingPanel`)를 `TYPE_APPLICATION_OVERLAY` + `FLAG_NOT_FOCUSABLE|FLAG_NOT_TOUCH_MODAL` 로 띄운다(패널 밖 터치는 내비로). 데이터는 싱글턴 `SurfaceState.panelUi`(Hilt EntryPoint) ← `FloatingPanelMapper`(순수 함수, 단위 테스트):
- 다른 차만, 선두부터(`distanceToLeaderM` 오름차순), 최대 4대 + "외 N대". 간격 = 상대 − 나 → 음수 "앞", 양수 "뒤", 1 km 미만 m(10 m 반올림), 모르면 "—". 도착 시각 = `eta.destTs` 기기 시간대 HH:mm, 머리줄 = "{그룹 이름} · {목적지} 도착 · 연결 점".
- **머리줄 배치(2026-10-28 사용자 지시 — 머리글은 그룹 이름):** 기준 문구 "{목적지} 도착"(`FloatingPanelUi.etaPlace` + " 도착")은 자기 폭으로 먼저 자리를 잡아 **잘리지 않고**, 그룹 이름이 남는 폭을 다 쓴다(`weight 1`). 폭이 모자라면 **그룹 이름만 말줄임**한다("아빠 차와 같이…" — 375 dp·22sp 에서 "경포해변 도착" 옆 그룹 이름 몫 ≈ 180 dp, 한글 약 8자). 기준 문구에는 상한 **180 dp**(`FloatingPanelSpec.HEADER_LABEL_MAX_DP` — 머리줄 안쪽 319 dp 중 그룹 이름 몫을 139 dp·약 6자 이상 남기는 값, 한글 약 7자 + " 도착" — "광주송정역 도착" ≈ 160 dp 까지 그대로)을 두고, 그보다 긴 목적지만 **목적지 이름을 말줄임하고 " 도착"은 남긴다**("강릉 경포해변 중앙… 도착"). 시안 `panel_worst`(시연 기본 그룹 이름 "아빠 차와 같이 가기"), `panel_longdest`(상한에 걸리는 긴 목적지 + 긴 그룹 이름).
- 저잔량 = min(연료%, 배터리%) ≤ 15(주유기 아이콘), 경고(주황) = |간격| > 3 km 또는 연결 끊김, 연결 끊김 = !online 또는 OFFLINE(회색 점).
- 소식 줄 = 받은 지 10초 안 + 서버 시계로 60초 안에 생긴 가장 최근 이벤트(내 차 출처 제외, 대상 아님 제외 — 앞차는 뒤차의 급제동을 보지 않는다, 재접속 때 밀려 온 옛 이벤트 제외 — `SurfaceEvents`, 정차 대시보드 띠와 같다). **단, 위험 이벤트(급제동·에어백)는 줄을 붙잡는다**(2026-11-02, B016 — `SurfaceEvents.holdsBanner`): 창 안의 위험 이벤트가 **아직 그 음성이 시작되지 않았거나** 강조 중(BLINK·STEADY = 음성 시작 + 3초)이면 더 최신 메시지·무전·저잔량보다 먼저 보인다(여럿이면 그중 최신). 급제동 직후 다른 차의 무전·프리셋이 와도 빨간 강조가 가려지지 않게 — 음성이 끝나고 3초가 지나면 다시 최신순. 음성 값이 없는 호출은 창 안의 위험 톤 먼저. 나이는 서버 시계 − 봉투 ts. 톤: 급제동·에어백 = 위험(빨강), 저잔량·연결 끊김·경로 이탈 = 주의(주황), 그 밖 = 정보(초록) — 색 + 아이콘 이중 표기.
- **위험 이벤트 강조(2026-10-28 사용자 지시, R19 — Pleos TTS 는 부하 시 시작까지 5~9 s):** 급제동·에어백(위험 톤) 소식 줄은 **음성 시작이 3초 안에 없으면** 빨간 바탕 + 흰 굵은 글씨 + 깜빡임(불투명도 1.0 ↔ 0.35, 약 0.9 s 주기 — 초당 3회 미만)으로 **음성보다 먼저** 보인다. 지금 음성 경로가 화면 표시만이거나 그 경로의 최근 평균 요청 → 시작이 3초를 넘으면(늦을 게 분명) 받은 순간부터 강조한다. **'늦을 게 분명'은 이벤트를 받은 순간 한 번만 정한다**(`SurfaceState.noteEvent` → `EventHighlightPolicy.noteReceipt` → `VoiceCue.lateAtReceipt`, eventId 별·최근 32개, QoS1 중복은 처음 값) — 그 이벤트의 시작 표본으로 평균이 3초를 넘나들거나 경로가 바뀌어도(선택 중 화면만 → Pleos 준비) 강조 시작 시점이 바뀌지 않아, 켜졌던 강조가 STEADY 없이 꺼지거나·깜빡임이 끊겼다 다시 켜지거나·강조 전에 시작된 음성 뒤에 STEADY 가 새로 뜨지 않는다(리뷰 2026-10-28). 판정이 없는 이벤트(옛 호출)는 지금 값으로 본다. 강조 중에 **그 이벤트의 음성이 시작되면**(eventId 꼬리표의 `Started` 신호, §3.5 `VoiceCueTracker`) 깜빡임을 멈추고 빨간 강조만 3초 유지한 뒤 평소 모양. 강조 전에 음성이 시작되면 평소 모양 그대로. 음성이 끝내 없으면(음성 꺼짐·중복·실패) 소식 줄이 보이는 10초 동안 깜빡인다. 규칙은 순수 함수 `surface.EventHighlightPolicy.decide(type, eventId, receivedAtMs, nowMs, VoiceCue)` → `EventBannerUi.highlight`(NONE/BLINK/STEADY) — **패널 소식 줄과 정차 대시보드 띠가 같은 값**(`SurfaceEvents.bannerUi(…, cue)`). `SurfaceState` 는 음성 신호가 바뀌면 1초 틱을 기다리지 않고 다시 그린다. 로그: 강조가 바뀔 때 `surface: event highlight BLINK|STEADY|NONE tone=DANGER age=Ns path=PLEOS_TTS avg=6100ms`, 디버그 `surface` 한 줄의 `highlight=`. 테스트 `EventHighlightPolicyTest`·`SurfaceHighlightTest`.
- [무전] 줄(F16, §5.3): 라임 버튼이자 무전 진행 상태(녹음·"보낼까요?" 확인과 5초 원형 카운트다운·보냄·받은 무전 재생·안내) — 탭 = `VoiceTriggerAdapter.press(PANEL)`. 주행 중 패널에서 받는 입력은 이 탭 하나다.

**크기·가독성(`surface.PanelLayout`, 사용자 지시):** 내비 화면 폭 = 가로 디스플레이면 폭의 2/3(Pleos 2창 실측 — 왼쪽 853/2560 px 가 차량 영역), 세로면 전체. 패널 폭 ≤ 내비 폭의 **22%**(Pleos 2560×1440·1 dp = 1 px 에서 375 dp), 높이 ≤ 디스플레이 높이의 **32%**(460 dp — 차 4대 + 이벤트 + [무전] ≈ 375 dp, "외 N대" 줄과 소식 2줄까지 ≈ 454 dp. 2026-11-05: 소식 문장이 "…"로 잘리지 않게 최대 2줄로 감싼다 — 앱 대시보드의 소식 띠도 같다). 글자: 거리·도착 시각 숫자 **31sp**(시안 24sp × 1.3), 이름 **29sp**(× 1.2, 고정폭 100 dp — 안 들어가는 긴 닉네임은 20sp 까지 줄여 맞추고 그래도 넘치면 말줄임, 2026-10-28 실측 "DemoCarB" 가 "De…" 로 잘리던 것 개선), 간격은 10 km 미만 소수 1자리·그 이상 정수("뒤 28 km" — 소수까지 쓰면 단위가 잘렸다), 저잔량 아이콘까지 붙어 남은 폭에 안 들어가면 간격 숫자를 24sp 까지 줄인다(`FitGap`, 최악 조합 시안 `panel_worst`), 단위 "km/m" 18sp 작게, 머리줄 22sp·소식 줄 24sp·무전 31sp(× 1.2), 행 높이 ≥ 40 dp·행 간격 10 dp. 폭이 375 dp 보다 좁은 화면은 같은 비율로 줄인다(하한 0.6배).

**위치:** 기본 **오른쪽 위 고정**(오른쪽 110 dp — 오른쪽 끝 메뉴 손잡이 회피, 위 190 dp — 내비 2D 버튼 아래; 내비 TBT 는 왼쪽 위, 하단은 ETA 카드·음량/설정 버튼). **정차 중(`DrivingStateMonitor` false)에만** 드래그 가능 → 놓으면 가장 가까운 모서리(좌우 = 내비 화면 가운데, 위아래 = 디스플레이 가운데 기준)로 스냅 → SharedPreferences `dh_surface`(`panel_corner`)에 저장. 모서리 여백: 오른쪽 아래(150, 24) — 음량·설정 버튼 열 회피, 왼쪽 위(내비 왼쪽 + 24, 360) — TBT 아래, 왼쪽 아래(내비 왼쪽 + 24, 340) — ETA 카드 위. 주행 중에는 드래그를 무시한다(뿌리 뷰 `PanelDragFrame` 이 슬롭을 넘는 이동만 가로챔, 짧은 탭은 [무전]으로). 드래그 도중 주행으로 바뀌면 그 드래그를 **취소**한다(`cancelDrag` — 원래 모서리로 돌아가고 저장하지 않음, 이동·놓기 처리도 `dragEnabled` 를 함께 본다).

**이벤트 알림 카드(`surface.EventCardNotifier`, 판단 `EventCardPolicy` 순수 함수):** `MqttSessionManager.groupEventsReceived` 구독. 대상 = LOW_ENERGY·HARD_BRAKE·AIRBAG_DEPLOYED·WAYPOINT_ARRIVED·DESTINATION_ARRIVED·MEMBER_JOINED·MEMBER_OFFLINE·PASSENGER_MESSAGE(+ F16 `VOICE_MESSAGE` — 문자열 비교). 내 차 출처 제외, 대상 아님 제외(`not-audience` — 급제동은 출처보다 뒤차만, 스냅샷은 `MqttSessionManager.groupState`), 신선도 60 s(`ClockSync.serverNow() − 봉투 ts`). 빈도 제한 `CardThrottle`: 같은 `eventId` 한 번(최근 128개, QoS1 중복 수신), 같은 종류·같은 출처 30초에 한 장(연결 들락날락 MEMBER_OFFLINE 등; 메시지는 제외), 전체 5초(= 카드 수명)에 2장까지(위험 ALERT — 에어백은 예외), 못 올린 카드는 한도를 쓰지 않는다. 채널 **`dh_events_silent`(IMPORTANCE_HIGH, `setSound(null, null)`·진동 없음** — 같은 이벤트를 음성이 읽으므로 알림음과 겹치지 않게; 소리 있던 첫 채널 `dh_events` 는 지운다, 채널 소리는 만든 뒤 못 바꾼다), category 메시지 → `msg`, 그 밖(저잔량·급제동·도착·합류·끊김) → `navigation`. **Pleos 알림 표시기(`ai.umos.notification`)는 일반 앱 알림 중 category `call`·`msg`·`navigation`(·`connect.system`)만 헤드업 카드로 띄우고 `status` 는 IMPORTANCE_HIGH 여도 알림 목록에만 넣는다** (2026-10-28 실측 — 첫 구현의 급제동·저잔량 카드(`status`)가 안 떴고, 표시기 로그 `needHeadUpNotification` 이 navigation·msg 에만 찍힘; `car_warning` 등 차량 category 는 시스템 서명·권한 앱 전용, SecurityException), 제목 = 서버 음성 문구(없으면 종류 라벨), 본문 = 그룹 이름, `setTimeoutAfter(5000)`(2026-10-28 8초 → 5초)·autoCancel, **같은 종류는 같은 알림 id 로 교체**(쌓이지 않음). **주행 중에 올린 카드는 눌러도 동행을 열지 않는다**(2026-11-02, B125 — `EventCard.openOnTap=false`, contentIntent 없음, 5초 뒤 저절로 사라짐 — 앞 화면은 늘 순정 내비). 정차 중에 올린 카드만 정차 대시보드로 연결(로그 끝 `tap=open|none`). **`CARDS_ONLY` 에서만 동작** — `PANEL` 이면 카드 없이 skip `panel-mode`(같은 소식은 패널 소식 줄 10초 + 음성), 미룬 카드가 있을 때 `PANEL` 로 바뀌면 버린다(`mode-PANEL`). `POST_NOTIFICATIONS`(API 33+)는 위치 권한과 같은 시점(활성 그룹 + 정차, `LocationPermissionGate`)에 함께 요청하고, 거부되면 카드 없이 패널·음성만.

**카드 TBT 게이트(`surface.TurnCardGate` 순수 클래스 + `TurnProbe`, 사용자 지시 2026-10-28):** 헤드업 카드는 순정 내비 상단 회전 안내(TBT) 위에 겹치므로 대체 모드에서도 회전 직전에는 띄우지 않는다. 카드를 올리기 직전에 `NaviAdapter.nextTurn(0.8 s)` 를 **한 번** 묻고 다음 회전까지 **≤ 300 m** 면 카드를 미룬다(음성은 `VoiceAnnouncer` 가 이미 읽었다, 로그 `surface: card deferred type=… tbt=…m`). 미룬 카드가 있는 동안만 **1초마다** 다시 묻고(평소엔 묻지 않는다), '회전 후' — ① **다음 회전이 300 m 밖** ② TBT 없음(안내 끝) ③ 모름이 **3번 연달아**(한 번 늦은 응답·재탐색으로 회전 직전에 뜨지 않게, 내비가 아예 답을 못 하면 약 3~5초 뒤) — 이면 미룬 순서대로 올린다(`surface: card released type=… reason=far|no-guidance|unknown tbt=… after=…s`). **회전을 지났어도 다음 회전이 또 300 m 안이면 계속 미룬다**(연속 회전 — 놓으면 그 회전의 TBT 를 가린다, 로그 `surface: card still held — …`). 같은 종류는 최신 1장만 남기고, **120초** 넘게 밀린 카드는 버린다(`surface: card expired …`). **미룬 카드가 있으면 새 카드도 줄 끝에 선다** — 같은 TBT 읽기에서 옛 카드만 올리고 새 카드는 미루는 일이 없고, 줄이 풀릴 때 빈도 한도(5초 2장)에 걸린 카드는(새 카드 포함) 버리지 않고 다음 확인에서 순서대로 나간다(`why=near|tbt-unknown|burst`). 미룬 카드가 없을 때 빈도 한도에 걸린 카드는 전처럼 버린다. **미룬 카드가 없을 때 TBT 를 모르면(타임아웃·미지원·실패·자리표시 항목) 카드를 바로 올린다.** TBT 첫 항목 → 결과는 순수 함수 `nextTurnOf`(자리표시 `TURN_UNKNOWN`·0 m 에 문구 없음 → 모름, docs/10 R16). AVD 차 A 는 안내 중 TBT 가 고정값이라 덮어쓰기 없이는 카드가 120초 뒤 버려진다(docs/09 §1.3). **위험 카드(급제동·에어백) 예외(2026-11-02, B067 — 카드 + 음성 모드에는 패널 강조가 없어, 음성이 늦으면 회전 직전 몇 초 동안 경고가 하나도 없었다)**: ① 받는 순간 음성이 늦을 게 분명하면(화면만·평균 지연 3 s 초과 — `EventHighlightPolicy.expectLate`) 게이트를 건너뛰고 바로 올린다(`surface: card danger … gate skipped (voice late …)`) ② 미뤘는데 3초 안에 그 이벤트의 음성이 시작되지 않으면 재확인 루프가 그 카드만 놓는다(`surface: card danger released (no voice in 3s)`) ③ 위험 카드는 15초(`TurnCardGate.DANGER_MAX_DEFER_MS`) 넘게 밀리면 버린다 — 지난 급제동이 회전 뒤 늦게 떠 헷갈리지 않게. 맞바꾸는 점: 위험 카드는 TBT 를 최대 5초 가릴 수 있다(사용자 지시 '카드가 TBT 를 가리지 않게'의 예외 — 안전 경고가 먼저). 음성 값은 `SurfaceState.voiceCue()`. 시계는 단조 시계(`SystemClock.elapsedRealtime`). 진행 상태는 `EventCardState`(held·deferred·released·expired·lastTbt) → 디버그 `surface` 한 줄.

**조용한 상시 알림:** `DriveSessionService` 의 포그라운드 알림은 옛 채널 `drive_session`(IMPORTANCE_LOW, category navigation — Pleos 상단 카드로 떠 내비 TBT 를 가렸다, `b_floating_panel_design.png`)을 지우고 새 채널 **`drive_session_quiet`** 로 올린다. 채널은 IMPORTANCE_MIN(소리·진동·배지 없음)으로 **만들지만** 포그라운드 서비스 알림이라 Android(NotificationManagerService)가 사용자 설정이 없으면 **LOW 로 올린다**(dumpsys 에 importance=2 로 보일 수 있다 — LOW 도 소리·헤드업 없음). Pleos 상단 카드를 막는 핵심은 **`CATEGORY_SERVICE`** 다(category navigation 이 카드로 뜨던 원인; 78dcafd 프로브는 FGS 가 아닌 ongoing 알림으로 확인했고, FGS 알림은 `dumpsys notification` + 순정 내비 화면 캡처로 확인한다). 알림은 `setSilent`·`setOnlyAlertOnce`·`PRIORITY_MIN`·`CATEGORY_SERVICE`·ongoing, **문구 고정 "동행 그룹 주행 중"**, 내용 갱신 없음. 내비 위에 뜨는 것은 플로팅 패널과(권한이 없을 때만) 이벤트 알림 카드뿐이다.

- **음성 안내와 마이크가 섞이지 않게(2026-11-02, B013)**: 녹음을 열기 직전 `PttController` 가 ① 자기 지난 안내("보냈어요."·"취소했어요."… — 꼬리표 `ptt-N`)가 아직 남았으면 버리고 ② `VoiceAnnouncer.yieldToMic` 으로 이미 넘긴 NORMAL·LOW 안내를 멈춰 무전 뒤 다시 읽게 한다(§4 T27 ⑧). Pleos 경로는 시작이 5~9 s 늦어 소식 줄을 보고 바로 누르면 그 안내가 녹음 한가운데 나와 그룹에 보내는 무전에 섞였다(MIC 소스는 AEC 없음, 녹음 포커스 EXCLUSIVE 는 같은 앱 TTS 를 멈추지 않는다). 급제동(HIGH)·에어백은 녹음 중에도 읽는다(안전 우선).

"○○ 무전" 알림을 읽는 중이거나 MediaPlayer 를 준비하는 중이어도 끊는다(알림 TTS 가 새 녹음에 섞이지 않게 — 알림+재생을 코루틴 하나로 돌려 취소하고, 알림 중이면 **그 알림 문장만** 버린다(체인 `speakAndWait` 의 꼬리표 취소, 2026-11-02 B012 — 전에는 TTS 큐 전체를 비워 그 순간 큐에 있던 HIGH 안내도 함께 지워졌다)). 끊긴 무전은 '지난 무전'에 **"다 못 들음"**(INTERRUPTED)으로 보이고(로그 `ptt: playback interrupted voiceId=… why=ptt-press status=INTERRUPTED resume=after-flow`), 같은 파일로 재생 큐 맨 앞에 '다시 틀 것'이 선다. **내 녹음·확인 흐름이 IDLE 로 끝나면**(보냄 3 s·취소·보관·너무 짧음·실패·마이크 권한 안내 어느 쪽이든 — 안내 3 s 가 끝난 뒤) `PttRuntime` 이 `VoicePlayback.resumeInterrupted` 를 불러(`ptt: resume released why=send-flow-idle cycle=N`) 알림부터 **처음부터** 다시 튼다(`ptt: resume voiceId=… waited=…s → 처음부터` → `ptt: playing … manual=true resume=true` → `ptt: playback done … resume=true` = '들음'). 다시 트는 동안은 목록에서 빠지고 끝나면 결과 상태로 다시 들어간다. 흐름 중 도착한 다른 무전은 그 뒤에 선다(**끊긴 무전이 먼저**). 흐름 끝 판정은 사이클 번호(`PttState.cycleSeq`·`idleCycleSeq`, 순수 `ResumeAfterFlow`) — 누름이 상태 기계에 닿기 전 번호로 걸고 그 뒤 사이클이 IDLE 로 끝나야 푼다(안내 중 누름은 새 사이클, 전송 중 누름은 지금 사이클). 60 s 신선도는 끊긴 무전에 적용하지 않고 대신 끊긴 때부터 **2분 상한**(`RESUME_MAX_WAIT_MS`) — 넘겨 풀리면 다시 틀지 않고 "다 못 들음"으로 남기며(탭 재생), 상한이 지나도록 풀리지 않으면 스스로 열어 뒤의 무전이 막히지 않게 한다. 다시 트는 중 또 누르면 또 끊기고 그 흐름이 끝나면 또 처음부터. 기다리는 동안 [지난 무전] 줄을 탭하면 탭 재생이 그 자리를 대신한다(두 번 나오지 않음). 그룹이 끝나거나 바뀌면 버린다. 디버그 `ptt_status` 재생 줄 `resumeWaiting=true|false`. 단위 테스트 `PttResumeTest`·`VoicePlaybackTest`.
- 사이클은 한 번에 하나: 새 사이클(새 녹음·다시 보내기·안내)은 옛 사이클이 **끝난 뒤**(`cancelAndJoin`) 시작하고, 녹음기를 여는 동안(MediaRecorder prepare·포커스 — 실기기 수백 ms)에도 단계는 이미 RECORDING 이라 그 사이 누름은 새 사이클을 세우지 않는다(녹음 루프가 시작할 때 버린다). 녹음기가 하나라 옛 사이클의 정리가 새 녹음을 풀면 말한 무전이 사라진다(실제 스레드 이중 탭 단위 테스트).

**'네/아니' 인식 체인(`RecognizerChain`):**
1. **Pleos SpeechToText 3.3.1**(pleos flavor 만, `PleosSttYesNoRecognizer`) — 준비 중 SDK 라 선택적(규칙 5): CaaS ≥ 4.1.29 + `pleos.car.permission.STT_SERVICE`(normal) + `initialize` 성공일 때만. `registerApp` 키를 몰라(docs/10 Q9) **ON_DEVICE** 모드에서 initialize → request 만 하고, 인증 오류·실패는 영구 실패로 건너뛴다 — **단 initialize 시간 초과(3 s)는 이번만 실패**(2026-11-02, B045 — 차량 부팅 직후 CaaS 콜드 스타트로 넘겨도 프로세스 내내 음성 확인이 빠지지 않게; 다음 녹음 때 다시 시도하고 연달아 3번이면 영구, `PleosSttInitPolicy`). 시간 초과는 **녹음 사이클(녹음 중 prepare ~ 확인 listen)마다 한 번만** 세고, 녹음 중 prepare 가 이미 시간 초과로 끝난 사이클의 listen 은 새 초기화(또 3 s)를 시작하지 않고 바로 이번만 실패(`init-slow`)로 다음 단계에 시간을 넘긴다(RB-4 — 전에는 확인 5 s 중 3 s 를 아무것도 듣지 않은 채 보냈고, 한 사이클에 2씩 세어 녹음 1.5회 만에 영구가 됐다, `PleosSttCycleTimeouts`). prepare 없이 듣는 호출(경로 제안 질문)은 그 듣기 하나가 사이클이다. **판정(B014)**: 부분 결과(`isFinal=false` — SDK `UpdateSttResult`)로는 **아니만** 바로 끝내고 **네는 최종 결과**(`isFinal=true` — 끝점 검출 뒤 `UpdateSttCompleted`)에서만(`YesNoParser.streamVerdict`) — "어… 아니 보내지 마"의 첫 부분 결과 "어"로 무전이 나가지 않게. 시간이 다 돼 최종 결과가 끝내 없으면 무응답(보관). `initialize`(CaaS 연결, 최대 3 s)는 **녹음하는 동안**(`prepare`) 한 번 하고 같은 인스턴스로 request/stop 을 되풀이한다(NONE 재듣기 포함) — 확인 5초의 앞부분이 연결 대기로 마이크가 닫혀 있지 않게. 그래도 듣기 안에서 연결을 기다렸으면 그만큼 듣기 상한을 줄이고(남은 1.5 s 미만이면 다음 단계로), 60 s 안 쓰면 놓는다(release). 듣다 오류가 나면 인스턴스를 버리고, 취소(확인 중 누름·주입 답)돼도 리스너 해제·release 는 한다.
   의존성: universal-access 0.6.0 이 끌어오는 appcompat·material 은 이 줄에서, security-crypto-ktx 1.1.0-alpha06 은 **모든 구성**에서 뺀다(`configurations.configureEach` — TextToSpeech SDK 줄이 생겨도 debug·release 가 같은 security-crypto 1.0.0). **주의**: UA 의 보안 저장소(`ua.s` — MasterKey·MasterKey$Builder)는 1.1.x API 라 1.0.0 에 없다. UniversalAccess.create 에서만 만들어지고 STT SDK 는 `registerApp`(UA 변형)으로 useUaSdk 를 켤 때만 그 경로를 타므로 ON_DEVICE 만 쓰는 지금은 닿지 않는다 — registerApp 을 켜려면 security-crypto 를 1.1.x 로 올리고 토큰 저장소를 다시 검증한다(docs/10 Q9).
2. **Android `SpeechRecognizer`**(`isRecognitionAvailable` + 실제 시작) — Pleos AVD 는 `onError(9)`(아래 표) → 영구 실패로 기억. 단 **마이크가 실제로 열리는 상태(앱이 앞이거나 서비스에 microphone)에서 난 9 만** 영구(2026-11-02, B045 — 백그라운드 while-in-use 제한 때문에 난 9 는 이번만 실패, 타입이 올라간 뒤 다시 시도).
3. **Vosk 0.3.75**(`com.alphacephei:vosk-android`, Apache 2.0, JNA 5.18.1, 32비트 .so 는 APK 에서 뺌) + 소형 한국어 모델 `vosk-model-small-ko-0.22` — **앱 `files/vosk-ko-small/`(am/·conf/ 필요)에 있을 때만**(APK 에 넣지 않는다: zip 82 MB·풀면 253 MB). 단어 문법 {네, 예, 응, 어, 그래, 보내, 보내줘, 아니, 아니요, 아니오, 취소, 싫어, 하지마} + `[unk]`(모델 어휘에 없는 `보내줘`·`[unk]` 는 Vosk 가 경고만 하고 뺀다). 모델 적재(수 초)는 녹음하는 동안 미리 — 단계별 준비는 **나란히**(2026-11-02, B064 — 차례로 하면 Pleos STT 초기화 3 s 뒤에야 적재가 시작됐다). 듣기 안에서 적재를 기다렸으면 그만큼 듣기를 줄이고 남은 시간이 1.5 s 미만이면 `model-loading`(이번만 실패)으로 다음 단계에 넘긴다. **판정(B014)**: 구간(`onResult`)·부분 결과를 이은 문장 전체로(`YesNoSegments`) — 아니는 바로, **네는 구간이 끝난 뒤 0.7 s 더 들어** 문장이 계속 네일 때만(“어” 뒤 잠깐 멈추고 "아니"가 와도 네로 보내지 않게). WAV 주입은 아니만 바로, 네는 파일 끝까지 들은 문장 전체로.
4. 아무것도 없으면 **카운트다운 모드**.
- 듣기가 취소돼도(확인 중 누름·주입 답이 체인의 나머지를 취소·컨트롤러 확인 상한·그룹 변경) 마이크를 닫는다 — Vosk 는 `SpeechService.stop/shutdown`·`Recognizer.close` 를 `NonCancellable` 로 돌린다(취소된 코루틴에서 그냥 `withContext` 를 부르면 블록이 돌지 않아 AudioRecord·녹음 스레드가 남는다).
- 듣다 실패하면 남은 시간으로 다음 단계, NONE(말 없음·네/아니 아님)이고 1.5 s 이상 남으면 같은 단계로 다시(최대 3번). 판정은 '아니'가 우선, 문장 전체가 네일 때만 네(`YesNoParser`).
- 로그 예: `ptt: recognizer=VOSK answer=YES conf=0.91 (PLEOS_STT=unavailable(no-stt-permission), ANDROID_STT=failed(stt error=9))`, 카운트다운 `ptt: recognizer=NONE → countdown (…)`.
- 디버그: 답 직접 주입(`ptt_answer --es answer yes|no|none` — 듣는 중이면 바로 끝내고 카운트다운 중에도 받는다), WAV 주입(`--es file <wav>` — 다음 듣기 한 번을 마이크 대신 Vosk 에, 듣기 **전에** 넣는다), 카운트다운 강제(`ptt_countdown` — `RecognizerChain.forceCountdown`, 모델이 있어도 카운트다운 장면을 찍게).

**재생·포커스·음성 안내:**
- 받기: `VOICE_MESSAGE` 중 **내 차가 보낸 것 제외**, 수신 대상은 공용 `EventAudience`(무전은 audience 없음 = 그룹 전체). 서버 시계(`ClockSync`) 기준 봉투 나이 60 s 이내면 내려받아 큐, 넘었으면 자동 재생하지 않고 '지난 무전'(못 들음).
- 재생 직전 TTS "{닉네임} 무전"(서버 speech, 설정 '음성 안내'를 끄면 생략, TTS 엔진이 없으면 즉시 다음) → `MediaPlayer`(USAGE_ASSISTANCE_NAVIGATION_GUIDANCE + `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` — 음악은 멈추지 않고 작아진다) → 끝나고 3 s 머문 뒤 사라짐. 녹음·확인·전송 중에 온 무전은 끝난 뒤 재생.
- '지난 무전'(사용자 결정 2026-10-28): 다 들은 것도 남기고 **최근 20개**(`VoicePlayback.MAX_PAST`) — 넘치면 오래된 것부터 캐시 파일(`cache/ptt/in`)과 함께 버린다(재생 큐가 아직 쓰는 파일은 남김). 그룹이 바뀌거나 끝나면 큐(다시 틀 것 포함)·'지난 무전'·캐시 폴더를 모두 지우고, 재생 중(알림 포함)이면 멈춘다. 내려받는 중이던 항목은 버리고 재생 워커는 계속 돈다(새 그룹 무전은 그대로 재생 — 단위 테스트).
- TTS 대기(`speakAndWait`·`speakAndWaitStaged`)는 onDone·onError 뿐 아니라 **onStop**(CRITICAL 의 `QUEUE_FLUSH` 로 지워짐)에도 풀린다 — "보낼까요?" 가 지워져도 상한을 기다리지 않는다. 상한(질문·카운트다운 안내 = 시작까지 12 s + 시작 뒤 6 s, "○○ 무전" 알림 4 s)을 넘기면 **그 문장을 버린다**(B012 — 늦게 나와 마이크·녹음 재생과 겹치지 않게, `ptt: voice announce timeout … → 알림 버리고 재생`). 체인 로그 `voice: wait result=… start=…ms`(두 단계 상한일 때 시작까지 걸린 시간).
- `VoiceAnnouncer` 는 `VOICE_MESSAGE` 문구를 읽지 않는다(재생 쪽 몫 — 중복 방지). 녹음·확인·전송·재생 중에는 NORMAL·LOW 문장을 붙잡고 **HIGH 이상(급제동 등)은 그대로 읽는다**(안전 우선 — 그래서 녹음·재생과 겹칠 수 있다). 녹음을 여는 순간 이미 엔진에 넘긴 NORMAL·LOW 문장도 멈추고 무전 뒤 다시 읽는다(`yieldToMic`, 위 B013).
- 포그라운드 서비스: 마이크 권한이 있으면 `DriveSessionService` 타입에 `microphone` 을 더한다 — 순정 내비가 앞이면 동행은 백그라운드라 Android 11+ 에서 마이크 입력이 무음이 되기 때문. 백그라운드에서 막히면 microphone 을 빼고, 그래도 안 되면 dataSync 로 다시 시도. 권한 다이얼로그 결과 뒤 `DriveSessionController.refreshType` 으로 다시 시작하고, **동행 화면이 앞에 올 때마다**(`MainActivity.onResume` → `ensureType`) 실제로 붙은 타입(`DriveSessionService.attachedType`)이 권한보다 모자라면 다시 시작해 올린다 — 폰 합류·START_STICKY 재시작처럼 백그라운드에서 시작돼 microphone 이 빠진 서비스도 화면을 한 번 열면 붙는다. 타입 갱신은 화면이 보일 때만 한다(백그라운드에서 다시 시작하면 location·microphone 이 막혀 dataSync 로 떨어진다 — 디버그 `ptt_status` 도 결과 `fgs=` 만 남긴다)(§6).

## 6. 백그라운드 동작
- 그룹 활성 중에는 **포그라운드 서비스**(`DriveSessionService`)가 텔레메트리·MQTT·음성을 담당 → 다른 앱이 화면을 차지해도 동작.
- 그룹 비활성 시 서비스 종료(불필요한 상주 금지, Pleos 리소스 가이드).
- 앱 프로세스 재생성 시 `activeGroupId`로 자동 재연결.
- **(T23 구현 메모)** `domain.telemetry.TelemetryCollector`(싱글턴, 앱 시작 시 start): `MqttSessionManager.session` 이 non-null 인 동안 1초마다 `Telemetry` 를 `dh/v1/vehicle/{vid}/telemetry` 에 QoS 0 으로 발행한다.
  위치 = `LocationFeed.fixes` 최신 Fix(10초보다 오래됐거나 없으면 그 틱은 건너뜀 — 가짜 위치 금지), 속도 = `VehicleSignals.speedKph`(Car API) → 없으면 `LocationFeed.speedKph`(Haversine), 기어 = 차량 신호(UNKNOWN 은 null),
  ETA = `NaviEventMonitor.state` 의 마지막 TripInfo(120초 이내)를 **30초마다 또는 거리 500 m/시간 60 s 이상 변화 시** 포함(`destTs = tripTs + remainS`), 에너지 = 연료/SoC **1%p 변화 시 + 60초마다 재전송**.
  안내가 끝나면(내비 `RouteStateInfo` ENDED·CANCELLED 또는 목적지 없음 → `NaviEventMonitor` 가 남은 거리·시간을 비움, 또는 TripInfo 120 s 끊김) 전에 ETA 를 보냈으면 **모든 값이 빈 ETA(`{}`)를 30 s 간격으로 3번** 보내 서버의 옛 도착 시각을 지운다(A009 — 서버는 eta 가 있을 때만 덮어써 옛 '도착 HH:mm' 이 그룹 끝까지 남았다).
  그룹 이름은 로그에 남기지 않는다(기본값에 방장 닉네임 — groupId 마스킹·이름 길이만, A090).
  발행 실패(연결 없음)는 세기만 하고 재전송하지 않는다. 의존은 전부 함수/StateFlow(`di/SignalsModule` 에서 배선)라 JVM 단위 테스트로 검증한다.
  `service.DriveSessionService`(포그라운드, `foregroundServiceType="location|dataSync|microphone"` — 위치 권한이 있으면 location, 없으면 dataSync 로 시작, F16 마이크 권한이 있으면 microphone 을 더함(§5.3 — 백그라운드에서 막히면 빼고 다시, 앱이 앞에 올 때 `ensureType` 으로 다시 확인), 다 실패해도 크래시 없이 계속) 는 `DriveSessionController` 가 그룹 세션 유무를 보고 시작/종료한다. 서비스는 알림 하나로 프로세스 우선순위만 올리고, 수집·발행은 Application 싱글턴이 한다. 알림은 조용한 채널 `drive_session_quiet`(MIN 으로 만들지만 FGS 라 시스템이 LOW 로 올릴 수 있음, `CATEGORY_SERVICE`·문구 고정 — §5.2)이다.
  백그라운드에서 시작이 막히면(API 31+ `ForegroundServiceStartNotAllowedException` — 오버레이 권한 없는 실차의 폰 합류·START_STICKY 재시작) **동행 화면이 보이는 순간**(`ensureType`·`refreshType` — onResume·권한 결과) 다시 시작한다(A003, 예전엔 같은 그룹 안에서 다시 시도하지 않아 그룹 끝까지 FGS 없이 돌았다). 마지막 실패는 `lastStartFailure`. 그룹이 끝나면 시작 실패로 알고 있어도 늘 `stopService`(멱등).
- **(T16 구현 메모)** MQTT 접속은 그룹 전에도 유지한다: 폰(companion)이 이 차를 그룹에 넣는 순간 서버가 `dh/v1/vehicle/{vid}/cmd` 로 `GROUP_JOINED` 를 보내므로(docs/03 §5.5, T18) 차량은 페어링만 돼 있으면 cmd 를 듣고 있어야 한다. `MqttSessionManager` 가 Application 에서 시작해 페어링 상태(TokenStore)를 보고 붙고 끊으며, `GROUP_JOINED` 를 받으면 `GroupSessionStore`(DataStore `group_session`)에 저장하고 그룹 `state/event` 를 구독한다. 포그라운드 서비스(T23)는 이 연결을 백그라운드에서 유지하는 역할만 더한다.
- **(2026-11-02 세션을 서버와 맞추기 — A000/A001, docs/03 계약 1)** cmd 는 MQTT 영속 세션(만료 300 s) 안에서만 다시 오므로, 그보다 오래 꺼져 있던 차는 `GROUP_JOINED`(전날 합류)·`GROUP_ENDED`·`MEMBER_LEFT` 를 잃는다. 그래서 `MqttSessionManager` 는 **MQTT 가 (다시) 붙을 때마다** 차량 JWT 로 `GET /v1/vehicles/me/group` 을 부른다(`GroupMembershipSource` → `RestGroupMembershipSource`): 200(`GroupJoined` 형태) → 다른 그룹이면 갈아타고 같은 그룹이면 이름·방장·목적지·토픽만 맞춘다(합류 시각·초대 유지) / 204 → 로컬 세션을 `RECONCILED` 로 지운다 / 404·405(옛 서버) → 저장된 그룹만 `GET /groups/{id}` 로 확인해 `status=ENDED`·내 차 없음·404·409·410 이면 지운다 / 네트워크·5xx·401 → 아무것도 바꾸지 않는다(다음 접속 때 다시). 요청 중에 세션이 바뀌었으면(cmd·생성·나가기) 결과를 버린다(`skipped(changed)`). 그룹 토픽 구독이 세 번 거부돼도(`MqttGateway.subscriptionDenied`) 다시 맞춘다. 진단용 `reconcileState`(횟수·마지막 결과), 로그 `reconcile trigger=… → joined|updated|switched|cleared(none)|cleared(gone)|kept|unknown(…)`.
- 같은 그룹의 `GROUP_JOINED` 를 다시 받으면 세션을 유지하고 방장만 맞춘다(다시 보낸 cmd 가 방장을 강등하지 않게). **방장 갱신(A004)**: 그룹 이벤트 `LEADER_CHANGED`(payload `leaderVehicleId`)와 스냅샷의 `leaderVehicleId`(2초마다 — 이벤트를 놓쳐도 확정)로 세션의 `leaderVehicleId`·`isLeader` 를 맞추고, 방장이 아니게 되면 초대를 지운다(값이 같으면 저장하지 않음). 그래서 승계된 새 방장은 `ROUTE_CHANGED` 를 보내고, 위임된 옛 방장이 '종료'를 누르면 403 → 나가기로 대신한다(`GroupRepository.end`). 그룹 이벤트 `GROUP_ENDED` 도 세션 정리 신호다(cmd 만 놓친 경우).
- 그룹이 바뀌거나 끝나면 `groupEvents` replay(20)를 비운다(A010 — 이전 그룹 소식이 새 그룹 피드·그룹 관리·주행 화면에 '실시간'으로 섞였다). 세션 정리 사유는 `MqttSessionManager.lastSessionClear` → `GroupDriveUiState.endReason`(GROUP_ENDED·ENDED_WHILE_OFFLINE·REMOVED·LEFT·UNPAIRED·OTHER, A115 — 화면 문구는 E 단계).
- 그룹 관리 화면(`CreateGroupViewModel`)은 화면을 열 때 받은 replay 의 멤버 이벤트(합류·나감·방장 바뀜)로는 상세를 다시 받지 않는다(첫 상세는 폴링이 1회) — 최근 소식에는 넣는다. 실시간 멤버 이벤트는 0.5 s 모아 `GET /groups/{id}` 한 번(진행 중 요청은 끊지 않음, RA-6 — 예전엔 10대 그룹이면 열 때마다 replay 이벤트 수만큼 REST).
- 로컬 세션 삭제 `MqttSessionManager.onGroupLeftLocally(expectedGroupId)` 는 호출 쪽이 본 그룹(나가기·종료한 그룹, 상세를 받은 그룹)을 **잠금 안에서** 지금 세션과 다시 비교한다 — 그 사이 다른 그룹 `GROUP_JOINED` 가 먼저 적용됐으면 새 그룹 세션은 지우지 않는다(RA-5).
- 나가기·종료 `204 No Content` 는 본문이 없어 Retrofit 이 body=null 을 준다 — `safeUnitCall` 로 받아 성공 처리하고 로컬 세션을 바로 지운다(A002 — 예전엔 '예상치 못한 오류' 대화상자가 뜨고 세션은 MQTT 가 지워 줄 때까지 남았다).
- 설정 '연결 해제'·페어링 '연결 해제 후 다시 연결'은 먼저 `DELETE /v1/vehicles/me`(docs/03 계약 2, 3 s 상한)로 서버에서도 스스로 해제한다 — 활성 그룹에서 빠지고(방장이면 승계) 토큰이 폐기된다. 204·401(이미 해제)은 성공, 실패해도 로컬 정리는 계속(A007 — 예전엔 로컬만 지워 서버에 유령 멤버가 남았다). 이 경로의 401 은 토큰 갱신을 시도하지 않는다(`VehicleTokenAuthenticator` 제외). 해제 시 그룹 토픽은 **끊기 전에** 구독을 푼다(A070).

**T32 — 클라우드 기본 · 숨은 서버 주소 메뉴 · MQTT WSS 자동 전환**
- **release 기본 = 클라우드**: release buildType 이 `https://{dhCloudHost}` / `ssl://{dhCloudHost}:8883` 를 BuildConfig 에 넣는다. VM IP 를 받으면 gradle.properties 의 `dhCloudHost=` 를 채우거나 `-PdhCloudHost=` 로 준다(공개 주소 — 비밀 아님). VM IP 가 바뀌면 재빌드 대신 숨은 메뉴로 바꿀 수 있다.
- **숨은 메뉴 '서버 주소'** (`feature/settings/ServerAddressDialog`): 설정 화면 제목을 **3초 안에 5번 탭**(`HiddenTapCounter`) — 주행 중에는 탭을 세지 않고, 열려 있어도 저장·복원 버튼이 꺼진다(§4).
  지금 유효값과 출처(빌드 기본값/사용자 지정), 빌드 기본값을 보이고 서버 주소·MQTT 주소(비우면 페어링 응답 `mqtt.uri`)를 받는다.
  검증(`ServerAddressRules`): 서버 주소는 경로 없는 `http(s)://호스트[:포트]`(API 가 `/v1/…` 절대 경로라 경로 접두는 못 쓴다, 기본 포트 80·443 은 지워 저장 — 같은 서버인지는 scheme·host·port origin 으로 비교), 평문 http 는 `BuildConfig.DH_CLEARTEXT_HOSTS`(open = `*`, cloud = 로컬 3개) 안에서만, MQTT 는 `MqttUriPolicy` 규칙(새 서버 기준 https 면 평문 금지).
  정규화: 서버 주소는 빌드 기본값과 같은 origin 이면 '사용자 지정 아님'. **MQTT 는 빈 값만 '지정 안 함'**(= 페어링 응답) — 빌드 기본 MQTT 주소와 같은 값도 사용자 지정으로 저장한다(서버의 `DH_MQTT_PUBLIC_URI` 가 빠져 응답이 `tcp://` 라 거부될 때 바로 그 값으로 고치는 메뉴라서). BuildConfig `DH_MQTT_PUBLIC_URI` 는 접속·표시에 쓰이지 않는다.
  저장 전 확인 창 → `ServerSwitcher.apply`: **서버 주소가 바뀌면 `TokenStore.clear(SERVER_CHANGED)`**(차량 JWT 는 그 서버의 RS256 키로 서명돼 다른 서버·EMQX JWKS 에서 무효) → `MqttSessionManager` 가 토큰 Empty 를 보고 MQTT 를 끊고 그룹 세션을 정리(기존 경로) → 폰에서 다시 연결. 시계도 새 서버로 다시 맞춘다(`ClockSync.resync`). **MQTT 주소만 바뀌면** 같은 자격 증명으로 끊었다 다시 붙는다. 어느 쪽이든 기억한 MQTT 전송은 지운다. [기본값 복원] = 사용자 지정 삭제(같은 규칙).
  `ServerSwitcher` 는 앱 수명 범위(자체 `SupervisorJob` + IO)에서 돈다 — 설정 화면을 벗어나 ViewModel 이 취소돼도 주소 교체·토큰 삭제·재연결이 반쯤 멈추지 않고(`await` 만 취소), `commit()`·MQTT 끊기(최대 3 s)가 메인 스레드를 막지 않는다.
  REST 는 `ServerHostInterceptor`(OkHttp, 로깅·인증 인터셉터보다 앞)가 Retrofit base(빌드 기본값) origin 으로 가는 요청의 scheme·host·port 만 유효값으로 바꾼다 — Retrofit·API 인터페이스 재생성 없음, 토큰 갱신 전용 클라이언트에도 같은 인터셉터. 저장: SharedPreferences `server_config`(인터셉터가 요청마다 동기로 읽으므로 DataStore 대신). 홈 빌드 정보·진단 빌드 카드의 서버 주소는 유효값 + "(사용자 지정)", **MQTT 주소는 실제로 쓰는 값**(`MqttAddressDisplay`): 사용자 지정 "(사용자 지정)" > 지금 자격 증명의 `mqtt.uri` "(서버가 준 주소)" > 페어링 전 "페어링하면 서버가 알려 줘요". 실제 전송(wss 폴백 등)은 진단 MQTT 카드 '브로커'·'전송'.
- **MQTT WSS 자동 전환** (`MqttTransportFallback` 순수 로직 + `HiveMqttGateway`): 서버 주소(유효값)가 https 면 후보 = [기본 전송(서버 응답/사용자 지정, 클라우드 `ssl://…:8883`), 파생 `wss://{베이스 호스트}[:{베이스 포트}]/mqtt`(기본 443)]. 파생 규칙은 docs/03 머리말 — 서버 응답(protocol)은 바꾸지 않는다. http(로컬)면 후보는 하나(1883 직결).
  - 실패 분류(`mqttFailureKind`, 원인 사슬): CONNACK 응답(인증 거부 등) = 브로커에 닿음 · DNS 실패(`UnknownHostException`)·`ENETUNREACH` = 망 없음(터널·시동 직후 — 후보가 같은 호스트라 전송을 바꿔도 같다) → **둘 다 세지 않고** 연속 실패도 지운다 · 그 밖(거부·시간 초과·TLS/WebSocket 핸드셰이크 실패·`EHOSTUNREACH`) = 닿지 못함. `EHOSTUNREACH` 는 방화벽 ICMP host-prohibited 거절(firewalld 기본)에서도 나와 8883 차단 신호일 수 있어 센다. 연결됐다 끊긴 것도 실패 아님.
  - 전환 조건 ① 닿지 못한 시도가 **연속 2회** → 재연결 직전 `reconnector.transportConfig(…)` 로 전송만 바꾼다(같은 클라이언트·clientId·세션). ② **첫 연결이 10 s 안에 안 됨**(소켓·TLS 가 매달리는 8883 차단망 — 아직 붙은 적·전환한 적·브로커 응답(인증 거부 뒤 갱신 대기 포함)·망 없음이 없을 때 한 번) → 다음 전송을 **정해만 두고** 매달린 시도가 끝나면(실패 콜백) 또는 다음 시도 직전(gate 콜백)에 같은 클라이언트에 적용한다 — 클라이언트를 새로 만들지 않아 늦게 붙은 이전 연결이 새 연결의 세션을 빼앗고(EMQX session taken over) LWT offline 을 내보내는 일이 없다. 매달린 시도가 늦게 붙거나 브로커 응답·망 없음으로 끝나면 그 전환은 무른다.
  - 다음 시도 대기: 마지막 연결 뒤 **한 바퀴 안**의 새 전송은 1 s 뒤 곧바로, **후보를 한 바퀴 다 돈 뒤**(망·서버 문제일 가능성)는 계속 번갈아 시도하되 정상 백오프(1 s → 30 s)·로그 INFO 로 — 서버 다운 중 재시도가 두 배가 되거나 WARN 이 30초마다 쌓이지 않는다.
  - WebSocket: HiveMQ `transportConfig().sslWithDefaultConfig().webSocketConfig().serverPath("mqtt").subprotocol("mqtt")` — 시스템 신뢰 저장소 TLS(Let's Encrypt, API 28 포함). `io.netty:netty-codec-http:4.1.115.Final` 을 직접 의존(HiveMQ POM 에서 optional — 없으면 wss 사용 시 NoClassDefFoundError).
  - 기억: **다른 전송이 실제로 실패한 뒤 한 바퀴 안에 붙은 전송만** SharedPreferences `mqtt_transport`(`{브로커 호스트}|{tls|wss}`)에 남겨 다음 시작에 먼저 시도, 그 전송이 같은 조건으로 실패하면 반대로 돌아간다(그 전송으로 붙으면 기억을 고친다). 망 없음·인증 거부·한 바퀴 다 실패(서버 다운)로는 바뀌지 않는다 — 망이 돌아온 순간의 전송이 우연히 기억돼 8883 이 열린 망에서도 wss 로 고정되는 일이 없다. 서버 주소를 바꾸면 지운다.
  - 관측: 로그 `mqtt transport fallback → wss (from tls: 2 failed attempts cause=…) broker=<host>:443` 또는 `… (from tls: not connected in 10s — applied at next attempt) …` + `mqtt transport wss applied after the hung tls attempt ended`, `mqtt connected broker=<host>:443 transport=wss …`; `MqttStatus.transport`(tcp/tls/ws/wss)·`transportFallbacks` → 진단 MQTT 카드 '전송', 30초 `health … tr=wss …`.
  - 단위 테스트: 결정은 `MqttTransportFallbackTest`(실패 종류·한 바퀴·시간 초과 무르기·인증 거부 뒤 시간 초과 → 전환 없음·기억 규칙), 배선은 `HiveMqttGatewayFallbackTest` 가 실제 HiveMQ 클라이언트를 로컬 소켓(받자마자 닫는 서버 / 3 s 붙잡는 서버, EMQX 없음)에 붙여 ssl 2회 실패 → 같은 클라이언트 wss 전환, 시간 초과 → 매달린 시도가 끝난 뒤에야 wss 시도를 확인한다.
- 남은 것(VM 수령 후, docs/08 T32): 실 VM 에서 ssl 8883 연결·WSS 폴백(숨은 메뉴 MQTT 주소에 닫힌 포트 `ssl://<VM-IP>.sslip.io:8884` → 거부면 2~3 s, 방화벽이 버리면 약 10 s 뒤 `→ wss`) 로그·진단 캡처.

## 8. T33 구현 메모 — 토큰 수명·저장소 오류·재연결·로그 보존
배경: docs/10 R13 — 확인 창 없는 해제 버튼이 토큰을 지웠고, `MqttSessionManager` 가 토큰 Empty 를 보면 사유 불문 그룹 세션까지 지웠다. 차량 토큰(24h)에는 갱신 흐름이 없어 만료 뒤 REST 401·MQTT 인증 거부 무한 재연결인데 홈은 '연결됨' 인 상태가 될 수 있었다.

**토큰 저장소 상태** (`core/common/TokenStore`)
```
Loading ─ load() ─┬─ Present(credentials)
                  ├─ Empty                 ← 미페어링 / clear(reason)
                  └─ Unavailable(reason)   ← 생성·읽기 예외(Keystore·SecurityException·IOException…). 지운 게 아니다
```
- `EncryptedTokenStore` 는 생성 실패를 프로세스 동안 고정하지 않는다 — 다음 `load()`/`save()` 가 다시 만든다. 쓰기 실패는 이번 실행 동안만 메모리에 두고(Present 유지) E 로그·`dh_diag` 기록.
- `clear(reason: TokenClearReason)`: `USER_SETTINGS_DISCONNECT`·`USER_REPAIR`·`TOKEN_REVOKED_CMD`·`REFRESH_REJECTED`·`SERVER_CHANGED`(T32 런타임 서버 변경용)·`STORE_RESET`(설정 '저장소 초기화' — `dh_tokens` 파일째 삭제). 암호화 파일을 열 수 없으면 파일째 지운다.
- `updateTokens(expectedRefresh, access, refresh)`: refresh 회전 결과를 한 번의 commit 으로, 보낸 refresh 가 아직 저장돼 있을 때만(compare-and-set) — 갱신 도중의 연결 해제를 되살리지 않는다.
- `clearIf(expectedRefresh, reason)`(T33 리뷰): 저장된 refresh 가 보낸 것과 같을 때만 지운다 — 비교·삭제가 저장소 잠금 안에서 한 번에라, 갱신 응답을 기다리는 사이 재페어링한 새 자격 증명을 옛 401 이 지우지 않는다.
- `StoredCredentials`·`TokenStoreState.Present` 의 `toString()` 은 마스킹 값만(vehicleId·ownerId 앞4+뒤2, 토큰 앞 4자+길이, 닉네임 첫 글자) — 상태를 통째로 문자열에 넣어도 logcat·링 버퍼·`dh_log.txt` 에 원문이 남지 않는다(규칙 8, T33 리뷰).
- `GroupSessionStore.clear(reason: SessionClearReason)`: `UNPAIRED`(토큰 Empty 일 때만)·`GROUP_ENDED`·`MEMBER_LEFT_ME`·`LEFT_LOCALLY`·`STORE_CORRUPT`·`RECONCILED`(재접속 때 서버와 맞춰 보니 끝났거나 멤버 아님, §6). DataStore `group_session` 에 `ReplaceFileCorruptionHandler` — 손상이면 빈 값으로 갈아 끼우고 `STORE_CORRUPT` 기록, 해석 불가 세션도 비운다. 읽기 I/O 오류는 '세션 없음'(파일 유지).
- 삭제 기록: 일반 SharedPreferences `dh_diag` 에 마지막 토큰 삭제·세션 삭제·저장소 오류의 사유·시각·마스킹 ID(`ClearRecord`) + `DhLog.i("token store: cleared reason=… vehicleId=veh_…7Q")`. 설정 '마지막 해제', 진단 '토큰·저장소' 카드에 표시.

**MqttSessionManager** — Present: 접속·구독. Empty: 옛 cmd 토픽 구독 해제·끊기·세션 `UNPAIRED` 삭제. **Unavailable: 세션 유지, 연결 안 함, 30 s 간격 최대 10회 `load()` 재시도**(홈 '다시 시도' 가 처음부터 다시). `start()` 의 코루틴에 `CoroutineExceptionHandler`, 단계마다 예외를 삼켜 수신 루프가 끊기지 않게 했다. cmd `TOKEN_REVOKED` 는 `clear(TOKEN_REVOKED_CMD)` — 단 봉투 `ts`(epoch ms, 서버 시계)를 초로 내린 값 ≤ 지금 토큰 `iat`(초)면 재페어링 전 MQTT 영속 세션(clientId = vehicleId, 세션 만료 300 s)에 쌓였다 늦게 온 것이라 무시한다(같은 초도 무시 — 해제 직전 같은 초에 갱신된 토큰은 남을 수 있다). 300 s 넘게 오프라인일 때의 해제는 cmd 가 사라진다 — 다음 갱신 401 까지 '연결됨' 으로 남는 한계(docs/03 §1.3). 단계별 예외 로그에는 상태 객체가 아니라 종류 이름만 넣는다(`token state Present`).

**차량 토큰 갱신** (`domain/pairing/TokenRefresher`, 싱글턴, `DongHaengApp` 에서 start)
- 선제: 앱 시작 직후·30분마다 JWT payload `exp`(base64url, 서명 검증 없음 — `JwtClaims`)를 보고 남은 시간 ≤ 2시간이면 `POST /v1/auth/refresh`.
- REST 401: `VehicleTokenAuthenticator`(OkHttp `Authenticator`) → `runBlocking { refreshAfterRejection(거부된 토큰) }` → 새 Bearer 로 1회 재시도. `/v1/auth/*`·`/v1/device/*`·`priorResponse` 있음·Bearer 없음은 제외. 갱신 호출은 **Authenticator 가 없는 별도 OkHttpClient**(`@RefreshClient IdentityApi`, 자기 Dispatcher) — 기본 클라이언트 스레드가 막혀도 호스트당 동시 요청 한도에 걸려 교착하지 않는다.
- MQTT: `HiveMqttGateway` 의 disconnected 리스너가 cause 의 `Mqtt5ConnAckException` reasonCode `NOT_AUTHORIZED`/`BAD_USER_NAME_OR_PASSWORD` 를 보면 `authFailures` 로 알리고(`MqttStatus.authFailures`·`lastAuthFailureAtMs`) 재연결을 최대 15 s 미룬다 → `MqttSessionManager` 가 갱신 → 저장소가 새 토큰을 내면 `connect(새 토큰)` 이 대기 중인 재연결을 즉시 연다.
- single-flight `Mutex`: 기다리는 동안 다른 호출이 회전했으면(거부된 토큰 ≠ 현재 토큰) 서버를 다시 부르지 않는다. 방금(60 s 안) 받은 토큰이 또 거부되면 회전하지 않고(`Throttled`), MQTT 발 시도는 30 s 간격.
- **MQTT 발 회전 백오프**(T33 리뷰): 회전한 새 토큰도 브로커가 거부하면(EMQX JWKS 캐시·kid 불일치·authn 설정 등 토큰과 무관한 원인) 다음 MQTT 발 회전까지 1→2→4→8→16→30분. MQTT 가 CONNECTED 가 되면(`MqttSessionManager` → `TokenRefresher.onMqttConnected()`) 처음부터. 백오프 중 `Throttled` 는 구간마다 W 한 줄만(`token refresh backoff … streak=N`). 단계는 `TokenRefreshState.mqttRotationStreak` → 진단 'MQTT 발 갱신 백오프'·health `mqttRot`.
- 결과(T33 리뷰 반영): refresh 401 은 본문 `code == INVALID_TOKEN` 일 때만 자격 증명 문제(그 밖의 401 은 프록시·캡티브 포털일 수 있어 `Failed`, 토큰 유지).
  - 선제 갱신(STARTUP/PERIODIC/MANUAL)이 401 인데 access token 이 아직 유효 → `RejectedDeferred`: 지우지 않고 `repairNeededSinceMs` → 홈 '다시 연결이 필요해요 — HH:mm 까지는 지금처럼 동작'. 다음 점검은 만료 직후(+5 s)로 당겨져 그때 401 이면 지운다. 회전 응답 유실(서버 커밋 뒤 타임아웃) 때 그룹 세션까지 즉시 지워지던 문제(R13 과 같은 결과)를 막는다.
  - 실제 거부(HTTP_401/MQTT_AUTH) 뒤 401, 또는 access token 도 만료 → `clearIf(보낸 refresh, REFRESH_REJECTED)` → 홈 '폰에서 다시 연결해 주세요'.
  - 네트워크·5xx → 토큰 유지. 선제 갱신이면 20 s 뒤 한 번 더(서버 재사용 유예 60 s 안 — docs/03 §1.1), 그다음은 30분(만료 시각을 넘기지 않음). `ApiResult.HttpFailure.Unauthorized`(401) 하위 타입.
- `TokenRefreshState.accessExpiresAtMs` 는 저장소 상태를 구독해 재페어링·해제·회전 즉시 갱신(진단 '토큰 만료'·health `expMin` 이 옛 토큰 값으로 남지 않게).
- 그룹 화면 REST 401: 자격 증명이 서버 사유(`REFRESH_REJECTED`·`TOKEN_REVOKED_CMD`)로 지워졌을 때만 '폰에서 다시 연결', 그 밖(갱신 네트워크 실패·백오프)은 '연결을 확인하고 잠시 후 다시 시도해 주세요'.

**재연결 보강 (2026-11-02)** — 실측: EMQX 재시작 5 s 인데 차가 다시 붙기까지 138~273 s(인증 거부를 토큰 문제로 보고 15 s 대기·토큰 회전·회전 백오프, Caddy 502 를 '전송 막힘'으로 세어 8883↔wss 왕복).
- **브로커 재시작 창**(A-RT1, 순수 `MqttReconnectPolicy` + 단위 테스트): 붙어 있던 연결이 끊긴 뒤 2분 동안 ① 일반 실패 백오프 상한 5 s ② 지금 토큰이 만료까지 5분 넘게 남았으면 CONNACK 인증 거부(EMQX JWKS 미적재)는 **토큰을 갱신하지 않고** 3 → 5 → 10 s 로 다시 시도 ③ 끊긴 뒤 60 s 동안 **'브로커 앞단은 답했지만 브로커가 아직 준비 안 됨'** 실패(`mqttBrokerNotReady` — 연결 거부, TLS·WebSocket 뒤 CONNACK 없이 깨끗이 닫힘(클라우드 Caddy L4), WSS 업그레이드 5xx(Caddy 502))는 전송 폴백에 세지 않는다(방금까지 그 전송으로 붙어 있었다). 연결 시간 초과·TLS 핸드셰이크 실패·연결 재설정·EHOSTUNREACH 는 창 안에서도 센다(RA-8 — 주행 중 8883 을 막는 망으로 바뀌면 예전처럼 실패 2회(약 25 s) 뒤 WSS, 예전 규칙이면 70~90 s 끊김). 창 밖·처음부터 못 붙은 경우는 아래 기존 규칙. 로그 꼬리 `(broker restart window)`·`token kept`. 목표 60 s 안 재연결(단위 테스트의 재시작 장면 시뮬레이션: JWKS 40 s 에 적재 → 40 s 에 재연결).
- **판단과 적용 분리**(RA-7): 끊김마다의 판단(붙어 있었나·끊긴 시각·창 안 인증 거부 수·토큰 대기·전송 폴백 집계)은 접속별 순수 `ReconnectTracker.onDisconnected(DisconnectEvent) → DisconnectPlan`, SUBACK 결과 처리(거부 표시·세 번째 거부 알림·재시도 예약, 접속 세대가 바뀌면 중단)는 순수 `SubscribeRetrier`(스케줄러 주입) — 게이트웨이는 계획만 적용한다. 배선은 실제 HiveMQ 클라이언트 + 테스트용 최소 MQTT 5 브로커(`HiveMqttGatewayWiringTest`, 로컬 소켓)로 고정: CONNECT keepAlive 30(처음·재연결), 끊긴 뒤 NOT_AUTHORIZED 는 토큰 갱신 요청 없이 3 s → 5 s, SUBACK 0x87 재시도·`deniedTopics`·알림 한 번·받아들여지면 지움.
- **구독 재시도**(A018): SUBACK 거부(EMQX 인가 훅이 아직 안 됨 → no_match=deny 0x87)·실패는 같은 접속이 살아 있고 토픽이 아직 목록에 있는 동안 2 → 4 → 8 → 16 → 30 s 로 다시 건다(서버 공유 구독 재시도와 같은 모양). 세 번째 거부에 `subscriptionDenied` 로 알려 세션 관리자가 소속을 다시 맞추고, `MqttStatus.deniedTopics` 에 보인다(진단 표시는 E 단계).
- **끊긴 동안의 구독 해제**(A070): 연결이 없을 때 푼 토픽은 다음 접속 때(다시 구독하기 전) UNSUBSCRIBE 를 보낸다 — `cleanStart=false` 영속 세션에 떠난 그룹의 좌표 구독이 남지 않게.
- keepAlive 30 s(A072, docs/02 §6 — 기본 60 s 면 조용히 끊긴 연결을 약 120 s 동안 '연결됨'으로 본다).
- 발행 봉투 ts = `ClockSync.serverNow()`(동기화 전이면 기기 시각 — docs/03 계약 4, A068). 서버는 신선도·OFFLINE·정차 판정에 수신 시각을 쓰고 차량 ts 는 참고만.

**재연결** (`HiveMqttGateway`): automaticReconnect 는 켜 두되 대기 시간은 게이트웨이가 정한다 — 끊길 때마다 `reconnector.delay(0)` + `reconnectWhen(gate)` 로 다음 시도를 우리 타이머(1 s → 30 s 지수 백오프 ±20 %, 인증 거부는 ≥ 15 s)에 묶고, 시도 직전 콜백에서 최신 토큰을 다시 싣는다(HiveMQ 1.3.4 javap: `connectWith`·`reconnect(false)` 는 이벤트 루프면 콜백에서도 가능, `reconnectWhen`·`delay` 는 리스너 안에서만). 앱이 끊거나 클라이언트를 갈아 끼우면 이전 클라이언트는 retired — 콜백이 `reconnect(false)` 로 대기 중 재연결을 취소하고, 늦게 붙으면 바로 끊는다(같은 clientId 두 개가 서로 밀어내지 않게). 토큰만 바뀌면(갱신) 연결은 유지 — EMQX 가 옛 토큰 `exp` 에 끊으면 다음 재연결이 새 토큰을 쓴다.
