## 3. 어댑터 인터페이스

```kotlin
interface VehicleAdapter {
    suspend fun vehicleId(): String?                    // CarInfo 차량 ID
    fun fuelPercent(): Flow<Int?>                       // Fuel.registerFuelPercent
    fun evStateOfCharge(): Flow<Int?>                   // EvBattery.registerEvBatteryStateOfCharge
    fun brakePedal(): Flow<Boolean>                     // Brake.registerBrakePedalStatus
    fun turnSignal(): Flow<TurnSignalState>             // TurnSignal.registerTurnSignalState

interface NaviAdapter {
    fun events(): Flow<NaviEvent>   // CurrentLocation, TripInfo, DrivingInfo, RouteStateInfo,
                                    // DestinationChanged, WaypointChanged, WaypointArrived, DestinationArrived,
                                    // SpeedLimit, NavigationStatus, Error
    suspend fun requestRoute(dest: Place)
    suspend fun requestRouteWithWaypoints(dest: Place, waypoints: List<Place>)
    suspend fun addWaypoint(place: Place, index: WaypointIndex = WaypointIndex.FIRST)

interface LocationAdapter { fun locations(): Flow<Fix> }   // Fix(lat, lon, heading, accuracy, ts, source)

### 3.1 Pleos SDK 사용 규칙 (공식 문서·샘플 기준)
- `Vehicle(context).initialize()` 후 `vehicle.getFuel()` 등 `getXxx()`로 도메인 객체를 얻는다. 사용이 끝나면 `vehicle.release()`.
- get·set·capability 결과는 `onComplete`/`onFailed` 비동기 람다. **콜백이 끝나기 전에 release 금지.**
- 구독은 `registerXxx(listener)` / `unregisterXxx(listener)` — **등록한 같은 리스너 객체·같은 area로 해제.**
- 지원 여부를 먼저 `checkXxxCapabilities`로 확인하고, 미지원이면 그 기능을 UI에서 숨긴다.
- NaviHelper: `NaviHelper(context)` → `initialize()` → `addListener(NaviHelperEventListener)` → 요청 → `removeListener` → `release()`.
  - 경로 요청 데이터: `RouteInfo(latitude, longitude, poiId, poiName, poiSubId, address)`,
    `RequestWaypointInfo(..., waypointIndex = WaypointIndex.FIRST, ...)`, `RouteWithWaypointsRequest(destination, waypoints)`
  - 사용하는 콜백: `onCurrentLocationInfo`, `onTripInfo`, `onDrivingInfo`, `onRouteStateInfo`, `onDestinationChanged`,
    `onWaypointChanged`, `onWayPointArrived`, `onDestinationArrived`, `onRouteStarted`, `onRouteEnded`, `onRouteCancelled`,
    `onCurrentRoadSpeedLimit`, `onNavigationStatus`, `onError`
  - 실제 전달되는 이벤트는 Navigation 앱 상태에 따라 다를 수 있으므로 **모든 필드를 nullable로 다룬다.**
- 데이터 클래스 필드명은 SDK 버전에 따라 다를 수 있다 → 어댑터 안에서만 SDK 타입을 다루고, 밖으로는 우리 도메인 타입으로 변환.
- **T20 구현 메모 (`PleosNaviAdapter`, NaviHelper 3.0.5 javap 확인):**
  - `events()` 는 `callbackFlow` — 구독마다 리스너 1개 등록, `awaitClose` 에서 같은 리스너로 `removeListener`. 안내 중이 아니면 위치 콜백이 없으므로 구독 중 1초마다 `getCurrentLocationInfo()` 를 요청한다(응답은 `onCurrentLocationInfo`). 구독 시작 시 `getRouteStateInfo()`·`getDestinationInfo()` 1회.
  - `onDestinationChanged()` 는 인자가 없다 → `getDestinationInfo()` 재요청 → `onDestinationInfo(DestinationInfo)` 를 `DestinationChanged(Place)` 로. `onWaypointChanged` 도 같은 방식으로 `getWaypointInfo()` → `onWayPointInfo(List)`.
  - SDK `TripInfo(distance, eta)` 와 `DrivingInfo.destination(DrivingState duration/distance)` 둘 다 도메인 `TripInfo` 로 보낸다. `onWayPointArrived`/`onDestinationArrived` 는 이름·주소만 주므로 마지막으로 알던 목적지·경유지 목록에서 `Place` 를 찾아 채운다.
  - `onCurrentRoadSpeedLimit` 는 AVD 에서 1Hz 로 같은 값(0)이 반복돼 **값이 바뀔 때만** `SpeedLimit` 이벤트로 올린다. `onNavigationStatus` 의 `isGuiding` = `ROUTE_DRIVE`.
  - `currentDestination()` = 임시 리스너 등록 → `getDestinationInfo()` → `onDestinationInfo` 2초 대기(없으면 null). `showNavigation()` = `requestNavigationScreen(NavigationScreenRequest.RouteOptionList)` — **`pleos.car.permission.NAVI_CUSTOM_MAP` 필요**(SDK 가 검사하는 권한: NAVI_ROUTE, NAVI_ROUTE_SEARCH, NAVI_CUSTOM_MAP, NAVI_CUSTOM_ROUTE, NAVI_CUSTOM_ETC(InternalApi)).
  - 확인 화면: 진단 → "내비 이벤트 (T20)" 카드(콜백 종류별 수·마지막 값·확인용 요청 버튼), 캡처 `docs/images/t20/`.
  - 도메인 `WaypointIndex.FIRST/LAST` → SDK `WaypointIndex.FIRST/SECOND`(SDK 는 경유지 2개까지). `RouteInfo`/`RequestWaypointInfo` 는 named-arg 로 생성(`poiSubId="0"`, `routeOption=RECOMMENDED`).
  - 앱 전체에서 리스너는 `NaviEventMonitor`(싱글턴) 하나만 구독하고 나머지(T23 텔레메트리, T26 이벤트, 진단 화면)는 그 `events` SharedFlow / `state` 를 쓴다. 스트림이 끝나거나 예외면 10초 뒤 재구독.
  - `FakeNaviAdapter` 는 `assets/gpx/lead.gpx`·`follow.gpx`(직선 보간 가상 경로, 약 57 km) 를 틱당 `speedMps` 로 재표본화해 1Hz 재생 — heading 은 다음 점 방향, 10틱마다 `TripInfo`(경로 잔여 거리/시간)·`DrivingInfo`, 경유지 60 m 이내 `WaypointArrived`, 종점에서 `DestinationArrived`+`RouteStateInfo(ENDED)` 1회 후 정지. GPX 가 없으면 기준점 드리프트로 폴백.

### 3.2 위치 소스 우선순위
1. `FusedLocation.isSupported()` 와 `pleos.car.permission.FUSED_LOCATION` 런타임 승인이 **모두** true → FusedLocation (선택 사항 — Playground 상 "준비 중"이지만 SDK는 배포됨, 에뮬레이터에서 런타임 확인. 없어도 아래 체인으로 동작, CLAUDE.md 규칙 5)
2. NaviHelper `onCurrentLocationInfo` (주력 대안)
3. Android `LocationManager` (AAOS 표준)
4. Fake (GPX 재생, 개발·데모용)

속도: Car API → 실패 시 연속 위치로 계산(Haversine / Δt, 3샘플 이동평균).

**T21 구현 메모:**
- `adapter.location.LocationSource`(source, isAvailable, staleTimeoutMs, locations) 를 `CompositeLocationAdapter` 가 순서대로 시도한다. 첫 Fix 10초 / 이후 소스별 stale(기본 5초, Android 15초) 안에 Fix 가 없거나 스트림이 끝나면 다음 순위, 끝까지 실패하면 5초 뒤 처음부터. 하위 소스를 쓰는 동안 60초마다 상위 소스를 **병렬로** 짧게 구독해 Fix 가 실제로 오면 올라간다(탐색 중에도 현재 Fix 는 계속 흘러 1Hz 에 구멍이 없다). 발행 `Fix.source` 는 실제 소스.
- 소스: `PleosFusedLocationAdapter`(pleos: `FUSED_LOCATION` 승인 && `isSupported()` 일 때만 가용, register/unregister 같은 리스너, `confidence` 는 미터가 아니라 accuracy=null) → `NaviLocationSource`(`NaviEventMonitor.events` 의 CurrentLocation — 리스너 중복 없음) → `AndroidLocationSource`(FINE 승인 + GPS/NETWORK provider, 30초 이내 lastKnown 먼저, 1초/0 m 업데이트) → `FakeLocationAdapter`(항상, 고정점).
- `domain.location.LocationFeed`(싱글턴, 앱 시작 시 start): 체인을 한 번만 구독해 `fixes`(replay 1)·`speedKph`·`state` 제공. 소스가 바뀌면 `SpeedEstimator` 리셋. T23 텔레메트리·T26 이벤트는 이걸 구독한다. 권한이 바뀌면 `restart()`.
- `SpeedEstimator`: Δt<0.5s 샘플은 기준점 유지, Δt>10s 면 창 초기화, 250 km/h 초과는 튐으로 무시, 3샘플 평균.
- 권한 요청 시점: `feature.permissions.LocationPermissionGate`(NavHost 옆) — **활성 그룹 + 정차** 일 때 1회 `ACCESS_FINE/COARSE_LOCATION`(+API 33 `POST_NOTIFICATIONS`) 요청, 결과와 무관하게 체인 재탐색. 진단 화면 "위치 소스 (T21)" 카드에도 요청·재탐색 버튼.
- Pleos AVD 실측(2026-10-27): `FUSED_LOCATION` 이 미승인으로 나와 FUSED 건너뜀 → NAVI 첫 Fix 없음(내비 앱 미동작) → ANDROID gps 활성. `adb -s emulator-5556 emu geo fix <lon> <lat>` 를 1Hz 로 이동시키면 속도 ≈ 62 km/h 로 계산된다. fake flavor 는 NAVI(FakeNaviAdapter GPX) 가 활성.

### 3.2.1 차량 신호 구현 메모 (T22)
- `PleosVehicleAdapter` 신호 Flow 는 공통 골격 `vehicleFlow(name) { v -> register…; 현재값 1회 조회; Cleanup { unregister(같은 리스너) } }` — SDK 없으면 빈 스트림, 미지원(onFailed)은 `null` 한 번 후 종료(Int 계열) / 빈 스트림(Boolean 계열).
  리스너 파라미터는 **nullable**(`Int?`, `Boolean?`, `TurnSignalValue?`, `VehicleGear?`; javap + 컴파일 실측), `onFailed(Exception)` 은 non-null.
- 에어백: `checkAirbagDeployedCapabilities` 가 준 좌석 영역마다 `registerSeatAirbagDeployed(area, listener)` → 하나라도 true 면 true. AVD 는 check 자체가 실패 → 빈 스트림.
- 속도: Pleos SDK 에 없음 → `CarApiSignals`(AAOS `android.car`, `useLibrary("android.car")` + pleos 매니페스트 `uses-library required=false`) `PERF_VEHICLE_SPEED`(m/s×3.6). dangerous 권한 `CAR_SPEED` 는 `LocationPermissions.runtimePermissions()` 가 자동차 기기에서만 묶어 요청. 기어: Pleos `Gear.registerGearSelection`(check 메서드 없음 → 현재값 조회로 capability 판정) → 실패 시 Car API `GEAR_SELECTION`.
  Car API 속성 목록은 앱 시작 직후 비어 있을 수 있어(AVD 실측) probe 를 1.5초 간격 3회 재시도한다.
- `domain.vehicle.VehicleSignals`(싱글턴, 앱 시작 시 start): 신호마다 독립 코루틴으로 구독해 최신값·수신 수·스트림 상태를 `state` 로 제공, 끝난/실패한 스트림은 30초 뒤 재구독, 값이 바뀔 때만 로그 `vehicle signal fuel=61`. T23 텔레메트리·T26 이벤트는 이걸 쓴다(어댑터 Flow 를 직접 또 구독하지 않는다).
- AVD 실측(2026-10-27, Virtual Console HTTP): 기어 Reverse → `gear=R`, 브레이크 70% → `brake=true`, 방향지시등 BlinkLeft → `turn=LEFT`, EV SoC 23 → `soc=23`, 속도 55 km/h → `speed=55.0`(Car API). Fuel 은 `property ID is not in carPropertyConfig list` 로 미지원(null), Airbag check 실패 → 빈 스트림.
- Virtual Console 을 스크립트로 조작하려면 `adb forward tcp:8089 tcp:8088` 뒤 **`POST /browser/session` 을 1초마다 보내 세션을 살려 두고**(timeout 3초, 없으면 PUT 이 503) `PUT /vehicle/gear?gear=Reverse`, `PUT /vehicle/controls?speed_kph=55&brake_pct=70`, `PUT /vehicle/turn-signal?mode=BlinkLeft`, `PUT /vehicle/ev-battery?field=soc&value=23`; 상태는 `GET /vehicle/state`, 항목 목록은 `GET /vehicle/catalog`(`write_endpoint`·`control.field`).

### 3.3 급제동 판정 (EventDetector)

### 5.1 정차 대시보드 (GROUP_DRIVE 경로, 2026-10-28)
그룹 주행 경로(`DhRoutes.GROUP_DRIVE`)의 화면은 T25 의 리스트+지도 대신 `feature.drive.DriveDashboardScreen` 이다(시안 D1·D2 → 실데이터). **주행 중 앞 화면은 순정 내비**이므로 이 화면은 그룹 생성·합류 직후와 **정차 중**에 본다.
- 데이터: `GroupDriveViewModel`(T25 상태 + `RouteSyncEngine.activeWaypoint` + `NaviEventMonitor` 제한속도 + `LatencyMeter` 이벤트 지연 + `SurfaceFeed` 모드·실제 수신 시각이 붙은 최근 이벤트) → 순수 함수 `DriveDashboardMapper` → `DriveDashboardUi`(단위 테스트 `DriveDashboardMapperTest`).
- 대열 막대: 위치(선두까지 거리)를 아는 차만, `offsetKm = (최후미 distanceToLeaderM − 그 차 값)/1000`, 대열 길이 = 최후미 값, 바로 앞차와 3 km 초과면 주황 구간, 간격은 내 차 기준("앞 1.2 km"/"뒤 350 m"). 막대 끝 = 다음 정차지(내 위치 + 직선거리), 없으면 선두 + 2 km. 오른쪽 끝 "{목적지} {내 남은 km} km".
- 다음 정차지 = `RouteSyncEngine` 이 **마지막으로 수락(멤버)·발행(선두)한 경로의 첫 경유지**(`RouteSyncState.activeWaypoint` — 경유지 없는 경로 수락·내비 경유지 도착·그룹 변경 시 null). 다음 정차 카드는 경유지가 있을 때만(이름·내 위치에서 직선거리; 차별 ETA·주유/충전·도달 가능은 아직 모름 → 생략·"—").
- 그룹 도착 = 멤버 `eta.destTs` 최댓값과 그 차, 내 도착 = 내 eta(남은 km·분). 내 주행 줄 = 제한속도(내비, 0 은 숨김) · 연속 주행(`ContinuousDriveTimer` — 앱 시작부터 `DrivingStateMonitor` 를 따라 주행 구간만 더하고, **15분 이상 정차하면 0**, 짧은 정차는 유지; 2시간 이상 주황 + 휴식 권장. 처음 구현은 그룹 합류 `joinedAtMs` 부터 세어 밤새 이어진 시연 그룹에서 정차 중인데도 "연속 주행 18시간 27분"을 띄웠다) · "다음 휴식 추천: {경유지}"(회전 안내 자리 — 회전은 순정 내비 몫).
- 이벤트 띠·지난 소식은 플로팅 패널과 같은 규칙(`surface.SurfaceEvents`): **내 차 출처 제외**, 띠 = 받은 지 10초 안 **그리고** 서버 시계(`ClockSync.serverNow`)로 60초 안에 생긴 가장 최근 이벤트(없으면 띠 숨김), 정차 블록 '지난 소식' = 발생 시각(봉투 ts) 최신 5개, "N초 전" = 서버 시계 − 봉투 ts(+[더 보기] → 이벤트 피드). MQTT 세션 유지(cleanStart=false) 때문에 재접속하면 브로커가 쌓아 둔 QoS1 옛 이벤트를 한꺼번에 '지금' 보내는데, 이들이 '방금 소식'·"0초 전"으로 보이지 않게 하려는 것이다(카드 60 s·음성 5 s 와 같은 기준). 정차 블록 버튼: 그룹 관리(→ 그룹 생성 화면 Active: 초대 QR·멤버·나가기/종료 — **확인 다이얼로그**를 거친다, 방장 한 번 탭 = 그룹 전체 종료라 R13 오탭 방지) · 설정 · 홈. 프리셋(F8)·보내지 않은 무전(F16)은 데이터가 생길 때까지 블록째 숨긴다.
- 하단 [무전](F16 다음 작업 — 지금은 "무전은 곧 지원돼요" 토스트·로그) · [내비 보기](`surface.NaviLauncher`, 경로 선택은 순수 함수 `choose`: ① 순정 내비 패키지 `ai.umos.maps.android.navigation.app` 의 실행 인텐트 ② `CATEGORY_APP_MAPS` selector 가 순정 내비로 풀릴 때 ③ pleos 빌드는 그 밖이면 `NaviAdapter.showNavigation()`(NaviHelper) — 다른 지도 앱·선택 창으로 새지 않게 ④ fake 빌드는 selector 가 한 앱으로 풀릴 때만, 선택 창이면 NaviHelper 폴백. 매니페스트 `<queries>` 에 패키지·APP_MAPS 인텐트) · 오른쪽 끝 연결 상태 + T31 지연 문구 그대로("지연 이벤트 N ms · 상태 N ms", 설정에서 끄면 없음).
- 선두 경로 제안 카드(T28 `ProposalCard`)는 대시보드 위 가운데 위에 겹쳐 띄우고 주행 중엔 버튼 비활성(30초 자동 거절) 그대로. 오류 다이얼로그 유지.
- 표면 모드가 `CARDS_ONLY`(플로팅 창 권한 없음)면 맨 위 1줄 "플로팅 창 권한이 없어 알림 카드와 음성으로 안내해요" — [권한 열기]는 `ACTION_MANAGE_OVERLAY_PERMISSION` 이 resolve 되는 기기 **그리고 정차 중**에만(주행 중 입력 UI 비활성; Pleos AVD 처럼 그 화면이 없으면 버튼 없이 안내만).

### 5.2 주행 중 표면 (사용자 확정 2026-10-28)
**원칙: 주행 중 앞 화면은 항상 순정 내비, 동행은 가리지 않는 표면으로만.** 표면은 넷뿐이다 — ① 순정 내비 위 **플로팅 패널** ② **이벤트 알림 카드**(8초) ③ **음성**(T27 `VoiceAnnouncer`) ④ **그룹 휴게소 = 내비 경유지**(T28 `RouteSyncEngine`). 실측 근거: `docs/images/surfaces/*.png`, 제약은 docs/10 R16.

**모드 전환(`surface.SurfacePolicy`, 순수 함수):** 그룹 세션 없음 → `OFF` / 오버레이 권한(`Settings.canDrawOverlays`) 있음 → `PANEL`(패널 + 카드 + 음성) / 없음 → `CARDS_ONLY`(카드 + 음성, 정차 대시보드 안내 1줄). 권한은 `OverlayPermissionMonitor` 가 앱 시작·포그라운드 복귀(Activity 생명주기) 때, 그리고 **그룹이 있는 동안만** 5초마다 다시 본다(Pleos 는 `appops` 로만 바뀌므로; 그룹이 없으면 쓸 데가 없어 주기 바인더 호출을 하지 않는다). 패널 표시 = `PANEL` && 동행 `MainActivity` 가 **보이지 않음**(`AppForegroundTracker` — resumed 가 아니라 started~stopped 로 본다: 정차 중 위치 권한 다이얼로그처럼 화면은 보이지만 paused 인 동안 패널이 동행 화면 위에 뜨지 않게) — 동행 화면이 보이면 대시보드가 같은 정보를 보여 준다. 깜빡임 방지로 표시만 0.6 s 늦춘다.

**플로팅 패널(`surface.FloatingPanelService`):** Service + LifecycleOwner + SavedStateRegistryOwner 가 `ComposeView`(`feature.drive.FloatingPanel`)를 `TYPE_APPLICATION_OVERLAY` + `FLAG_NOT_FOCUSABLE|FLAG_NOT_TOUCH_MODAL` 로 띄운다(패널 밖 터치는 내비로). 데이터는 싱글턴 `SurfaceState.panelUi`(Hilt EntryPoint) ← `FloatingPanelMapper`(순수 함수, 단위 테스트):
- 다른 차만, 선두부터(`distanceToLeaderM` 오름차순), 최대 4대 + "외 N대". 간격 = 상대 − 나 → 음수 "앞", 양수 "뒤", 1 km 미만 m(10 m 반올림), 모르면 "—". 도착 시각 = `eta.destTs` 기기 시간대 HH:mm, 머리줄 = "{그룹 이름} · {목적지} 도착 · 연결 점".
- **머리줄 배치(2026-10-28 사용자 지시 — 머리글은 그룹 이름):** 기준 문구 "{목적지} 도착"(`FloatingPanelUi.etaPlace` + " 도착")은 자기 폭으로 먼저 자리를 잡아 **잘리지 않고**, 그룹 이름이 남는 폭을 다 쓴다(`weight 1`). 폭이 모자라면 **그룹 이름만 말줄임**한다("아빠 차와 같이…" — 375 dp·22sp 에서 "경포해변 도착" 옆 그룹 이름 몫 ≈ 180 dp, 한글 약 8자). 기준 문구에는 상한 **180 dp**(`FloatingPanelSpec.HEADER_LABEL_MAX_DP` — 머리줄 안쪽 319 dp 중 그룹 이름 몫을 139 dp·약 6자 이상 남기는 값, 한글 약 7자 + " 도착" — "광주송정역 도착" ≈ 160 dp 까지 그대로)을 두고, 그보다 긴 목적지만 **목적지 이름을 말줄임하고 " 도착"은 남긴다**("강릉 경포해변 중앙… 도착"). 시안 `panel_worst`(시연 기본 그룹 이름 "아빠 차와 같이 가기"), `panel_longdest`(상한에 걸리는 긴 목적지 + 긴 그룹 이름).
- 저잔량 = min(연료%, 배터리%) ≤ 15(주유기 아이콘), 경고(주황) = |간격| > 3 km 또는 연결 끊김, 연결 끊김 = !online 또는 OFFLINE(회색 점).
- 소식 줄 = 받은 지 10초 안 + 서버 시계로 60초 안에 생긴 가장 최근 이벤트(내 차 출처 제외, 재접속 때 밀려 온 옛 이벤트 제외 — `SurfaceEvents`, 정차 대시보드 띠와 같다). 나이는 서버 시계 − 봉투 ts. 톤: 급제동·에어백 = 위험(빨강), 저잔량·연결 끊김·경로 이탈 = 주의(주황), 그 밖 = 정보(초록) — 색 + 아이콘 이중 표기.
- [무전] 라임 버튼(F16 다음 작업 — 지금은 토스트). 주행 중 패널에서 받는 입력은 이 탭 하나다.

**크기·가독성(`surface.PanelLayout`, 사용자 지시):** 내비 화면 폭 = 가로 디스플레이면 폭의 2/3(Pleos 2창 실측 — 왼쪽 853/2560 px 가 차량 영역), 세로면 전체. 패널 폭 ≤ 내비 폭의 **22%**(Pleos 2560×1440·1 dp = 1 px 에서 375 dp), 높이 ≤ 디스플레이 높이의 **30%**(432 dp — 차 4대 + 이벤트 + [무전] ≈ 375 dp, "외 N대" 줄까지 ≈ 410 dp). 글자: 거리·도착 시각 숫자 **31sp**(시안 24sp × 1.3), 이름 **29sp**(× 1.2, 고정폭 100 dp — 안 들어가는 긴 닉네임은 20sp 까지 줄여 맞추고 그래도 넘치면 말줄임, 2026-10-28 실측 "DemoCarB" 가 "De…" 로 잘리던 것 개선), 간격은 10 km 미만 소수 1자리·그 이상 정수("뒤 28 km" — 소수까지 쓰면 단위가 잘렸다), 저잔량 아이콘까지 붙어 남은 폭에 안 들어가면 간격 숫자를 24sp 까지 줄인다(`FitGap`, 최악 조합 시안 `panel_worst`), 단위 "km/m" 18sp 작게, 머리줄 22sp·소식 줄 24sp·무전 31sp(× 1.2), 행 높이 ≥ 40 dp·행 간격 10 dp. 폭이 375 dp 보다 좁은 화면은 같은 비율로 줄인다(하한 0.6배).

**위치:** 기본 **오른쪽 위 고정**(오른쪽 110 dp — 오른쪽 끝 메뉴 손잡이 회피, 위 190 dp — 내비 2D 버튼 아래; 내비 TBT 는 왼쪽 위, 하단은 ETA 카드·음량/설정 버튼). **정차 중(`DrivingStateMonitor` false)에만** 드래그 가능 → 놓으면 가장 가까운 모서리(좌우 = 내비 화면 가운데, 위아래 = 디스플레이 가운데 기준)로 스냅 → SharedPreferences `dh_surface`(`panel_corner`)에 저장. 모서리 여백: 오른쪽 아래(150, 24) — 음량·설정 버튼 열 회피, 왼쪽 위(내비 왼쪽 + 24, 360) — TBT 아래, 왼쪽 아래(내비 왼쪽 + 24, 340) — ETA 카드 위. 주행 중에는 드래그를 무시한다(뿌리 뷰 `PanelDragFrame` 이 슬롭을 넘는 이동만 가로챔, 짧은 탭은 [무전]으로). 드래그 도중 주행으로 바뀌면 그 드래그를 **취소**한다(`cancelDrag` — 원래 모서리로 돌아가고 저장하지 않음, 이동·놓기 처리도 `dragEnabled` 를 함께 본다).

**주간/야간:** `Configuration.uiMode` 야간 → 짙은 반투명(0xE6161A20) + 흰 글씨, 주간 → 밝은 반투명(0xEDFAFBFC) + 짙은 글씨(톤 색은 흰 바탕 대비 4.5:1 이상으로 진하게), 라임 [무전]은 둘 다 유지. 설정이 바뀌면 서비스가 즉시 다시 그린다. 시안 확인: `screen=design&variant=panel_dark|panel_light|panel_full|panel_worst|panel_longdest`, Compose Preview "플로팅 패널 야간/주간/5대/폭 최악(긴 그룹 이름)/긴 목적지".

**이벤트 알림 카드(`surface.EventCardNotifier`, 판단 `EventCardPolicy` 순수 함수):** `MqttSessionManager.groupEventsReceived` 구독. 대상 = LOW_ENERGY·HARD_BRAKE·AIRBAG_DEPLOYED·WAYPOINT_ARRIVED·DESTINATION_ARRIVED·MEMBER_JOINED·MEMBER_OFFLINE·PASSENGER_MESSAGE(+ F16 `VOICE_MESSAGE` — 문자열 비교). 내 차 출처 제외, 신선도 60 s(`ClockSync.serverNow() − 봉투 ts`). 빈도 제한 `CardThrottle`: 같은 `eventId` 한 번(최근 128개, QoS1 중복 수신), 같은 종류·같은 출처 30초에 한 장(연결 들락날락 MEMBER_OFFLINE 등; 메시지는 제외), 전체 8초에 2장까지(위험 ALERT — 에어백은 예외), 못 올린 카드는 한도를 쓰지 않는다. 채널 **`dh_events_silent`(IMPORTANCE_HIGH, `setSound(null, null)`·진동 없음** — 같은 이벤트를 음성이 읽으므로 알림음과 겹치지 않게; 소리 있던 첫 채널 `dh_events` 는 지운다, 채널 소리는 만든 뒤 못 바꾼다), category 메시지 → `msg`, 그 밖(저잔량·급제동·도착·합류·끊김) → `navigation`. **Pleos 알림 표시기(`ai.umos.notification`)는 일반 앱 알림 중 category `call`·`msg`·`navigation`(·`connect.system`)만 헤드업 카드로 띄우고 `status` 는 IMPORTANCE_HIGH 여도 알림 목록에만 넣는다** (2026-10-28 실측 — 첫 구현의 급제동·저잔량 카드(`status`)가 안 떴고, 표시기 로그 `needHeadUpNotification` 이 navigation·msg 에만 찍힘; `car_warning` 등 차량 category 는 시스템 서명·권한 앱 전용, SecurityException), 제목 = 서버 음성 문구(없으면 종류 라벨), 본문 = 그룹 이름, `setTimeoutAfter(8000)`·autoCancel, **같은 종류는 같은 알림 id 로 교체**(쌓이지 않음). PANEL·CARDS_ONLY 모두에서 동작. `POST_NOTIFICATIONS`(API 33+)는 위치 권한과 같은 시점(활성 그룹 + 정차, `LocationPermissionGate`)에 함께 요청하고, 거부되면 카드 없이 패널·음성만.

**조용한 상시 알림:** `DriveSessionService` 의 포그라운드 알림은 옛 채널 `drive_session`(IMPORTANCE_LOW, category navigation — Pleos 상단 카드로 떠 내비 TBT 를 가렸다, `b_floating_panel_design.png`)을 지우고 새 채널 **`drive_session_quiet`** 로 올린다. 채널은 IMPORTANCE_MIN(소리·진동·배지 없음)으로 **만들지만** 포그라운드 서비스 알림이라 Android(NotificationManagerService)가 사용자 설정이 없으면 **LOW 로 올린다**(dumpsys 에 importance=2 로 보일 수 있다 — LOW 도 소리·헤드업 없음). Pleos 상단 카드를 막는 핵심은 **`CATEGORY_SERVICE`** 다(category navigation 이 카드로 뜨던 원인; 78dcafd 프로브는 FGS 가 아닌 ongoing 알림으로 확인했고, FGS 알림은 `dumpsys notification` + 순정 내비 화면 캡처로 확인한다). 알림은 `setSilent`·`setOnlyAlertOnce`·`PRIORITY_MIN`·`CATEGORY_SERVICE`·ongoing, **문구 고정 "동행 그룹 주행 중"**, 내용 갱신 없음. 내비 위에 뜨는 것은 플로팅 패널과 이벤트 알림 카드뿐이다.

**배선·확인:** `surface.DriveSurfaceController`(Application 에서 start) — Activity 생명주기 등록, 권한 감시·`SurfaceState`·`EventCardNotifier` 시작, `PanelKeeper`(순수 코루틴 로직)가 `panelVisible` 과 서비스의 `shownState`(창이 실제로 붙었는지)를 함께 보고 패널 서비스를 시작/종료 — 붙지 않으면(백그라운드 시작 제한 `IllegalStateException`, addView 실패 뒤 stopSelf, 시스템의 유휴 서비스 정리) 3초부터 두 배씩(최대 30초) 다시 시작하고 시도·실패를 `describe()` 의 `keeper=` 에 남긴다. Hilt 바인딩 `di/SurfaceModule`. 로그 `surface: mode=…`, `surface panel: shown corner=… widthPx=… scale=…`, `surface: card <종류> id=… category=…`. debug 리시버 액션 `surface`(상태 한 줄)·`surface_pos corner=…`(모서리 지정)·`event type=…`(로컬 이벤트로 패널 소식 줄·카드·음성 확인). 테스트: `SurfacePolicyTest`·`FloatingPanelMapperTest`·`EventCardPolicyTest`(+ `CardThrottle`)·`SurfaceStateTest`·`SurfaceSignalsTest`(`PanelKeeper` 재시작·백오프, 권한 주기 확인, `NaviLauncher.choose`)·`DriveDashboardMapperTest`.

## 6. 백그라운드 동작
- 그룹 활성 중에는 **포그라운드 서비스**(`DriveSessionService`)가 텔레메트리·MQTT·음성을 담당 → 다른 앱이 화면을 차지해도 동작.
- 그룹 비활성 시 서비스 종료(불필요한 상주 금지, Pleos 리소스 가이드).
- 앱 프로세스 재생성 시 `activeGroupId`로 자동 재연결.
- **(T23 구현 메모)** `domain.telemetry.TelemetryCollector`(싱글턴, 앱 시작 시 start): `MqttSessionManager.session` 이 non-null 인 동안 1초마다 `Telemetry` 를 `dh/v1/vehicle/{vid}/telemetry` 에 QoS 0 으로 발행한다.
  위치 = `LocationFeed.fixes` 최신 Fix(10초보다 오래됐거나 없으면 그 틱은 건너뜀 — 가짜 위치 금지), 속도 = `VehicleSignals.speedKph`(Car API) → 없으면 `LocationFeed.speedKph`(Haversine), 기어 = 차량 신호(UNKNOWN 은 null),
  ETA = `NaviEventMonitor.state` 의 마지막 TripInfo(120초 이내)를 **30초마다 또는 거리 500 m/시간 60 s 이상 변화 시** 포함(`destTs = tripTs + remainS`), 에너지 = 연료/SoC **1%p 변화 시 + 60초마다 재전송**.
  발행 실패(연결 없음)는 세기만 하고 재전송하지 않는다. 의존은 전부 함수/StateFlow(`di/SignalsModule` 에서 배선)라 JVM 단위 테스트로 검증한다.
  `service.DriveSessionService`(포그라운드, `foregroundServiceType="location|dataSync"` — 위치 권한이 있으면 location, 없으면 dataSync 로 시작, 둘 다 실패해도 크래시 없이 계속) 는 `DriveSessionController` 가 그룹 세션 유무를 보고 시작/종료한다. 서비스는 알림 하나로 프로세스 우선순위만 올리고, 수집·발행은 Application 싱글턴이 한다. 알림은 조용한 채널 `drive_session_quiet`(MIN 으로 만들지만 FGS 라 시스템이 LOW 로 올릴 수 있음, `CATEGORY_SERVICE`·문구 고정 — §5.2)이다.
- **(T16 구현 메모)** MQTT 접속은 그룹 전에도 유지한다: 폰(companion)이 이 차를 그룹에 넣는 순간 서버가 `dh/v1/vehicle/{vid}/cmd` 로 `GROUP_JOINED` 를 보내므로(docs/03 §5.5, T18) 차량은 페어링만 돼 있으면 cmd 를 듣고 있어야 한다. `MqttSessionManager` 가 Application 에서 시작해 페어링 상태(TokenStore)를 보고 붙고 끊으며, `GROUP_JOINED` 를 받으면 `GroupSessionStore`(DataStore `group_session`)에 저장하고 그룹 `state/event` 를 구독한다. 포그라운드 서비스(T23)는 이 연결을 백그라운드에서 유지하는 역할만 더한다.

buildTypes: debug / release

```
